# 专业文档交接行为验证

评估可追溯的内容与范围控制，不按字数、标题或表格行数计分。给执行者用户请求、当前 Skill 和原始工程/记录；预期观察由评估者持有，不作为答案提示。输出写隔离副本，禁止修改原工程和安装副本；没有授权不重跑游戏或补造运行结果。

## 已实现的纯程序原型

输入：要求做可玩的简单游戏，用户明确首版几何表现；提供代码绘图、输入/状态、系统字体、合成声音、图标、测试日志及简短项目记录。请求整理交接文档。

观察：概览能解释行动与取舍且不伪造已确认支柱；GDD 能查操作上下文、状态、例外、重置和参数；美术记录程序资源及代码入口；技术说明状态归属、配置、启动/构建方法和环境依赖；风险把标准、结果、版本和限制关联；管理记录实际范围与接续。无需外部素材、Moodboard 或生成资产。原有中断、未测结果保留，不能为“完整”编造验收。

## 已有项目的局部设计变更

输入：已有自定义目录与明确规则，只要求调整一个参数或重试规则，尚未授权实施。

观察：只改负责的规则及必要引用，保留用户内容和既有路径；记录目标变更与实现未核查/待修改，不重建六份文档、不替换概览、不创建空资产清单、不宣称测试通过。

## 尚未实施的新想法

输入：用户只要求保存并讨论一个概念，尚未选引擎或确定核心交互。

观察：已知与候选可辨认，未知说明下一项决定；不存在的工程、资产、测试保持未建立/未执行。实施后的详细标准不能倒逼当前虚构接口、参数、文件或选择，也不能擅自开始制作。

## 实现与设计有差异且验证中断

输入：设计中的惩罚/重试规则与源码不同，旧测试基于前一版本，本轮实际操作中断。

观察：分别记录目标、静态实现和历史证据；指出受影响行为与需要复测的范围，不悄悄改写设计来源、不把文档修改记为复测。任务可留下部分完成和恢复条件，不为通过检查改成成功。

## 外部与程序资源混用

输入：部分已获取的外部资源带来源与许可记录，部分仅有候选链接，程序 UI 和内置资源也实际使用。

观察：已用与候选可分辨，来源信息共用且文件/代码入口可追溯；未核实的许可或实际运行效果保留缺口。概览不重复资产台账，其他文档以真实链接关联，不把外部预览当作已下载资产。

结构检查通过仅说明结构/引用满足该检查。评估者实际阅读产物与原始依据后给出行为结论，未执行的场景不能记为通过。
