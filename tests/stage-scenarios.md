# 阶段与职业验收场景

本文件定义输入与检查，不能作为执行通过记录。原 skill / combat / production-method / playable-experience / document-handoff / ability-system-choice 场景继续适用。区分对话选择评审、自动回归、真实引擎和主观体验；标注是否为独立盲测。

| 输入和现场 | 应产生的具体行动及产物 |
| --- | --- |
| 任意连续阶段 s→e，1≤s≤e≤5 | 只创建这一区间，读取必要已有输入；十五组合与非法区间均测试，结束检查不审批区间外工作 |
| 只做完整策划，没有引擎工程 | 专业规则和交接稿；不通过技术运行检查冒称玩法已验证，也不启动引擎 |
| 从阶段3接手但缺玩法依据 | 定位缺少的具体机制证据、做授权内定向补充，保持原区间，不重建全部项目 |
| 项目处于阶段4，新角色仅需2→3 | 独立对象范围与依赖；其他对象证据保留，角色样例通过后停止 |
| 只换素材来源为社区资源 | 原体验目标、角色职责与品质范围继承；来源许可变化不等于降级交付 |
| 先找能看到真实动作的怪物，再形成玩法 | 已核实候选与搜索计划分开，素材能力/缺口支持取舍，玩家武器不外推 Boss |
| 取消旧项目并从头开始 | 保存授权明确的清理/恢复范围；旧决定不自动继承，不能误删别的工程 |
| 只改局部规则或模型问题 | 选择相关职业方法与消费者，不要求所有职业全部参与或逐一补齐文档 |
| 原包编辑态没有武器 | 运行作者场景，读实际运行附着与相对旋转；不能用静态空列表证明无武器 |
| 原生 UE 动作已存在，无 FBX | native_reuse，保留原生权威资产与消费者；不强制伪造 Blender 回传 |
| 已有角色但看板只能静态展示 | 导出实际动作关联和必要预览；FBX 播放/时间轴/跟随镜头；变更源或预览后拒用旧映射 |
| 命令成功但品质差，后来出现反证 | 功能结果保留，当前品质明确失败/待验；历史不会被删除，也不能自动带动里程碑完成 |
| 取消后持续 FX/音频残留 | 记录真实事件、游戏时钟、取消和清理，先定位生命周期再修；技术录音分析不能冒充听感 |
| 曲线中点预测21但实测不同 | 查实际参数来源、覆盖与消费者；显示预测/实测/差值，不创建第二权威配置 |
| 只修改碰撞宽度或移动速度 | JSON pointer/原生读回与真实消费者关联；只将有依据的相关检查列为复测项 |
| 导入超时，重启任务 | 先查询实际副作用和运行进程，保留执行回执；活跃锁不可解，未知结果不可盲重放 |
| 4→5接手已有完整内容，或5→5只做交付 | 复用现有有效结果，在明确接收环境运行/继续编辑，交付源、依赖与已知限制 |
| 已安装包和看板仍旧 | 读实际路径、版本、文件指纹与启动指纹；定位旧进程或定制差异，保留用户修改 |

真实工程最小复现目录为 `fixtures/godot-observation` 与 `fixtures/unreal-observation`。原用户素材仅用于获授权的私有验证，不能装入公开夹具。
