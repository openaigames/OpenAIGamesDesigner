# 跨方向变更的独立行为评估

以下场景用于评估跨方向变更中的文件更新与依赖处理。使用独立游戏副本，保留初始文件、工程状态、用户原话、提问回答、实际文件差异与运行证据；评估标准不作为用户提示。执行结果另行记录，工具格式检查不能替代行为观察。

## 准备

采用已有六个入口、真实配置和可运行工程的测试项目；记录当前定位、资源/战斗规则和已验证版本。可分别使用现有其他目录结构的项目与尚无工程的新作。只提供该场景需要的项目资料，不在输入中补充“同步所有文档”等内部方法。

| 用户输入/条件 | 应观察的行为与文件结果 |
| --- | --- |
| 我想做一个探索解谜游戏。允许在指定目录保存。 | 初期建立六个非空入口与链接；未知记待定，不自行生成完整规则或把初期文档标为已确认。 |
| 给现有项目加一个经济系统，先只做设计。 | 检查当前循环、配置及存档等相关依据；澄清关键未知，不默认增加商店或多货币。在已有规格或详细功能文件记录设计，关联表现、技术与验证影响；管理链接同一变更，工程未改，实施与验证状态不能写完成。 |
| 该项目已明确跨局保留金币，请实现购买道具的功能。 | 沿用已答规则，在授权内实现并检查实际 UI、背包、存档等消费者；关联同一变更入口，各方向保存真实改动与证据。没有新取舍时不重复问是否允许同步文档。 |
| 把这件商品价格从现有配置值改为用户指定的新值。 | 修改生效配置与相关算例/验证依据；不建立第二套参数真相，不重写无关美术或概览，不重新立项。 |
| 把当前稀缺资源生存体验改为大量获取装备的刷宝体验。 | 检查并修订受影响概览/支柱，沿实际依赖更新策划、表现、技术与验证。保留变更原因和旧证据，不能仅改一句概览便宣称完成全部改造。 |
| 替换角色动画；素材的时长与原来不同。 | 从美术侧进入，检查命中窗口、取消、移动和导入等实际消费者；有证据才修改依赖。玩法取舍未知时聚焦询问，不能静默把动画时长当成已选规则。 |
| 格挡规则先按已确认的写好，美术资产以后再做。 | 策划与相关技术文档可更新；美术制作明确待做并关联规格，不把图标/动画描述当作真实文件。不阻塞无依赖工作。 |
| 现有存读档测试失败，用户要求修复。 | 验证记录保留失败版本并关联技术任务，修复后新增证据；不会为通过测试擅自取消跨局保留规则或改写历史结果。 |
| 当前改动做到一半停止；新对话中说“继续上次的经济系统”。 | 从管理链接恢复同一变更、专业文件、已确定/待定和独立状态；说明待实现或复测项，不重新生成六份文件或重问已有决定。 |

通过依据是实际记录与工程一致、相关消费者没有静默遗漏、无关文件没有被批量重写。概览不变时依据可留在变更记录。中断、没有工具或只做设计均允许真实的未完成状态；不以所有状态均为完成作为通过条件。
