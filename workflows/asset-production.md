# 资产制作、处理与接入

用于新增、修改或替换图像、模型、动画、特效、声音等资产。沿用项目当前阶段和资产体系；局部替换不重新立项。文件获取方式可以是人工制作、已有素材或已配置生成工具，不预设必须 AI 生成。

## 输入与分工

- 从实际需求与消费者开始：资产支持什么玩法或信息，替换什么版本，被哪些场景、材质、动画或代码引用。
- 美术 Skill 定义用途、风格、规格、来源和可检查的交付要求；按需使用 `templates/asset-spec.md`。
- 技术 Skill 核对导入格式、坐标、命名、依赖、引擎设置与替换影响；策划提供碰撞、时序、可读性等功能约束。
- 管理 Skill 关联任务、资产规格、依赖和目标版本，不复制专业正文。验证 Skill 定义实际检查和回归范围。

## 制作与交接

1. 根据当前授权和工具选择制作路径。初次制作或关键资产替换时先明确本轮模型/动作等素材方案与占位范围，或有效的选材委托；工具可用、素材已安装和要求原型都不代替这一决定。方案与方法由美术 Skill 维护，已有明确方案直接沿用。仅讨论风格时形成规格；已要求生成或处理且素材方向明确时继续执行可用工具，不把写规格当成已交付资产。
2. 本地工具任务使用 `tools/asset_workflow.py`。先保存输入、参数与工具配置，提交任务，再执行；命令配置从项目的 `.openaigame/asset-providers.json` 读取，不从设计文档提取 shell 命令。
3. 保存原始输入、输出、日志、任务编号和哈希。失败保留证据；重试建立关联的新任务，旧产物不覆盖。工具不可用时明确缺口。
4. 需要转换时建立后续处理任务，输入引用选定的实际文件。生成和 Blender 处理是不同任务，来源通过输入快照关联。
5. 按规格检查可打开性、尺寸、轮廓、材质、动画或音频等适用项。格式扩展名和哈希检查不能证明质量。
6. 在已授权工程内接入选定版本，沿用项目的导入工具、配置和引用规则；先保留可恢复的旧版本。CLI 产物登记本身不执行引擎导入。
7. 在实际消费者中检查显示、播放、功能、性能和替换回归，使用验证报告链接任务、资产和运行版本。更新管理入口中的完成项及剩余问题。

## 完成依据与反馈

分别记录“文件已生成/登记”“已检查”“已导入”“游戏内验证”。只有当前任务范围内的要求有证据才完成该任务；生成成功不自动通过切片或发布验收。后续改规格、资产或消费者时，标记受影响的检查需要重做。

本地命令协议与恢复方式见 [资产工具接入](../adapters/assets/README.md)。


结束本轮实施时回写涉及的专业事实、任务/里程碑状态、证据与管理下一步；失败或中断也要保存。新项目按管理文件约定运行 `validate_records.py --layout --production --closeout --markdown` 并处理结果；只涉及局部资产/功能、已有或自定义结构时检查等价记录，不强制补新作里程碑。检查结构通过不代表验收通过。
