# 已有项目新增、修改与修复

首次立项建立的六个入口持续沿用；本轮从负责方向进入，修改其正文或详细规格，再检查下游消费者。跨专业时依管理 Skill 的变更影响参考，在一个现有任务/issue/变更记录中关联来源、受影响文件、动作、设计/实现/验证状态和证据。资料足够且属于授权范围的联动修改直接完成；未知选择记录待决并按需澄清，不把识别影响写成已完成。

概览仅在定位、核心体验、目标玩家或设计支柱改变时修订；管理入口每轮链接变更，摘要完成与未完成、阻塞和下一步。价格微调等局部修改无需改概览，资产替换也无需强制修改全部专业。保存和验证后复查关联状态，恢复工作时从同一入口继续。

读取本轮相关的设计、资源和实际实现，识别变更影响；小改动无需五份文档或新里程碑。较大功能建立任务，关联现有阶段，必要时有自己的实验里程碑。全项目不会因为新功能被重置为立项。

先沿用用户要求的交付范围。只讨论、研究或整理规格时完成对应交付，不修改工程、不运行游戏，也不把所有修订都创建为制作任务；已要求实施时继续完成授权内的实际修改和检查。

依次明确规则/规格的变化、兼容与依赖、实现位置、回归范围。美术替换记录源文件与引擎资源；配置改动保持唯一来源；存档/接口变更明确迁移和恢复策略。

实施任务在已有工程执行改动，调用实际可用的命令并记录证据；采用本工具时关联 run，其他引擎沿用工程现有日志/测试记录。比较改前依据与改后结果；旧证据不删除，受到影响的结论标为需复核。回写实际改动、完成依据、剩余问题及下一步，不为小改动生成新项目结构。


结束本轮实施时回写涉及的专业事实、任务/里程碑状态、证据与管理下一步；失败或中断也要保存。新项目按管理文件约定运行 `validate_records.py --layout --production --closeout --markdown` 并处理结果；只涉及局部资产/功能、已有或自定义结构时检查等价记录，不强制补新作里程碑。检查结构通过不代表验收通过。
