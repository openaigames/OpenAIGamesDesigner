# 机制学习、辅助与可用性

## 确定要学会什么

把“理解系统”拆为可观察行为：辨认可交互对象、预测一次操作结果、完成选择、发现失败原因。说明此前知识和本轮新增概念，不能把已经熟悉游戏的作者当作初次玩家。

说明提示出现的上下文、触发、结束、重复与重看方式。一次弹窗展示不证明玩家掌握；沉默也不一定是理解。核心信息应有适合当前行动负荷的呈现方式。

## 保留探索与自主性

提示可以基于请求、卡住的观察或固定情境，但要说明判断依据和误触发代价。用户希望自由发现时，不默认用任务箭头或强制教程替代。

允许已有经验者跳过、允许需要帮助者恢复信息。重复失败时可能需要解释规则、改变反馈或降低重试负担，不一定要降低整个游戏难度。

## 辅助不改变未授权的规则

根据目标使用情境评估字体、对比、颜色之外的区分方式、字幕、声音替代线索、输入保持/切换和运动效果设置。没有素材或实际显示环境时只给设计要求，不宣称达成可访问性标准。

舒适和感知选项应与玩法辅助区分：关闭镜头震动不必改变命中判定；更强瞄准辅助可能影响玩法，需要单独决定。

## 用观察改进

给参与者目标，避免在任务指令中提前说出要找的按钮。记录他们的尝试、误解、犹豫、恢复以及主持人提供的提示；提示后的完成不能算独立发现。

区分不会操作、不了解规则、找不到信息和不想继续。点击次数与耗时只是证据的一部分，需结合行为解释。程序跑完教学流程不能证明人类学会了机制。

交付学习目标、触发与退出、辅助方案、观察问题和剩余风险。实际试验使用 game-prototype-validation 的可用性方法；未执行保留待验证。
