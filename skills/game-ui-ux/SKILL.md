# 界面与交互体验

从玩家任务和真实状态进入：玩家想做什么、需要知道什么、可操作什么、失败后如何恢复。读取已有输入方式、界面实现、系统规则及风格；局部修正不重做所有菜单。

方法入口为 [UI/UX 专题](references/ui-ux.md)，按问题读取任务与信息、输入与反馈、学习与可用性。先画清有效操作和状态关系，再确定布局与表现；按钮禁用、加载、空列表、失败和焦点返回属于操作契约，按本次范围实现。

界面状态读实际规则源，不在界面再维护一份生命、货币或任务完成逻辑。信息优先级决定位置、大小、持续时间和动效；动画需表达变化或引导操作，不能用无关运动妨碍战斗阅读。触屏、键鼠与手柄焦点按支持设备检查，不默认所有设备都已实现。

和系统策划约定规则/数据，与美术指导保持视觉语言，与程序完成当前引擎的实际界面与输入，与音频/VFX约定反馈事件。继续使用项目已有框架；工具包看板属于制作工具，不充当游戏 UI。

交付界面流程、视觉/动效规格及适用的可编辑资源和原生实现。验证完整路径、误操作、返回/重试和数据刷新，区分静态设计、交互实现与实际可用性；用真实步骤和观察结果说明问题，不以截图数量判合格。

制作或导出本轮界面资产后，按 [分类与用途标签](../game-preproduction/references/project-workbench.md#分类与用途标签) 核对二维美术与 UI、代码/模板和音效各自分类；保留实际消费者及已有用途标签。

## 制作迭代与版本交接

栅格设定图、地图图纸、界面图片或效果概念图的生成工具按 [生成工具选择](../game-art-direction/references/generation-tool-selection.md) 决定；普通生图优先当前宿主可用的内置工具，配置密钥不改变默认选择。

交付物多次修改或使用旧方案时，按 [资产版本与迭代记录](../game-art-direction/references/asset-versions.md) 保留实际文件、修改底稿、参考用途和当前选用。不同专业交付物分别建组，配套文件组成同一版；选回旧版不删除新版本，也不自动覆盖工程、重新绑定或认定验收通过。

检查输入到反馈的等待时间时，可使用 [跨引擎动作记录](../../adapters/engines/action_timing/README.md)；在真实输入、界面状态变化、动画和声音请求处记录，区分时间检查与视觉、听感验收。使用 CLI 与引擎原生工具观察比较，游戏界面仍由目标引擎实现。

开发动作编排工具时参考 [条形时间轴编辑](../../adapters/engines/action_timing/EDITING.md)：持续内容画成条形，瞬时事件保留标记，提供波形、属性、吸附、撤销和修改预览。实机声音与草案试听明确切换，过渡不能只改变图形而不作用于引擎。

开发动作工具与原生测试场景的连接时，按 [实时预览](../../adapters/engines/action_timing/PREVIEW.md) 显示真实连接、待应用、已确认版本、错误与离线状态。新草案等待回传期间不能把上一版画面标为当前结果；只在已登记消费者的动作中展示原生控制。

本轮实际制作、转换或接入资产时，按 [资产生产登记与交付检查](../game-preproduction/references/asset-handoff.md) 同步维护既有权威清单：沿用稳定 ID，关联源文件、派生物、用途和实际证据。由执行方补齐本轮登记，不把补表留给用户；纯讨论与只读检查不写完成状态。

动作检查、片段编辑与原生预览的看板界面当前暂缓；上述接入协议保留供后续开发，不将隐藏功能作为当前可用入口。真实动作验证继续使用引擎原生工具和记录 CLI。
