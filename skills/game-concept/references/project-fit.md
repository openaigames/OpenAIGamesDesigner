# 现有项目定位与方向变更

新增局部功能、修复 bug、替换资产通常不需要改概览。仅在核心体验、目标玩家、长期目标、世界身份或设计支柱确实受到影响时使用本指南。

## 先找已有依据

读取项目介绍、相关设计决定和用户当前目标；没有概览时，可从实际资料提取本轮需要的体验约束，标明推断。缺少 Game Pillars 不阻止局部功能设计，不替用户编出一套支柱再当作批准基线。

对候选功能判断：它支持哪种体验，怎样参与已有循环，会挤占哪种玩家行动或改变何种承诺。例如加入永久成长可能改变跨局目标，但不能仅因游戏标注 Roguelike 就认定必须有或不能有永久成长。

## 交付范围

- 局部扩展且定位不变：简短记录与既有方向一致的依据，交给策划/美术/技术展开，概览可以不变。
- 可能冲突：指出具体承诺和取舍，给出适配现方向或调整方向的候选；不将个人偏好写成客观否决。
- 用户已要求转向：修订相关定位与支柱，保留原决定及变更原因，指出 GDD、美术、技术和风险中需要复核的内容，不重复问是否允许转向。

需要竞品或目标玩家研究时，围绕当前决策检索有来源的材料，区分产品事实、用户反馈样本与吸引力假设；同类作品成功不证明新功能必然有效。研究交付可以独立于概览，不把完整调查堆入概览正文。

没有方向变化时，不因任务完成而强制修改概览或创建新的立项版本。
