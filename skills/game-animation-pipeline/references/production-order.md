# 制作顺序与验证分工

用于决定模型、动作、规则与视听反馈何时制作和验收。以下是可反复迭代的依赖关系；已有项目从当前缺口进入，不重做无关阶段，不要求所有游戏具备连招或武器系统。

## 需求与素材都可以成为入口

先区分需保留的体验目标/已定规则与可替换占位。职责已定时由必要行为找组合；职责/招式未定、已有素材可复用或预算受限时，可先搜资源、检查模型/动作/装备能力，再提出能成立的职责与交互。角色分别判断，不能从玩家武器推定 Boss 装备。具体方法见 [角色职责与素材适配](../../game-art-direction/references/role-asset-fit.md)。

搜索、预览、外部检查和代表小样可以发生在详细规则之前；外部或引擎实验用于检验候选，不等于已采用全套设计。批量制作与正式接入前须有当前任务职责、玩家交互和组合适配依据。代表样本出现根本冲突时，决定换素材或在委托内改设计再扩量；记录改变的规则及使用方，不把整套动作烘焙完成当作选型合理的依据。

## 先稳定哪些条件

进入批量动画制作时，明确当前任务操作、镜头、动作目的和目标体验，再稳定角色比例、目标骨架、武器尺寸与握持基准；探索样本可保留待验证项。动画可以基于已认可的简化模型制作；精细材质、服装细节无需全部完成。后续改变比例、骨架或影响接触的装备尺寸时，复查蒙皮、握持、轨迹和碰撞。

骨骼动画与 VFX 分别制作：前者描述身体和武器运动；后者可由粒子、拖尾、材质、网格及烘焙贴图组成。外部工具可以制作特效素材或预演，但最终附着、事件、渲染和性能在目标引擎确认，不把外部渲染短片当作实时效果验收。

## 从粗验证到精修

| 阶段 | 当前任务制作重点 | 进入下一轮的依据 |
|---|---|---|
| 玩法与粗动作 | 已认可的角色/动作占位，输入、位移、判定、目标响应和最低可读反馈 | 引擎中可操作，能判断响应、距离和基本节奏 |
| 代表性招式或交互 | 少量最能暴露风险的动作，检查关键姿态、握持、衔接、取消；逐层加入声音、VFX 和镜头 | 源动作、测试场及真实操作的证据能支持当前任务目标，问题有明确归因 |
| 资产扩展与精修 | 按代表样本扩展动作和反馈，模型与材质继续细化 | 同类内容保持一致，替换影响已复查；缺口和占位保留明确状态 |
| 完整场景 | 多对象叠加、实际背景/镜头、完整战斗节奏及目标设备负载 | 玩法、动态视听与性能分别有证据，不能互相代替 |

早期保留必要提示、命中反馈与临时声音，不能因为“特效后做”让玩法缺少判断依据。动作清晰度检查时可暂时关闭遮挡性 FX；完整体验检查必须恢复目标反馈。规则时序与动画接触不匹配时共同修订，不用粒子或强制 IK 掩盖源动作问题。

常见迭代是“粗动作 → 引擎试玩 → 定位问题 → 修改源动作/规则/绑定 → 复测 → 精修”。先做一个有代表性的往返，避免整套资源做完后才发现导入或玩法接口不成立。

## 根据已有资产选择入口

- **已有 UE 工程资源**：直接查看 AnimSequence、目标 SkeletalMesh、Skeleton、Montage、挂点和依赖，在独立地图或实验工程验证。看板可登记 UE 资源路径并关联引擎预览/录屏；无需为了确认资产而批量导出 FBX。
- **已有 Blender/其他 DCC 源文件或 FBX**：使用真实目标骨架和武器做一个小样回传，确认单位、轴向、蒙皮与根运动，再扩展。
- **需要修订动作、蒙皮或模型**：优先使用作者源文件；只有引擎资源时按工具支持与许可导出所需内容。FBX 通常不保留完整的原始控制器、约束和编辑层，导出不等于恢复作者工程。
- **只需修正引擎绑定、混合或事件**：在引擎修正对应层，避免无必要地重制源动画。所有分支在变更后复测实际使用方。

## 外部与引擎分别验证什么

| 问题 | 外部制作环境 | 独立引擎测试场 / 真实游戏 |
|---|---|---|
| 姿态、重心、武器轨迹 | 真实模型和装备上的源动作与关键姿态 | 导入、重定向、混合和运行时修正后的实际骨骼结果 |
| 握持、蒙皮和穿插 | 作者约束、握点与变形 | 最终挂点、动画层、装备与实际镜头下的结果 |
| 脚步与位移 | 支撑窗口和根骨轨迹 | 地形、角色移动、碰撞与位移所有者的协调 |
| 连段和取消 | 已知序列与接缝的预览 | 不同输入时机、受击、切换和中断；独立播放不代表交互通过 |
| VFX、声音和镜头 | 素材、预演与节奏参考 | 实际触发、变速、附着、背景、叠加、清理与监听 |
| 打击感与性能 | 可提供参考，不能完成最终判断 | 操作者在真实控制条件下评价；性能记录目标环境与负载 |

Blender 可支持上述源端检查，但静态截图、代理几何或合成采样不足以证明连续动作合格。独立测试场用于定位资产问题，真实战斗用于确认交互和体验，按 [验收和交接](review-and-handoff.md) 分别记录。
