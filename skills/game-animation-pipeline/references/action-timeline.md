# 动作时间轴与事件对照

这是通用能力。移动、近战、施法、开门、拾取与射击都能使用；事件名称和玩法含义由项目定义。动画片段、允许操作的区间、输入到达和规则生效的时刻分别记录。实际规则仍由游戏负责，本工具只读取数据，不替换状态机、动画通知或网络逻辑。

## 使用

`scripts/action_timeline.py --spec 设定.json --capture 实测.json --out 新报告目录`

输出 JSON 与可直接打开的 HTML。退出码 0 表示记录中的指定事件在容差内；2 表示存在缺失、超差或无法精确判断的项目。没有输入尝试的窗口，不能据此证明操作可用。

设定文件示例（例子中的秒数只用于说明格式）：

```json
{
  "schema": "action-timeline/1", "revision": "example", "duration_s": 2,
  "clips": [{"track":"character","id":"reach","start_s":0,"end_s":1}],
  "windows": [{"track":"logic","id":"interact","start_s":0.3,"end_s":0.8}],
  "events": [{"track":"logic","id":"take_item","time_s":0.5,"tolerance_s":0.04,"window":"interact"}],
  "synchronize": []
}
```

实测文件：

```json
{
  "schema":"action-events/1", "revision":"build-id", "source":"实际运行日志路径及采样方法",
  "zero_s":10,
  "events":[{"track":"logic","id":"take_item","t_s":10.52,"uncertainty_s":0.01}]
}
```

同一轨道的事件 ID 必须唯一；重复开火或脚步使用独立编号，不能让后一条覆盖前一条。`zero_s` 是与本次动作起点对应的采样时钟。连续数据发现状态变化时，以前后两次采样的中点作为时刻、半个间隔作为误差；不能把首次观测值当成精确发生时刻。不同机器/时钟先校准，再比较。

`synchronize` 可写 `{"a":["first","magazine_in"],"b":["third","magazine_in"],"tolerance_s":0.04}`。一、三人称可以用不同姿态和片段，比较的是玩法事件与观察到的关键动作。单机记录不证明网络同步正确。

## 射击项目如何使用

按需定义奔跑开始、退出请求、抬枪结束、允许瞄准、允许开火、换弹提交与取消等事件。把移动减速、姿态回位、禁射等待、镜头过渡作为不同片段或窗口。某个等待时间改短，不应隐式改动另外几个时间。

中途取消、连续输入、空仓和非空仓等情况分别记录。弹药增加是逻辑提交的证据；弹匣插入是动画证据，两者不能互相冒充。具体事件、时间和阈值保存在项目配置中。通用工具没有内置武器类型、预设数量或固定开火窗口。

## 与现有采样配合

沿用 `anim_pipeline.py` 的骨骼与武器采样；本工具补事件时间比较。不要修改已有 `/1`、`/2` 数据来塞入虚假命中事件。工程适配脚本把已有日志转成上述格式，并记录原文件哈希、字段含义、时钟换算和没有采到的事件。

报告关联同一版本录像的时间范围。图表用于定位，完整动作仍需以正常速度和慢放观看，听音另行确认。报告中的 `visual_review` 和 `network_test` 始终表示本脚本未执行这些验收。

## 引擎实录与看板

共享工具可安装 [引擎记录器](../../../adapters/engines/action_timing/README.md)，用 CLI 导入与比较录制。记录器输出相同的 `action-events/1`，补充引擎版本、动作名、输入方式、输入说明、完成状态与丢失数。`action` 在记录和设定里保持一致；重复事件由记录器自动编号为 `commit#1`、`commit#2`。

除固定秒点外，设定可加入 `delays`，检查两次事件的相对间隔：

```json
"delays": [
  {"from": ["input", "activate#1"], "to": ["logic", "commit#1"], "min_s": 0.2, "max_s": 0.3}
]
```

这是项目定义的等待范围示例，不是任何游戏的默认数值。两次事件的不确定度相加；可能落在范围内外时标为精度不足。发生顺序反转或缺失也会报告。录制起点不必恰好等于输入时刻；仍需要共同的真实时钟。

看板保存检查副本和来源哈希，不能把录像、报告或未经运行的设定当作动作本身。缺少 `game-preproduction` 时，独立 Python 时间轴工具仍可使用；此时没有引擎安装和看板功能。

## 片段编辑与声音对齐

需要安排时长或调整声音时，使用 [条形时间轴编辑](../../../adapters/engines/action_timing/EDITING.md)。动画与声音用片段表示，规则窗口用区间表示，瞬时事件保持单点。素材时长和声音波形取自实际文件。编辑配置在引擎里读取并重新录制后，才能核对新的动作表现。
