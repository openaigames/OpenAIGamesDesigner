# 游戏动画资产管线

在职业分工中负责角色动画的姿态、节奏、接触与连续性；与 `game-technical-art` 共享骨架/蒙皮/重定向及显式绑定接口，与 `game-technical-design` 核对实际驱动、附着、混合和状态。单独使用可按同样职责完成本轮工作，无须安装全部职业。动画问题不因职责拆分而反复转单，沿实际源到消费者定位。

把动画当作可独立制作、返修和替换的资产。粗动作尽早进入引擎验证玩法，源动作、绑定和战斗反馈按问题反复修订；通过代表性招式验证后再扩展。精修交接前检查真实骨架、接触和衔接，不能把原型可玩当作动画品质通过。保持用户选择的引擎、角色、动作来源和现有项目规则；新管线不等于重做整个战斗系统。

## 开始工作

读取实际角色/骨架、动作源、武器、绑定方式、根运动所有者、招式时序与本次反馈。已有游戏项目沿用 GDD、美术清单和技术入口，仅追加受影响记录。独立使用时不要求安装其他游戏 skills。

为新模型选择动画与骨架时，按 [动画与骨架路线](../game-technical-art/references/rig-aware-asset-production.md) 沿用用户选择；未定则在依赖该路线的制作前确认。复用现有动作时先播放代表片段，再把其骨架/参考姿态和接触要求交给模型制作；自动生成骨架不保证动作质量。已有动画的局部修复不重新询问整条路线。

先区分问题所在层：源动作姿态/蒙皮、坐标与导出、重定向/导入、武器挂点/IK、混合与状态衔接、接触事件、反馈时序。不要默认“穿模”只要调整挂点，或“没打击感”只要增大粒子/震屏。旧实现的自动功能通过、静态截图、主观反馈分别保留。

对有问题的现有动作先保存真实基线。采样必须来自实际求值后的骨骼与武器，注明动画层、IK、变速和坐标；数学目标轨迹不能冒充实际骨骼结果。为当前任务选择必要动作、连段和取消场景，不固定要求所有项目制作某套招式。

既可按已定职责找动作，也可先检查现成模型/动作/装备的能力，再与策划形成候选交互；无需先确定全部招式才允许预览、外部检查或探索小样。批量校准与正式接入前，按 [角色职责与素材适配](../game-art-direction/references/role-asset-fit.md) 核对已采用的职责、组合和缺口，单独安装时沿用项目记录。玩家与 Boss 分别判断，早期占位不是永久限制；不要把结构或玩法冲突当成挂点问题继续批量烘焙。

## 工作顺序

按本轮资产状态选择入口：已有引擎资源可直接测试；已有外部源文件先小样回传；新制动作先做关键姿态。Blender 不是必经步骤，也不能替代引擎内输入、混合、中断、判定和实际镜头的验证。制作阶段与并行关系见 [制作顺序与验证分工](references/production-order.md)。

1. **约定接口**：固定骨架/参考姿态、单位与轴向、根运动所有者、武器接触标记、动作 ID、事件时基、进入/退出姿态。数值主源仍由游戏规则负责；动画候选改变接触时点时，提出规则/资产的协调修改，不能悄悄改伤害。
2. **按需外部制作与校准**：先做关键姿态、重量转移、接触与随动，再做细节。用真实蒙皮、武器、地面和目标体积观察；双手武器标明辅助手约束区间，不能整段强拉 IK 掩盖姿态问题。源文件保留可编辑层，导出副本烘焙约束。引擎试玩暴露节奏、距离或取消问题时，回到对应动作或规则修改，不等全套动画做完才联调。
3. **先做代表样本回传**：新骨架/新导出设置先用一个短动作验证单位、层级、方向和根骨，再批量制作。保留源文件、导出设置与哈希；不能以文件存在判定导出正确。
4. **目标引擎的独立测试场**：使用实际选定资源、当前目标骨架和武器绑定，标明占位范围。提供暂停/逐帧、变速、正面/侧面/游戏视角、接触标记和连段播放。先关闭掩盖动作的战斗 FX，再逐项恢复反馈；不加载 Boss AI 来代替动作测试。之后在可操作的代表战斗中检查输入、混合、打断与反馈；两种测试互补。UE 工程按 Unreal 采样工具执行；Godot、Unity 或浏览器工程沿用相应目标运行环境，不因本管线附带 UE 脚本而迁移引擎。
5. **分层验收**：自动检查坐标回传、握持误差、接触间隙与候选跳变；实际播放检查蒙皮穿插、脚滑、衔接和节奏。代理碰撞只是筛查，静态帧不能证明连续性，数值不能证明打击感满意。未声明脚部接触窗口就不声称脚滑通过。
6. **版本化交接**：只把有当前证据的候选交给战斗绑定，关联具体动作/事件/位移/中断清理和消费者。质量豁免注明具体问题、用途和限制；不伪造用户认可。改动源动作、绑定、时序、压缩或重定向后使对应证据失效并局部复测。

`scripts/anim_pipeline.py` 按显式协议版本检查清单、采样和交接：`/2` 支持外部制作、原生复用和局部修改；`/1` 保留旧攻击样例的严格回传检查。骨骼命名、接触事件及测量缺口见 [运行管线的适用范围](references/running-the-pipeline.md#当前入口与-1-兼容范围)。`scripts/blender_stage.py` 提供目标骨架校准、基线烘焙、FBX 导出、外部预览。`scripts/ue_editor_stage.py` 提供参考导出、独立导入和旧测试场生成；原生 `/2` 采样使用共享 Unreal Playback 的实际项目消费者。`assets/unreal` 为旧 `/1` 可移植测试场 C++，需编译到授权实验模块，不是已安装的 Unreal 插件。旧记录的兼容范围见 [旧版采样协议](references/legacy-capture.md)，不用于初始化新工程。

工具能完成的技术检查要实际运行。资产或软件缺失时完成不依赖它的工作，说明具体未执行环节；不要用示意角色、浏览器骨架或代理几何冒充指定角色的动画验收。使用用户指定的 DCC 时沿用该工具；Blender 适配器不是强制选择。

## 交付

交付可编辑动作源、导出资源、绑定/时序清单、独立测试入口、具体帧/时间点缺陷、回传报告和接入范围。分别报告管线可用、资产可导入、运动/绑定质量、游戏功能与主观体验。动画仍待返修时可以交付管线，但不得把基线命名成完成的动画包。

遇到参考姿态、左右映射、握柄或步幅偏差，和技术美术按 [角色集成方法](../game-technical-art/references/character-animation-integration.md) 定位。动画仍负责起手、接触、收招与过渡的姿态和重量评价；未声明脚部/副手接触窗口时不外推通过。

动作取得、制作或导出后，按 [分类与用途标签](../game-preproduction/references/project-workbench.md#分类与用途标签) 核对文件分类；带动作的模型保留主分类与“含动画”能力，独立动作按动画资源记录。分类不替代实际角色绑定。

## 制作迭代与版本交接

交付物多次修改或使用旧方案时，按 [资产版本与迭代记录](../game-art-direction/references/asset-versions.md) 保留实际文件、修改底稿、参考用途和当前选用。不同专业交付物分别建组，配套文件组成同一版；选回旧版不删除新版本，也不自动覆盖工程、重新绑定或认定验收通过。

通用动作事件、操作窗口和双视角时序比较使用 [动作时间轴](references/action-timeline.md)。射击、近战、移动与交互的事件由项目定义，原游戏仍负责规则。

需要对照原生动作事件与规则时刻时，按 [跨引擎记录接口](../../adapters/engines/action_timing/README.md) 接入当前工程，用 CLI 对照记录并在引擎原生工具中核对。动画通知、播放请求和实际渲染出来的姿态分别判断；同时记录取消、退出与事件缺失。

需要编辑动作和声音时，使用 [条形时间轴](../../adapters/engines/action_timing/EDITING.md)。先登记实际素材与引擎消费者，核对片段、过渡、声音和窗口，再应用并重新实录；不以草案试听代替游戏混音验收。

已接入原生测试场景时，可用 [原生预览桥接](../../adapters/engines/action_timing/PREVIEW.md) 在看板试调、暂停、逐帧、变速和换机位。观察实际骨架与武器求值，区分草案发送、引擎确认及实机结果；完成一轮后保存对应记录。画面回传不是骨骼编辑器，源姿态、蒙皮和 IK 仍按对应层修正。

本轮实际制作、转换或接入资产时，按 [资产生产登记与交付检查](../game-preproduction/references/asset-handoff.md) 同步维护既有权威清单：沿用稳定 ID，关联源文件、派生物、用途和实际证据。由执行方补齐本轮登记，不把补表留给用户；纯讨论与只读检查不写完成状态。
