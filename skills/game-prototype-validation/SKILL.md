# Risk & Assumption List 风险与验证

保留旧 Skill 名称，验证职责覆盖全部阶段与单独专业任务。按起止阶段、对象和交付范围选择检查，阶段外工作不误标通过；现有成果按依赖核对，缺证据不自动要求全项目重做。技术事实、专业判断和用户决定分别保存。新问题推翻旧结论时更新当前摘要、关联受影响验证，历史版本和独立有效结果保留。

验证发现的问题先记录适用版本、证据和判断，再关联负责的策划、美术或技术修改；测试失败不自动授权重设计。修订后保留旧证据并注明复测范围，文档修订不能把未复测项标为通过。 跨方向工作按 [变更联动](../game-preproduction/references/dependency-and-change-impact.md) 关联同一变更入口并更新管理摘要；仅安装本 Skill 时沿用项目现有变更记录，缺少管理 Skill 不阻塞本专业工作。

新作风险验证入口预先建立；计划、实际执行、未验证与中断分别记录。交付前核对任务、里程碑和管理入口是否链接本次证据并更新状态。新作运行收尾检查，不能只在聊天宣称测试通过而文件仍写“完成后补充”；具体检查见管理 Skill 的项目文件约定。

进入执行或解释结果时按问题选择：[实验设计](references/experiment-design.md)用于体验假设与原因区分；[数值与时序](references/balance-and-timing.md)用于规则、概率和动作窗口；[视听验收](references/audiovisual-validation.md)用于源文件、导入及动态表现；[性能验证](references/performance-validation.md)用于采样与瓶颈；[里程碑评审](references/milestone-review.md)用于原型、切片及交付取舍。只读取相关方法，不将所有专项检查作为每个小任务的门槛。

导航、移动交互、界面和教学问题使用 [可用性与学习验证](references/usability-and-learning.md)，记录操作者经验、行为与提示干预。模型或自动操作可以检查功能，不冒充初次玩家的理解、学习和舒适度证据。

地图按 [地图规划与迭代](../game-level-design/references/map-planning-and-iteration.md) 从当前玩家活动选择试验区域、起始状态和观察项，覆盖当前任务受影响的空间与规则；不把同一组路线或对抗指标套给所有关卡。草图静态检查、估算、软件输入和实际玩家体验分别记录，结论限于已测范围；需要多人对抗结论时取得相应样本。沿用既有阶段与授权，局部修改只回归相关依赖。

验证战斗动作、技能、敌人或相关资产变更时，按需读取 [战斗验证](references/combat-validation.md)，按实际规则选择功能、时序、表现与联网检查，不强制套用所有项目类型。

收到原型、切片或功能任务的实际运行记录时，读取 [运行证据与阶段评审](references/run-evidence.md)，核对结果适用版本，分别报告功能、体验、视听品质和阶段取舍。

新作初期使用 references/outputs.md。已有功能或资产变更、缺陷修复、实际试玩、原型及垂直切片验收时读取 [变更验证与回归](references/change-validation.md)。验证范围由改动和风险决定，不默认重做原型或重新立项。

维护 `Risk & Assumption List.md` 或项目已有的风险、测试与实验记录。先判断当前任务是提出假设、设计实验、执行实验、解释已有结果，还是对现有作品做逆向复盘。初期使用 [风险与实验指导](references/outputs.md)，已有变更使用回归参考，让证据回答一个具体决策。

汇总策划、美术与技术三侧假设，形成「假设 → 风险 → Prototype」对应表。Risk & Assumption List 初期只需要足以指导下一步验证的深度，不要求马上准备完整实验执行包。美术延期是未决事项，不自动等于阻塞性风险。

## 假设与实验

- 从设计、美术和技术文档提取可支持或否定的判断，关联体验支柱或系统关系。区分功能正确、性能可行、视觉可读、玩家体验与市场表现，它们不能互相证明。
- 按失败影响、不确定性和取证成本排序，不编造概率或精确风险分数。先补会改变规则理解的事实缺口，再检验体验解释。
- 最小范围须保留回答问题需要的因果链。例如测试收获是否激发下一次目标，不能只实现一次射击。初期只列验证方向；进入实施规划时再列范围、不做内容、依赖、步骤、观察标准、资源上限与停止条件；不要自动把完整游戏文档缩成这一范围。
- 技术试验注明构建、硬件、负载与指标口径；体验试验注明参与者条件、任务、观察行为和提示干预。没有数据不填任意满意度门槛，探索性研究允许结论不确定。
- 仅被要求计划时交付可执行计划；已授权实施才使用可用工具并记录实际操作。没有工程或工具时说明待执行部分，不把计划标为完成。

## 逆向复盘

区分三层：公开历史信号、基于信号提出的解释、未来拟做的观察/等效实验。开发者说做过调整不能证明调整效果；补丁记录说明特定历史问题，不说明当前仍存在，也不等于本次已复测。发售、销量或好评不能单独验证某个设计机制的因果作用。

未取得原始 MVP、预算、排期和实验记录时明确未知，不倒推出开发历史。若记录系统有 scope / outOfScope / resources 字段，标明是在记录历史未知，还是限定未来等效实验；不得将后者混写成原作首版范围。原作未知信息是取证缺口，不要求用户替原团队选择。

## 证据与交付

实施后的风险入口按 [风险与证据更新](references/outputs.md#实施后的风险与证据更新) 关联风险、判断标准、实际结果及下一步，不只汇总“若干测试通过”。对当前任务交付同时复核受影响文档能否解释实际规则、资产与工程；结构检查通过不能替代内容核对，也不能推定没有记录的行为已验证。

真实记录包含资料版本、构建/环境、操作、观察、日志或录屏位置与限制。分别判断“符合本次标准”和“支持假设”，允许不支持、失败或证据不足。结论指出继续、调整、补测或停止的依据，重大取舍沿用用户授权；模型不填写批准记录。

默认维护 `Risk & Assumption List.md` 或现有风险/测试记录，实际证据使用真实路径。同步已有项目管理入口的验证摘要、待办和下一步，不生成或启动看板。资料变更后保留历史证据并标明适用性；重复实验新增记录，不覆盖失败历史。用户指定的记录系统时遵守其字段范围，实验计划不能记成已执行实验。没有真实文件不生成假链接，也不把阅读公开文本记为亲自试玩。

验证涉及资产时，按 [资产生产登记与交付检查](../game-preproduction/references/asset-handoff.md) 把执行范围、结果和证据更新同一权威清单，并核对资产及使用方版本。记录完整度通过不代表未检查的视听品质通过。
