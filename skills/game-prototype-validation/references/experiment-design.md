# 将体验问题变成可执行实验

用于决定保留机制、比较候选或区分问题原因；功能是否符合已知规格可直接做回归，不必设计玩家研究。接续 [变更验证](change-validation.md)，参与者与提示干预按 [可用性方法](usability-and-learning.md) 记录。

## 选择能改变决定的问题

将“好不好玩”拆成当下能影响设计的判断：玩家是否理解代价、是否主动改变选择、是否愿意再次尝试，或某个规则是否阻断核心循环。写出可能支持、反对和无法区分的观察，不只设计能证明自己想法的任务。

区分故障、信息不足与偏好。例如没人买升级，可能是入口没发现、价格承担不起、作用不明或已有方案更合适。先核对功能与信息，再判断升级没有价值，否则会用经济改动补一个界面问题。

## 保留必要条件，控制无关差异

列当前构建、起始资源、目标、输入设备和场景，说明这次主动改变什么、其他关键条件如何保持。比较时避免同时改价格、奖励、界面和敌人强度；确需整包比较则结论只适用于整包，不单独归因某个参数。

参与者玩过第一版会学习路线与规则。可以在条件允许时改变体验顺序、使用新参与者，或缩小为同一熟练者的操作比较；说明选择和限制，不强制固定人数或统计方法。

## 假设例：补给与升级是否构成可理解的取舍

起始资源、两种购买机会和活动规则已由策划给出。给玩家完成区域的目标，不提前告诉其应该买哪个。记录看到商店、查看说明、购买/放弃、后续资源和遇险后的行为；操作结束后询问其理解的代价，原话与观察者解释分开。

如果按钮不可见，先归为信息/功能问题，不能用“无人购买”否定取舍；如果清楚知道升级价值但有意保留补给，这是策略选择，不是测试失败。若全部试玩者都提前知道最优路线，则无法支持首次探索情境的结论。

## 停止、解释与复测

执行前确定本轮时间/资源范围和会使实验无效的条件，例如关键功能不能用、起始状态错误。无效试次保留记录并说明原因。探索性实验可以得到“尚不能判断”；不要事后选择一个恰好通过的指标。

交付问题、候选原因、实验条件、实际观察、干预、证据、解释及下一项动作。量化数据写分母、样本范围和缺失情况；少量探索观察用于发现问题，不宣称总体比例或因果已证实。报告继续、调整、补测或停止的依据，阶段决定仍按项目目标处理。
