# 数值结算、动作时序与平衡验证

适用于伤害/资源结算、成长与奖励、动作窗口和组合迭代。战斗检查范围先读 [战斗验证](combat-validation.md)。把规则正确性、模型预测与真实选择分开：伤害算对了，不表示武器有价值；高胜率也不单独证明某个数值错误。

## 建立可独立核对的预期

从当前规格取单位、顺序、时点、上限、舍入和来源，而不是用被测代码生成自己的预期。缺少规则时明确缺口；用户已授权候选实验可使用标注的暂定规则，但不把程序现状直接当设计目标。

选覆盖不同结果分支的代表值：零/不足/刚好/超出、阈值两侧、重复或多来源、耗尽后恢复等。不是每个数值都穷举，更不需要为简单文案写自动测试。

假设目标 100 生命、每发固定 30、间隔 0.5 秒，首次命中在 t=0，则命中时点为 0、0.5、1、1.5，第四发击杀。用 100/(30/0.5) 得到约 1.667 秒不能作为此离散场景的预期。再增加前摇、飞行时间或换弹时应逐项明确，不把木桩时长当实战时长。

## 时序与竞争边界

记录输入请求、接受、成本提交、生效、结果和清理的时间或事件序号，使用同一时钟或解释时钟差。帧数需注明基准；渲染录像只支持其采样精度，不能据此承诺毫秒级输入延迟。

假设动作允许在 t < 0.6 秒取消，t = 0.6 秒先处理释放后拒绝取消。围绕临界点构造前、同刻、后输入，检查是否遵守这一项目约定；若规格没有同刻优先级，先要求补足规则。观察成本是否重复、已生效效果是否被错误撤销、循环表现是否残留。不要用大容差掩盖整段窗口错位。

## 分布与组合

随机奖励先验证合法池、权重归一、抽选/保底状态、种子与重复载入，再做多次样本分析。对独立概率 p 的 n 次试验，样本波动本来就存在；不能要求命中数精确等于 np。需要统计判定时预先说明方法和假设，不能从少数样本宣布分布错误。保底或无放回抽样不能继续当独立试验计算。

组合按实际依赖选择：低资源与冷却重置、死亡与持续效果、退款与重复提交等。发现循环收益先回查它是否有意，再判断漏洞；无需为不存在的多人或存档机制扩充测试。

## 从结果到调整

静态算例验证规则预测，自动断言检查实现，代表情境和真实试玩解释使用价值。按角色/场景/熟练度及可选机会比较，不直接把总使用率或平均输出当平衡目标。一次迭代尽量定位具体假设，复测保留对照条件。

交付规则来源、预期计算、输入序列、实测结果、异常与证据、当前结论能支持的范围。规格变化后旧报告保留并标明适用版本，不用新预期覆盖旧失败历史。
