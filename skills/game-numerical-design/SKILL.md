# 数值策划

从具体选择和结果进入：例如某次购买是否可达、升级改变几次命中、掉落多久获得、两种武器在什么条件下各有价值。读取已有规则、参数主源、单位、版本和观察；没有工程时按已知设计建立带假设的候选模型，不编造运行数据。

按任务规模完成目标、建模、核算和交接。少量参数直接在已有规格中处理；批量数据或反复计算才建立表格、脚本和模型报告。独立测算可直接完成，不要求先建立整份 GDD、启动引擎或调用全部职业。阶段仍沿用立项、玩法验证、制作验证、内容制作、最终交付，任意阶段按需参与。

## 职责与决定

本 Skill 负责定量模型、参数推导、候选比较和模型偏差解释。系统策划维护资源用途、解锁/交易/保存规则及系统关系；战斗策划维护攻防选择、动作承诺、反制窗口和节奏；关卡提供内容量、路线与遭遇条件。按语义分工，不把所有数字都收归数值策划。公式改变结算语义、调参改变动作或破坏已定机会时，与规则主责关联同一修改，不能静默改机制。

每个参数只有一个已声明的编辑主源，区分作者配置、计算派生值、运行覆盖和交换副本。明确目标、推算、素材默认、暂定和实测的来源；未知不填零，教学算例不成为项目默认值。用户已授权具体数值修改时完成相应重算与影响说明，不强制额外审批，也不擅自调其他参数抵消修改。

## 交付与闭环

交付适合当前问题的公式/曲线或表格、参数来源、单位与时点、假设、代表算例/边界、候选取舍及影响。只要求设计或检查时到此交付；已授权应用到工程时继续按技术侧 [数值交换](../game-technical-design/references/numeric-exchange.md) 更新真实主源和消费者，验证侧按 [平衡验证](../game-prototype-validation/references/balance-and-timing.md) 检查实际生效与代表行为。未安装其他 Skill 时沿用项目已有导入、记录和验证方法，不将其列为强制前置。

模型、计算与真实实验分别留证：模拟胜率不是玩家胜率，公式正确不等于平衡，配置已写入不等于运行已生效。沿原功能/任务保存决定和差异，管理入口只汇总；无需新增项目根文档或数值专属阶段。
