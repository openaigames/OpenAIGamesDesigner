# 从体验问题建立数值模型

## 明确问题与口径

先说明谁在何种条件下作什么选择、希望改变什么结果。将目标写成可比较的条件或范围，例如完成三次活动后有能力购买一次升级；没有依据时保留候选范围，不把个人偏好的时长写成行业标准。仅知识、空间或剧情进展的设计无需强加等级和货币。

区分可调输入、机制约束、推导输出和观测数据。每个量注明单位、适用对象、时间范围与来源：单次/累计、税前/税后、全流程/有效输出窗口、目标血量/实际承伤都不能混用。帧数须注明基准频率，暂停、变速和真实时间分别处理。

模型只纳入会改变当前判断的机制。写明结算顺序、舍入/截断、上下限、特殊分支和参数合法域，先用少量手算检查单位和极值，再选择表格或程序。零伤害、分母为零、不可达状态应给出明确语义；不能靠微小常数将不能攻击的角色算成最终能击杀。

## 专业接口

| 工作 | 当前任务需要约定的边界 |
| --- | --- |
| 系统 | 是否有等级、奖励用途、保存与重配政策由系统设计；成本/收益和曲线由数值推导；新增保底或兑换限制是规则变更 |
| 战斗 | 战斗提供距离、承诺、机会和反制目标；数值比较伤害、破防与资源收益；前摇不是可以脱离动画和反制随意优化的数字 |
| 关卡 | 用真实内容量、活动时间、路线和遭遇分布估算供给；理论每分钟产出不能假设玩家始终有目标可刷 |
| 工程 | 明确配置主源、派生产物、覆盖层与实际使用方；数值规格不指定所有工程改为 JSON |
| 验证 | 数值给可复核预期与假设，测试执行输入/观察，双方分析偏差；存在缺口时不互相代填通过 |

跨专业改变已定规则时，沿同一功能变更记录目标、候选与影响。小调整复用已有规格；没有依赖变化时无须重新召开全套设计或重建阶段任务。

## 选择求解方法

能解析计算的确定关系先计算并检查边界。重复配置可用表格；有状态、策略或随机依赖时再用枚举/事件模拟/抽样。声明策略、初始状态、样本范围、终止条件和未覆盖因素，不把理想最优操作当普通玩家行为。无可行解时展示冲突的约束，提出可解释的修改；不静默扩大攻击窗口或赠送资源让模型成立。

需要比较多个目标时分别展示，比如输出、资源效率和风险；权重若无项目依据就不合成一个“最优分数”。同一配置可能在不同目标上各有收益。

## 共享工具的实际范围

源码 `tools/numeric_workflow.py`，安装包 `game-preproduction/runtime/tools/numeric_workflow.py`：`model` 接受显式算术树、分段线性曲线或阶梯阈值，生成预测/观测 JSON 与 HTML；`model-check` 检查依赖是否变化。模型参数引用实际 JSON pointer、参数出处、单位和适用条件；预测文件不是新的参数主源。格式与命令在共享 runtime 或源码 `tools/README.md` 的“项目看板与资产核查”中的数值预测说明。

现有模型器不内置概率分布、随机模拟、自动拟合、通用优化或 Excel 公式重算。复杂分析使用项目中可审阅的脚本或 Agent 运行环境计算工具，保留输入、方法和执行结果；不要把模拟结果填进要求真实运行执行记录的 measurements。数值表 `export → plan → apply` 的格式及导入边界见 [数值表与交接](numeric-authoring.md) 和技术侧交换参考。
