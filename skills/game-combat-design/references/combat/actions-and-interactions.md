# 动作、技能与交互规则

用于制作攻击、防御、技能、道具动作或修改其交互。动作应服务系统中的选择，不能仅由动画资源或实现框架能做什么来定义。

## 从用途到行为合同

先说明动作的战术用途、适用情境、风险与替代选项，再定义输入、激活条件、目标、阶段、结果与结束。重复的实现类型可以共享规格，但保留真正改变决策的差异。

动作可以有前摇、生效与恢复阶段，也可以是即时、持续、引导、多段或回合动作；只使用适用模型。记录时间单位、计时基准、暂停/变速影响，帧数须注明基准帧率。若效果由事件或回合结算触发，说明事件/顺序，而非强行转换为动画帧。

| 合同部分 | 需要说明的规则 |
| --- | --- |
| 请求与激活 | 谁请求、何时合法、条件不足的反馈、输入何时消费 |
| 承诺与阶段 | 何时支付成本、开始冷却、能否转向/移动/改目标 |
| 生效 | 目标合法性、命中方法的设计要求、结果计算入口 |
| 重复与持续 | 每段/每目标命中次数、持续间隔、重入和叠加规则 |
| 结束 | 自然完成、取消、受击、死亡等适用分支及剩余效果 |

“命中方法的设计要求”描述玩家应感知的范围、遮挡和时机；具体碰撞查询/API 由技术侧决定并验证。

## 交互不是几个独立开关

对本次涉及的攻击、闪避、格挡、受击、控制和死亡，明确能否进入、能否同时存在、谁中断谁、在哪个窗口发生。仅复杂关系需要矩阵；不能从状态名称猜优先级。

尤其区分：不能激活、激活失败、被取消、被打断、正常结束。它们可能有不同的资源、冷却、输入缓存和表现后果。已发射的投射物或持续场是否随施法者中断消失，需要单独规则，不默认所有效果跟随动作生命周期。

连段按需定义连接条件、窗口、输入缓存、失败落点与循环边界；不要只列 A→B→C。防御按需定义保护方向/类型、成功/失败后果及资源关系；无敌、减伤、免控和不被硬直不是同一概念。

目标在执行中死亡、脱离范围、变为友方或不可选时，规定继续、重选、失效或部分结算。多段、多目标、穿透、反弹、召唤等仅在项目需要时展开，避免漏掉同一目标重复结算或效果来源归属。

## 命中与反馈的一致性

说明命中确认、伤害/状态、受击反应、击退和表现事件的关系。攻击命中但被免疫、格挡或吸收，可能仍需要不同反馈；不要把“播放受击动画”当成伤害已结算。

动画事件、视觉武器轨迹与实际判定要能被技术/美术解释；命中停顿、镜头与音效是表现手段，不在未定目标时强制加入。动作变速需检查判定、取消、位移和特效持续是否按规则同步。

这项修改至少要确定：哪些阶段可取消、已支付资源如何处理、冷却是否已开始、已产生效果是否保留、输入是否转交闪避、状态/表现如何退出。若“效果已释放后立即无成本取消恢复”也被允许，可能改变该动作的输出风险，需关联系统目标分析，而不只勾选 CanCancel。
