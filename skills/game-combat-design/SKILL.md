# 战斗策划

从本轮体验目标、现有规则/实现、实际素材能力和问题证据进入。新机制先说明玩家在什么信息下采取什么行动、付出什么代价、产生什么后果；已有战斗先定位具体情境，不因“手感不好”重写全部系统。可先探索素材再形成方案，已定目标与暂定实现分别保存。

## 做出可实施的战斗决定

1. 确定交战距离、相对位置、视野、可用动作与信息。玩家、敌人、装备是不同对象，玩家武器不自动成为 Boss 的要求。
2. 将动作写成条件、输入、提交、命中/失败、恢复、取消/受击和清理的关系。定义伤害/资源提交的权威源；动画播放成功不应直接代替规则成立。
3. 比较预警、玩家识别/移动时间、追踪和攻击覆盖共同留下的应对空间。长前摇未必公平，若追踪到命中前一刻仍可能没有应对机会；把追踪截止与闪避、走位、打断等实际反制一起测试。
4. 为数值标来源和单位，区分素材默认、作者示例、项目设定、实测与暂定估计。相同条件下调整一个有因果依据的变量，再观察代价、机会和压力变化；不用测试数量证明打击感。

向关卡提供实际移动/攻击范围、预警、遭遇组合与反击空间；向动画提供动作意图与时序边界，向 VFX/音频提供事件、主次和中断语义。程序实现输入、状态与判定，不能让每个表现层各扣一次资源。使用同一对象/动作 ID 和现有配置；GDD 总索引链接本专业规格，不维护第二份招式表。

直接战斗任务可独立进行，不需要先调用全部策划 Skill。阶段任务沿项目的起止阶段与终点执行；只做策划交付时给足规则、算例与实验依据，实施任务继续到实际修改和验证。交付本次规则、取舍、源参数/生效值、实际交战证据和未解决问题；区分功能、战斗假设、动画表现与用户认可。
