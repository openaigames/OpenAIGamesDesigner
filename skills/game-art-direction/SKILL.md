# 游戏美术方向

表现或资产要求变更先落在美术入口或资产规格，再检查玩法可读性、技术导入与运行约束及视听验证。规格已更新、资产已制作、已导入和已验收分别记录。 跨方向工作按 [变更联动](../game-preproduction/references/dependency-and-change-impact.md) 关联同一变更入口并回写管理摘要；仅安装本 Skill 时沿用项目现有变更记录，缺少管理 Skill 不阻塞本专业工作。

新作 Art Direction.md 入口预先建立，最终风格可以待讨论。实际采用占位模型、动画、VFX 或声音后主动记录来源、用途、临时表现与限制；不因最终美术未确认而让文件一直空置。

资产记录采用可逐项更新的 Markdown 表格，不把多个模型、动画及其来源/进度挤在一段话里。资产总览、来源与交付进度按共同标识关联；战斗动作按对象与动作映射到资源。格式见 [资产与动作记录表](references/outputs.md#资产与动作记录表)。方向意图、比较理由和限制仍用短段落。已有权威资产表时原位维护并链接，不另造重复清单；未知填待定，不能为了填表虚构资源或完成状态。

进入初版可见资产制作或集成前，先明确本轮资产方案：用户是否接受白模/占位、复用哪些已有素材、主要角色采用什么模型及动作来源。提出简短可比较的方案并依据回答记录；“做 Demo”“先验证玩法”或只选引擎，不自动授权任意几何体、角色外观或程序摆动代替所需动画。用户明确委托素材选择或已有有效方案时直接沿用，不逐个文件反复确认。方案仍待决时可继续设计、素材只读检查和不依赖该决定的工程工作，先不落实受影响的资产选择。方法见 [资产执行与登记](references/asset-execution.md)。

进入制作深度时按问题选择：[风格生产规则](references/style-production.md)用于建立一致基线与变体；[资产制作规格](references/asset-production-specs.md)用于角色、环境和材质；[动态视听制作](references/animation-vfx-audio-production.md)用于动画、VFX 与声音的事件配合；[生成素材质检](references/generated-asset-review.md)用于候选筛选和返修。局部任务只读相关资料，初期探索不要求填写完整生产手册。

进入实际资产制作、替换或转换时，读取 [资产执行与登记](references/asset-execution.md)，将规格连接到本地工具任务、真实产物和检查结果。

环境制作、灰盒转美术或路线线索问题使用 [环境可读性](references/environment-readability.md)；移动/交互动画、界面动效与状态资源使用 [动作与界面表现交接](references/animation-and-ui-feedback.md)。读取实际规则和镜头约束，表现不独立决定操作成功或世界状态。

涉及战斗动画、命中反馈、技能 VFX 或声音时，按需读取 [战斗表现交接](references/combat-presentation.md)，关联动作规则、资源与真实运行表现；不因战斗任务重新制定整个项目风格。

新作初期使用 references/outputs.md。已有项目新增、替换或修改角色、场景、UI、动画、VFX 或声音素材时，读取 [资产制作与变更交接](references/asset-change.md)。以现有风格和实际引擎用途为基线；局部资产任务不重做整套美术方向。

读取核心体验、镜头、平台、任务目的和用户要求保留的品牌/角色/颜色。初期方向参考 [美术交付指导](references/outputs.md)，资产任务使用变更交接参考，让每项表现选择说明它怎样支持玩家行动与判断。

## 渐进美术讨论

Art Direction 是持续完善的文档，不要求立项开始即完整。已有要求先记录，未决定的方向保留待讨论；用户选择晚些决定时不反复追问、不阻塞其他文档。推迟最终美术不等于已同意初版白模；占位验证在本轮占位范围已有依据或明确委托后推进，不要求先完成最终角色设计。

分开维护三类内容：Moodboard（颜色、氛围与风格的讨论依据）、Concept Art（用插画表达本项目的整体或关卡想法）、Reference Image（具体角色、建筑、物件、材质等结构参考）。三者都可先占位，不能用同一组图假装全部完成。

风格模糊时，可先用可用的图片搜索工具找少量有差异的真实参考并展示，与用户讨论喜欢的颜色、氛围、剪影或材质；不必先写满美术规范。保留图片出处、借鉴点和用户意见，选择后整理 moodboard 与基调。不能把找到参考图当作用户已选风格，更不能把它当作可直接制作的自有资产。

Concept Art 与 Reference Image 可以等后续讨论补齐，也允许用户自己上传。每类记录待补什么、已有候选、选择/修改意见；占位不是失败或已完成。宿主只有外部搜索入口、禁止模型联网或无法看图时如实说明能力，不伪造“模型已搜索/已看过”。

## 观察与设计

- 定义或观察剪影、比例、场景结构、明暗与色彩分工、UI 信息层级、特效反馈；声音有实际材料或明确设计任务时再分析。不能用“卡通、精致、沉浸”代替具体要求。
- 区分看到的特征、对用途的推断、给新项目的制作建议。至少建立“观察 → 玩法作用 → 如何验证”的联系。截图不能证明动画时序、声音或菜单是否暂停；视觉简化不等于已知面数、贴图尺寸或资产成本。
- Moodboard 表达色彩氛围，Concept Art 表达项目想法，Reference 提供具体结构/材质依据。参考保留真实来源、版本线索、所看内容与借鉴点。只有确实看到图像才描述图像；文件名、附件元数据和文字介绍不等于看过。
- 新作方向需比较时给少量有差异的候选，可使用现有图或可用生成工具准备预览；无工具时交付方向说明，不伪造图片。逆向已有作品先观察，不擅自生成一个替代风格再称原作分析。

## 资产与来源

风格参考、素材获取渠道、真实文件与可用许可分别记录。新项目制作路线未知时就当前重要部分聚焦询问，已答或延期不重问；原作来源未公开则标未知，不根据署名或风格推断自制、外包、资产商店或 AI 使用。

制作任务中按用途列本轮需要的交付项、数量、格式、规格与验收条件，区分占位与正式。根据维度与用途拆分，不机械套用完整 3D 流程。图像生成不证明模型拓扑、骨骼或材质合格。

候选选择绑定实际版本，记录用户意见并沿用授权；文件存在、方向选定、质检通过和引擎导入分别记录。只在已授权的工程接入任务中导入，不因写文档自行变更品牌或引擎资产。

## 文件与交付

默认将方向、参考及制作要求维护在 `Art Direction.md` 或现有美术文件，详细资产规格可单独链接。保存后同步已有项目管理入口的文档状态和变更摘要，不生成或启动看板。用户指定结构化宿主时再映射到其允许字段；文档任务不冒充资产生产。参考未查看、资产未生成或导入未验证时明确记录，不虚构预览链接、工具操作或确认。
