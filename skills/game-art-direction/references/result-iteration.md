# 根据评审结果迭代资产

已有源资产质量报告需要继续修正时，用共享运行目录的 `tools/asset_iterate.py`。命令和格式见[结果驱动迭代](../../../adapters/assets/result-iteration.zh-CN.md)，示例见[计划模板](../../../templates/asset_iteration/README.zh-CN.md)。

1. 读取报告及其原图、模型、参考与实际用途。失败项才进入生成修正或加工；未知、缺视图、低置信度先补证。不能从分数猜原因，也不能把未看过的图写成观察。
2. 执行 `draft`，依据问题选择 regenerate、postprocess、collect_evidence、accept 或 stop。每项调整说明引用的问题、原因及下一轮可观察结果。保留原始描述、必须特征、负面要求和参考职责，不借修正添加未要求的设计。
3. 优先选择能作用于实际输入的最小调整。图生模型不接收文字时更换符合缺陷的参考并重查关联路径；枢轴、碰撞和确定性结构加工交给相应工具。语音台词保留字面内容。工具不会自动写有效创作指令，Agent 对具体调整负责。
4. 完成实际评审后运行 `prepare`，查看本轮预览及 prepared 预览。排队、收费执行与结果恢复沿用既有授权；不得把本轮工具当作自动扣费重试。版本父子关系只是来源，不自动发送父图、选用新版本或替换项目。
5. 对实际结果重新采集并评审，保持用途、环境、标准、容差、视图身份和延期门槛。绑定本轮 preparation。复查目标与所有已通过项，不能用新总分掩盖旧要求退步。加工或补证保留先前 preparation。
6. 执行 `compare`，下轮传 previous。疑点消失还要语义复查；同一结果换文件名或重新打分不算生成进步。连续无进展、达到上限或退步时遵守停止/换方法建议，保留历史并解释新的基线与策略。
7. complete/accept 只覆盖报告声明的源资产范围。引擎与游戏验证、许可和实际选用分别执行。记录生成服务真实执行、外部文件登记或本地测试夹具来源，不把手工结果说成模型生成效果。
