# 角色、环境与材质的制作规格

在 [资产交接](asset-change.md) 的用途、来源和消费者基础上，把镜头与玩法约束落实为制作者可执行的要求。规格使用项目已有文件或 `templates/asset-spec.md`；选择实际资产类型，不给 2D 图标附加整套骨骼和模型要求。

## 用场景证据确定规格

先取得默认/最近镜头、目标显示尺寸、玩家或关卡尺度、可交互边界以及预计同时出现数量。区分来自现工程的测量值、批准的目标、待试制候选。面数、贴图大小和动画数量不是从“独立游戏”或“3A”标签直接推导的。

假设像素角色身高为 64 个源像素，选定相机下显示为 192 屏幕像素，则这次画面的放大为 3 倍。若另一资产想保持相同像素密度，要在同一相机与缩放条件下比较；把图片导出得更大不必然更清晰。窗口缩放、非整数缩放和镜头运动可能改变结果，需实际观察。此例不预设所有游戏必须整数缩放。

## 按生产对象补足约束

| 对象 | 交付需要明确的内容 | 选择依据与常见返工原因 |
| --- | --- | --- |
| 2D 角色/帧动画 | 源画布与可见范围、接地锚点、方向、帧顺序/时长、挂点、图集边距、透明边缘 | 锚点稳定才能比较动作位移；画布统一不代表每帧轮廓必须相同；图集与独立帧采样条件不同 |
| 3D 角色 | 单位、朝向、原点、轮廓、材质槽、骨架兼容及变形测试姿态 | 拓扑密度分配依据关节变形与轮廓；静止预览正确不代表抬臂或蹲下不穿插 |
| 模块环境/地形 | 尺度基准、拼接边界、原点、旋转方式、碰撞/通行面、模块变体 | 单块好看可能拼出缝、遮住入口或改变已验证跳跃距离；先验角落、交汇和高低差组合 |
| 材质/贴图 | 每张图的语义、通道、色彩解释、平铺/接缝、透明方式、采样和压缩要求 | 文件名不证明通道含义；着色输入与颜色输入应按真实引擎导入规则解释，不能套固定通道打包习惯 |

技术侧核查实际导入设置与着色实现；美术定义希望呈现的形态、材质层次和可接受瑕疵。没有 UV/骨架需求的资产不为模板增加这些步骤。

## 假设交付例：模块门框

假设灰盒已验证门净宽 2 个项目单位，玩家碰撞宽 0.8，门框模块占宽 2.4。规格将“通行净宽 2”列为需保持约束，把磨损、装饰和材质作为候选变化。源文件包含模块原点与单位；运行资源包含外观和实际碰撞，消费者是门场景。

先拼接两侧墙和一个转角，在真实角色与镜头下检查通行、斜向接近和遮挡。如果新增装饰侵入通道，应调整装饰或回交关卡/技术修改约束，不能只让渲染模型缩小却留旧碰撞。完成依据是代表组合中的实际效果，不只是导出文件存在。

## 交付边界与返修

列主文件和必要依赖、可编辑源、导出版本、绑定消费者以及检查场景。只有项目需要时增加 LOD、碰撞代理或其他派生物，指定由谁生成和如何比较，避免美术与导入脚本各维护一份不同版本。

问题单写对象/版本、观察条件、可见缺陷、预期与影响。例如“默认相机向右移动时脚底逐帧漂移”比“动画不稳”更可修；先区分锚点、根位移和控制器问题。生成素材另按 [候选质检](generated-asset-review.md) 处理，运行验收交验证侧，不以规格填写完整代替质量通过。
