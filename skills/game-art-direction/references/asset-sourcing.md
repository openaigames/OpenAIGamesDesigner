# 素材检索与获取

用于寻找免费或其他符合本轮预算的图片、精灵、3D 模型、动画、VFX、声音、材质和字体等游戏资源。将现成素材复用、必要修改、自制和已允许的生成方式一起比较，按用途、表现与适配成本选路线；不固定素材网站、提供器或必须先搜索再创作的顺序。

选材依据使用已有方向摘要、适用图板版本与资产设计说明：先判断素材能否承担本轮身份、体验和可读性要求，再比较适配成本。没有图板时直接使用已知规格；有精美或免费的候选也不据此改写既定方向。参考图片入板与实际资产获取分别记录，展示图不能代替可用的模型、动作或特效文件。

## 从需求与已有委托开始

用户要求寻找素材，或已授权的制作任务遇到资产缺口、替换占位、新增对象/动作/反馈时，主动检查项目已有资源，再按需要检索外部候选。仅研究或要求推荐时交付有依据的比较；已要求制作、获取或接入时，在对应范围继续执行，不停在网站清单。

读取资产用途、现有风格、镜头/平台、引擎与渲染条件、必要动作、预算和来源要求，只补充会改变当前选择的缺口。条件来自已有规格、实际工程或用户决定，不能为了搜索先要求完整美术手册，也不能自行填入面数、骨架或渲染管线。

已有有效资产方案，或用户已委托在某种风格、预算和来源范围内选材时，可直接比较、选择、获取并执行已授权的处理，不逐个文件重复询问。没有选材依据时先做可用性和兼容性检查，提出简短方案；只把影响本轮效果、范围、成本或制作路线的未决选择交给用户。选材委托不自动扩大为更换引擎、引入玩法框架或使用未授权服务。

Moodboard 的确认只约束图板制作，不阻塞其他已授权的素材检索、修改与创作。图板拒绝、暂缓或尚未答复时，沿用已有可执行方向或委托继续；方向仍未定则保留素材候选，不将其升级为项目基线。需要制作新板时仍按 [制作意愿与风格确认](moodboard-and-palette.md#先询问是否制作再确定风格) 执行。

## 搜索实际资源并比较路线

将用途转为适合该类型的检索条件，组合风格/对象、资源类型、必要内容、格式或引擎条件。例如找动作需要具体动作名称和骨架线索，找 VFX 需要可编辑效果或可用序列及目标运行环境；图片检索得到的渲染图和演示视频只是查看入口，不是模型、动画或特效文件。

使用当前宿主可用的搜索、浏览、资源库或本地工具，优先追溯作者、正式资源页面与包内说明。搜索摘要、旧文章和聚合页用于找线索，当前价格、下载内容、版本和许可依据回到实际资源核实。查看与用途有关的预览或文件，区分“页面声称”“已查看预览”“已检查文件”“实际运行”；未看到或听到的部分不写观察结论。

按关键需求筛出少量值得比较的候选，不机械要求固定数量或遍历全部网站。比较可用内容、风格差距、依赖、缺口和修改工作；说明推荐理由、淘汰原因及未核实项。模型、动作、持物附件和反馈有依赖时比较可配合使用的组合，不分别选中后才假定兼容。一个已满足需求的资源包可直接沿用，无需凑备选。

找不到合适资源、候选关键条件不符，或继续搜索/适配已超出本轮成本范围时，调整检索条件或比较修改、自制、已允许的生成方式，说明取舍后按已有委托推进。免费不等于总体成本最低，也不要求为了零价格改变已定角色或玩法。工具不可用、访问或下载受阻时保留真实缺口，继续可用的本地资源、其他来源或制作路线；需要用户补充访问条件或做取舍时，只处理该阻塞点，不伪造搜索和获取结果。

## 按资源类型核对可用性

以下用于选材和估计适配工作，只检查本轮涉及的项；具体制作参数沿用 [资产制作规格](asset-production-specs.md) 和项目实际工程。

| 类型 | 获取前后需要核实的内容 |
| --- | --- |
| 图片、精灵、UI 与 2D 动画 | 实际图片/图集与可编辑源是否包含；透明通道、方向/状态/帧覆盖、切分和锚点能否支撑目标显示与播放 |
| 3D 模型 | 格式、单位/比例、贴图与材质依赖；需要变形时是否有可用骨架和权重，目标动作下的形变；复杂度以文件数据和项目要求核对，不从预览猜测 |
| 动画包 | 实际动作列表、骨架/绑定姿态、原地或根运动、循环和持物姿态；列出缺失动作与重定向工作，同为 FBX 或同称人形不证明匹配 |
| VFX | 是引擎原生效果、序列贴图还是仅演示；引擎版本、渲染管线、粒子/着色器及插件依赖，所需触发、附着和结束方式；跨引擎使用需评估重建，不能只改格式即称兼容 |
| 音效、音乐 | 实际音频与包内覆盖、格式/声道、循环边界及用途；评价音色、响度或衔接需实际试听，预览不证明全包质量 |
| 材质、纹理 | 实际通道、平铺/透明需求、分辨率与可编辑源；材质球或渲染图不等于贴图齐全，目标着色器的输入需另核对 |
| 字体 | 实际字体文件、项目语言和所需字符覆盖、目标字号的可读性及嵌入用途依据；展示图包含文字不证明字体包包含那些字符 |

“动作模组”可能是动画资源，也可能是包含代码和规则的插件，依据包内容辨别。需要插件时把功能、依赖与接入工作交技术侧评估，不能因选择动作包就安装整套战斗框架或改变规则。动态资源的事件配合与运行检查见 [动态视听制作](animation-vfx-audio-production.md)，涉及战斗时另见 [战斗表现交接](combat-presentation.md)。

## 保存来源与使用依据

按具体资源及版本记录作者/提供方、原始页面、当前价格条件、许可名称与原文位置、核查日期，以及与本轮用途有关的要求或待核实项。按项目实际需要检查使用、修改、署名和分发条件；个人原型的依据不能直接写成正式发布或商用已获许可，公开展示或可免费下载也不等于许可已核实。用户提供的包沿用随包依据和用户说明，不凭上传动作推断所有权利。

包内不同资产或附带依赖有不同来源时分别关联，署名要求保存到项目已有署名记录或交付待办。仅找到预览、缺许可或条款用途不明时可保留候选和核实项，不能把它记为可正式使用；按本轮用途另找有明确依据的方案。保留原始许可材料与核查范围，不把本方法当成法律结论。

## 获取、处理与交接

实际素材与说明文件保存在目标游戏项目的已有资产目录；无约定时可使用 `assets-source/`，不写入 Skill 目录。保留包内贴图等相对依赖、README/许可及版本线索；已有同版本文件可复用，避免重复下载或静默覆盖。原始文件与修改/转换后的派生版本建立关系，记录所用工具、处理内容和实际产物，按项目已有机制保存校验值或版本记录。

获取后检查实际文件是否可打开、内容与依赖是否满足用途，再做需要的处理。格式转换不自动补齐骨架、动画、材质或 VFX 系统。选用、获取、文件检查、适配、导入和运行验证分别记录；部分完成时只更新对应事实。下载素材记为外部获取，自制或生成记录实际制作方式，不编造提供器执行或生成任务。

记录复用 [资产与动作记录表](outputs.md#资产与动作记录表)，同一资源包的来源信息共用，资产行引用实际版本及用途；不另造必须填写的完整素材库。候选与适配比较可放在对应资产规格中，采用后保留重要取舍和剩余缺口。

工具调用和外部文件登记见 [资产执行与登记](asset-execution.md#工具执行)。美术侧交付选用理由、文件/依赖、来源依据、必要修改与可观察的验收条件；技术侧接续已授权的导入、重定向、着色器/插件适配和消费者引用，验证侧检查实际显示、动作播放、特效生命周期或声音表现。没有共享工具或其他 Skill 时沿用项目已有能力，完成可执行部分并明确剩余工作，不把登记或预览成功写成游戏内通过。
