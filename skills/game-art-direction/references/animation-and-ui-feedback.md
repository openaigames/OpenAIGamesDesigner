# 动作与界面表现的状态交接

用于移动/交互动画、界面动效、输入提示及非战斗反馈。战斗专门事件继续使用 [战斗表现](combat-presentation.md)，资产来源与替换使用 [资产变更](asset-change.md)。

## 状态到表现的映射

读取策划的真实过程与技术状态来源：可用、选中、请求、进行、成功、拒绝、取消中哪些存在。每项说明玩家应理解什么、开始/结束信号、承载资源和反馈层级。

请求被接受与操作成功应可区分。进度动画不能先于实际成功展示“已完成”；规则失败时要停止或改写相应表现，不能只补一行错误文字而保留成功音效。

声音、特效、动画、镜头、触觉和文字选择合适组合，不把所有通道同时用满。降低或关闭强动效后保留必要状态信息。

## 角色动作交接

按实际资产表达明确朝向、原点/根、挂点、姿态、循环与过渡、位移来源和关键事件。2D 帧动画不套用完整骨骼要求；3D 模型则核对真实骨架、比例和动作兼容。

启动、循环、收尾、取消和失败只为实际存在的状态提供资源或复用策略。变速、切换目标、提前退出时要定义混合、挂点和循环声清理；动画结束不自动代表游戏操作完成。

规则需要的时序先约定，表现可以建议调整但不直接修改规则。动画事件的触发可靠性和位移接管交给技术核查，不能在美术文档写成工程已支持。

## UI 资源与动态表现

基于玩家任务和焦点设计视觉层级，准备实际需要的默认、选中、禁用、处理中和失败状态。缺失素材可以复用或占位，但标明范围。

规格包括尺寸/缩放、切片/边距、图标含义、文本区域和动效时序中的适用项。长文本、最大数值、不同输入提示和布局重排需能容纳，不仅检查默认截图。

交付事件—资源—消费者映射、状态差异、开始/结束/取消规则、实际来源及检查条件。视听资源可用、成功接入、体验可读分别记录。
