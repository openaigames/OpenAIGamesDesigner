# 资产版本与迭代记录

适用于设定图、平面图、角色图片及其他持续修改的交付物。以一次可供比较、选择或交接的结果为版本；不要求逐笔、逐帧登记编辑过程。临时中间文件可留在制作目录，但不能把未保存的聊天图片当成可恢复的历史。

## 身份与保存

- 一组版本对应同一交付物，例如“主角造型设定”。同一主角的设定图、模型、动作、音效分别建组，通过对象和明确参考关联。不能因为同属“主角”就成为同一组版本。
- 每版保存独立文件、内容摘要、制作时间、实际来源、修改说明、父版本及参考版本用途。源文件后来被覆盖，历史副本仍可读取；快照损坏时停止选用和作为输入，提示恢复，不能悄悄改写摘要。
- 同次生成的不同方案各建一个版本，共用实际底稿，不能伪造为依次修改。同方案的正面／侧面／背面、模型与配套贴图等用一个版本的文件集合保存。相对目录保留；登记前检查并带上真实依赖，不承诺自动找齐外部依赖。
- 旧项目不按文件名猜造父子关系或默认认可旧图。可以保留原路径，用户需要时明确加入版本记录。只有事实依据足够时才补录关系。

## 选用、分支与游戏接入

“最新生成”“当前选用”“工程目录中的实际文件”分别表达不同事实。新结果先作为候选；按用户明确选择或有效的自主选材委托更新当前选用。浏览器默认显示当前选用；尚未选用时展示最新未归档版本，并明确未选用。

选回 V2 保留 V3、V4；从 V2 继续修改创建新编号，parent 指向 V2。需要 V2 的结构与 V3 的颜色时，将 V2 记为修改底稿，V3 记为“配色参考”，并把相应真实文件交给支持多参考的工具。当前服务接收数量不足时调整制作方式，不悄悄丢掉参考。

归档只折叠历史，不删除文件，当前选用版须先改选其他版本才能归档。选用不迁移文件、不替换引擎资源、不更新已绑定动作或自动认定品质通过。正式接入仍由技术制作和运行验证负责。游戏实际使用哪些版本，以明确源路径、内容摘要、内容根和工程证据核对，不能只看“选用”标记。

下游产物固定引用制作当时的版本。参考资产后来改选时，保留原关系并显示复核提示，不自动重新生成、重绑定或作废仍有效的旧成果。

## 记录与看板

项目 `.openaigame/asset-versions/index.json` 是版本历史的权威记录；同目录保存不可覆盖的文件副本。生成任务记录输入快照、实际工具与输出，版本记录链接任务，不在多个文档重复维护全部历史。

已有 Art Direction 保留专业正文、对象与用途，自动版本摘要只链接当前选用、最新结果和权威记录。没有该文档时不为保存版本强行新建整套设计文档。生成路径、未知许可或未验收状态按事实填写。

资产库每组显示一张卡，详情提供历史、双版本对比、重新选用、归档和“从此版继续修改”。多文件可逐项查看；模型和特殊格式沿用原预览能力，图片对比不宣称已核对骨架、引擎材质或运行效果。资产分类仍按文件维护，版本分组不替代分类；候补／游戏应用仍按实际目录判断。

共享 runtime 的 `tools/asset_versions.py` 提供 `list`、`apply`、`record-native` 和 `link-job`。API 任务完成时自动登记，登记失败保留成功的实际输出并报告错误，通过 `link-job` 恢复，不能为了补历史再次收费生成。内置工具结果在真实保存到项目后用 `record-native` 登记；请求文件与配套文件格式见 runtime 的 `tools/README.md`。没有共享工具时沿用项目已有版本库并记录同样的关系，不声称已接入看板。
