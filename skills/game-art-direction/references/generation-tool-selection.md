# 生成工具选择

先判断任务需要的交付物，再选择当前可用的工具。保存 API Key 只表示服务可配置，不构成默认选用或收费授权。

| 需要的产物 | 选择方法 |
| --- | --- |
| 设定图、角色图片、平面图、图标、贴图等栅格图像 | 当前宿主有合适的内置生图／编辑能力时优先使用；明确指定 Seedream、项目已有固定服务流程，或内置能力无法满足需求时，再采用相应服务 |
| 可编辑平面图、矢量图、UI、图表 | 优先项目原有的可编辑制作工具；栅格生成图不能替代结构数据、真实尺度或布局约束 |
| 可导入的 3D 文件 | 结合已有素材、建模工具及已选的 Tripo／混元等服务；内置生图产生的图片不能登记成模型 |
| 音效、配乐、台词 | 沿用音频 Skill 的事件时序、监听与授权要求；按需使用 ElevenLabs 或项目已有工具 |
| 视频 | 在需要视频交付物时使用已选的视频工具；Seedance 生成的视频不等于可编辑的游戏角色动画 |

用户明确选定的服务或工具优先于默认规则；已有授权继续沿用。不因配置过密钥、修改次数多、希望保留历史，自动把内置生图切换成收费云服务。不重复确认已经授权的内置制作；云端 API 的具体任务费用确认仍由原有授权入口管理，助手不代签。

执行前检查实际工具是否可用、是否支持本轮编辑和参考图数量。看板的“内置生图”保存交给助手的请求，不会自行调用模型，也不能证明当前宿主具备生图能力。能力缺失时明确限制，继续独立工作；改用会影响费用或结果的服务时说明选择依据，不静默降级或重新收费生成。

内置工具、云服务和人工制作的实际结果统一按 [资产版本与迭代记录](asset-versions.md) 保存。生成后登记真实文件、实际工具、参数、修改底稿及真正传入的参考；不能仅凭提示词写了“参考 V2”就宣称已向模型传入 V2。


## 用户要求图片与 Prompt 共同约束时

每次 3D 生成都准备具体约束 Prompt，写清对象、风格、前后结构、姿态、关键比例、材质与应避免的结构错误。先核实当前提供方、模型和模式能否把它与图片一起传入。若用户要求实际联合输入，不得删去 Prompt、转存 brief、丢弃参考图或擅自改用文生/Sketch；继续整理图片与约束，说明接口缺口，由用户决定会改变输入方式的路线。

使用 `game-preproduction/runtime/adapters/assets/generation-api.md` 的 Prompt 要求配置与提交检查；源码布局对应 `adapters/assets/generation-api.md`。看板字段和本地说明不是服务已接收的证据。保存最终 payload 中的文字与逐张图片方向、摘要；将待发送、请求获接受、输出遵守约束分别记录。参考图须保持同一姿态、结构和共同尺度，生成后先检查原始网格的前后方向及体积，再绑骨。不要把本项目的角色外形写成其他资产的固定模板。
