# 角色职责与素材适配

用于选择或替换可操作角色、敌人、Boss 及其动作/装备。支持从玩法需求找素材，也支持先探索素材、根据实际能力形成玩法；两种入口可交替迭代。职责和适配依据是批量校准、正式接入前的条件，不是搜索、预览或代表小样检查的前置门槛。文件已下载、免费、好看或能重定向都不等于设计已成立。

## 继承需求，区分占位

沿用当前有效的用户决定和项目规格，区分：

- **体验目标与约束**：玩家应获得的体验，以及引擎、预算、来源等明确条件；局部选材不擅自改变。
- **已定规则与对象职责**：谁使用什么能力、承担什么压力或交互；玩家的武器选择不自动成为 Boss 的装备要求，某个角色的设定不外推给所有对象。
- **暂定实现与占位**：临时模型、动作、比例和技术方案可在本轮委托内替换；不要把早期“小白人”等占位机械视为永久设定，也不要把明确选定的角色擅自降为占位。

不确定项只补到能支持本轮决定的程度。已有方向和选材委托足够时直接推进；不是每个资产都要重新确认。

## 根据当前未知选择入口

用户指定顺序时遵循其要求；否则结合本轮目标与资产情况选择，不要求用户先说“围绕素材设计”才允许素材探索，也不固定所有项目必须先搜或先写详细方案。

| 入口 | 适用情况 | 本轮推进方式 |
| --- | --- | --- |
| **需求驱动** | 角色职责、关键交互或招式已经明确，主要未知是如何实现 | 将职责转成必要行为 → 检索模型/动作/装备组合 → 检查代表样本 → 根据证据调整实现或提出规则取舍 |
| **素材驱动** | 职责或招式尚未确定，已有资源可复用，或预算/周期使素材供给成为主要限制 | 沿用体验、引擎和预算等边界 → 搜索/盘点实际资源 → 检查能力与缺口 → 据此设计职责和玩家交互 → 用代表小样验证 |

素材驱动也适用于用户只给出“免费动作游戏”一类目标的探索任务，无需先编造完整招式表再搜。已有明确职责时，可以围绕其未定部分探索素材；搜索不能静默推翻用户已选的武器、角色、玩法目标或预算。若本轮只授权推荐/设计，交付候选和方案即可，不扩大为正式工程替换。

### 把素材能力转成玩法方案

复用 [素材检索与获取](asset-sourcing.md) 的证据和来源记录，按实际需要说明：素材确实能做什么、哪些能力仍是推测、缺什么，以及为采用它要付出的修改/补充成本。不把动作文件名、演示视频或自动重定向成功写成完整适配结论。

由这些能力提出能成立的角色职责，再补玩家信息、选择、风险、成功收益和恢复机会。必要时比较少量玩法方向；已有足够依据和委托时可直接选择，不强制凑方案数或逐项确认。动作齐全但不服务目标的素材仍可淘汰，缺招式时可以补素材、局部制作或在委托内缩减/改变方案，不能把包内动作列表当作完整设计。

探索达到“能选出代表玩法并知道关键缺口”的程度就进入小样，不为搜齐全部资源无限延后实验。未知的关键能力先保持候选状态，按风险做外部或引擎试验；结果可反过来改需求和选材，再扩量。

例如，用户已选“压迫型怪物”而具体招式未定时，可以先比较挥爪、扑击、投掷等实际可用动作，再设计不同的施压/反击节奏；发现有跳跃片段不等于它已有清楚的起跳预警、落地命中和收招。若用户已明确要求持双手锤的骑士，则不能只因找到怪物包就更换该设定。

## 将候选落实为角色交互

结合已有功能规格，用短段落或现有资产表说明对象职责、主要行为、玩家获得的信息与应对机会。战斗角色至少能解释本轮如何施压、玩家如何识别/应对，以及成功应对后的反击或收益；非战斗角色改为相应的交互目的。

需求驱动时据此列出必须支持的动作与表现，再筛模型、骨架、动作和装备；素材驱动时把已检查的能力映射到这些行为，并记录尚需补齐的内容。两种入口都允许代表动作和引擎实验反馈到规则，不要求冻结所有招式与数值。

采用素材带来的规则调整与资产选择分别记录，注明它属于已确认规则、暂定方案还是待验证假设。批量制作前至少能解释角色让玩家做什么，以及代表样本为何支持该交互。

## 用真实证据核对组合

先查预览与包内说明，必要时下载少量真实资源解决未知；仅凭名称或同为人形/FBX 不足以决定适用。按本轮需要检查：

| 适配问题 | 观察依据 |
| --- | --- |
| 身体是否能表达职责 | 体型、肢体结构/对称性、动作幅度、轮廓和游戏镜头下的可读性 |
| 动作能否在目标模型成立 | 实际骨架、参考姿态、比例、权重、支撑与重心；可重定向只是技术条件 |
| 装备能否合理使用 | 单手/双手意图、可用手指与握点、柄长/尺寸、持握和释放区间、负重与接触轨迹 |
| 行为是否服务交互 | 预警、生效方向/距离、位移、恢复和衔接，是否留下目标玩家应对机会 |
| 适配成本是否合理 | 必要修改、缺失动作、依赖与许可、剩余验证；免费资源仍有制作成本 |

选少量最能暴露风险的代表动作检查。发现肢体/握持或行为职责根本冲突时，停止沿该假设批量烘焙和替换；保留候选与证据。不要靠强拉 IK、极端缩放、扩大判定或 VFX 遮挡把不匹配伪装成通过。正常的局部校准仍按动画制作流程进行。

## 不匹配时明确走哪条路线

| 路线 | 前提与后续 |
| --- | --- |
| **保留职责，换或修改素材** | 已定角色/玩法仍是本轮目标。寻找匹配组合，或评估有依据的局部制作；先验证代表样本，再扩展。 |
| **保留素材，调整设计** | 用户已指定该素材，或调整职责仍在有效设计委托内。先写清候选规则与收益/代价，再更新功能规格及受影响接口；不能只换动画文件。 |

例如，持双手重武器的 Boss 需要能表达握持、承重和起收的组合；非对称爪臂怪物可成为挥爪、扑击或跳砸的候选，但不能仅因动作包现成就自动改掉原 Boss。该例说明判断方法，不规定所有怪物必须徒手，也不禁止经过验证的创造性改造。

比较两条路线对体验、制作成本和缺口的影响并给出建议。在现有委托内可以决定的选择直接记录并执行；只有将改变明确用户选择、核心体验或超出范围/预算且没有授权时，才提出具体取舍问题。准备足以判断的证据与方案后再问，等待期间继续不受影响的工作，不重复索取已有授权。

## 将决定带入制作与验证

在现有功能规格/资产条目或同一变更记录中保留：采用哪种入口及理由、需保留的条件、素材能力与证据/未知、对象职责与玩家交互、适配缺口与成本、选取路线及依据、受影响规则/资产/消费者、代表验证结果。沿用稳定 ID 和原资产状态，不另建重复总表；候选、已选、已获取、适配、导入与体验通过分别记录。

- 保留职责换素材：校对动作表达、接触和时序是否仍符合原规则，不因文件长度不同暗改范围或取消。
- 改变职责/招式：复查预警、追踪和攻击范围/方向、位移、命中窗口、恢复、玩家应对与反击机会；按实际改动更新 AI、碰撞、镜头、VFX/声音和中断清理。
- 先做外部或独立引擎代表样本，再在可操作场景验证；已有引擎资源无需强制导出。原型粗动作可以尽早进引擎，精修扩展须有当前适配依据。
- 修改职责、模型、骨架、绑定或关键时序后，旧证据只作历史基线，重测受影响部分。播放成功、伤害正确不能证明选型合理或体验通过。

分工沿用现有体系：策划负责职责/规则，美术负责素材组合与来源，动画负责姿态/握持/回传，技术负责实际消费者，验证负责真实应对与动态证据，管理仅汇总关联。单独安装本 Skill 时仍按上述判断维护项目已有记录，不要求补装其他 Skill。
