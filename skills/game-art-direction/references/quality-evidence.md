# 资产证据采集与评审工具

已有输入准备、生成结果、手工加工结果或素材候选需要质检时，使用共享运行目录的 `tools/asset_quality.py`；格式、命令、依赖和边界见[工具说明](../../../adapters/assets/quality-review.zh-CN.md)，示例见[模板](../../../templates/asset_quality/README.zh-CN.md)。不要求重新生成已有结果。

1. 先列源文件及全部依赖、用途、环境、必需视图、可观察的检查项。输入准备的必需要求逐项关联；碰撞、动作、镜头内识别等暂不能验证的要求，明确转到引擎或游戏检查，不能静默删除。
2. 对自包含 GLB 用 `capture` 获取共同正交比例的四面图及几何数据。确认前向轴和单位有依据；未知时保留未知。其他图片保留实际投影、姿态、遮罩与参考职责。不能把各自缩放图片声明为同尺度，也不能用正侧面轮廓重叠率证明一致。
3. 用 `collect` 固定证据，打开原图及联系图。按需查看局部、原模型和媒体；音频要实际听，动画和交互要看相应动态证据。工具记录媒体路径不等于已经观看/监听。看不到、被遮挡或工具不可用就记录 unknown，不推测通过。
4. 在生成的评审模板中逐项填写实际评审者、预期、观察、置信度及证据 ID；缺陷可注明局部区域。分数只总结所列检查，不能替代观察。镜像/重复疑点需引用两图：确认左右结构错误，或说明对称为何合理。缺失视图需补证，不能解释掉。
5. 执行 `assess`，再用 `check` 检查哈希。失败或未知都不能说“质量没问题”。必需自动失败不能用美观评分抵消。新文件或新参考需新采集目录，保留旧结论适用范围。
6. 已有资产评审记录时，确认源文件、用途和环境一致，再 `publish` 到 external 门槛。不能自动选用版本、替换工程、标记引擎/游戏通过或发起下一次收费生成。

四面静态图只说明被观察的表面；内部结构、背面细节、变形、接触时序和实际可读性可能仍缺证。没有额外证据时明确限制。需要根据已确认缺陷调整下一轮输入时，使用[结果驱动迭代](result-iteration.md)，保留原要求并复查退步；质量工具本身不发起生成。
