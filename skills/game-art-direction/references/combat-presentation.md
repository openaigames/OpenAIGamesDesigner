# 战斗表现交接

需要实际制作或协调动画、VFX、声音时，继续读 [动态视听制作](animation-vfx-audio-production.md)，其中给出事件职责、时序样例与返修方法；本篇保留战斗规则到表现的交接边界。

以本项目动作规则、镜头和既有美术为输入，沿用 [资产交接](asset-change.md)。普通反馈替换不重新讨论整个项目风格。

第一次制作战斗原型时，按 [本轮资产方案](asset-execution.md) 明确玩家与 Boss 各自的模型/占位、关键动作来源和演出范围。不要从“近身 Boss 战”直接决定胶囊玩家、几何体 Boss 或用物体旋转代替挥击。白模只描述模型表现，不能自动回答是否需要骨骼动画；模型确定也不代表其攻击动作包已选定。

按已经确定的规则列最小动作映射，例如移动、攻击、闪避、弹反/防御、受击、死亡，以及 Boss 已选招式的前摇、出招、收招。只列本轮适用项，不为凑表增加玩法。每项记录实际或候选动画来源、缺口、是否接受占位以及验证限制；可把玩家模型、Boss 模型、动作包和场景占位汇成一份方案供用户整体选择，不要求逐招确认每个文件。

动作资源由美术与技术共同检查骨架、武器姿态、位移和时序能否支撑规格。“攻击动作模组”可能指动画包，也可能指带规则的战斗插件；先明确所需内容，不能因选了动画包就采用整套战斗框架。UE 的 Montage、Notify 或重定向属于具体实现，按已选资源处理，不要求用户替技术侧填写参数。

按需建立事件到表现的对应：预警、蓄力、释放、命中/未命中、受击、防御、取消、死亡。说明玩家需要看懂什么、何时出现、在哪里出现、如何结束；动画、VFX、声音和镜头不互相遮蔽关键提示。

动作注明实际骨架、动画资源、根运动/位移关系、挂点、混合/分层和关键事件；UE 项目依据真实资产补 Montage/Notify 等信息。规则生效与表现播放的责任由技术侧明确，不以视觉帧默认决定伤害。

中断检查覆盖实际适用的动画退出、残留拖尾/循环声、挂点失效及特效清理。资产替换后复查受影响的共享动作、变速、镜头距离和密集场景；没有实际画面或声音不声称验收。

交付实际资源/消费者、来源、规格与运行证据。占位测试、动作可读与最终品质分别记录；作品参考不代表已拥有制作素材。
