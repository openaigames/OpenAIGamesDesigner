# 将美术方向转成可重复生产的规则

用于方向探索、把选定参考交给制作者，以及解决资产放在一起不一致的问题。文档组织见 [美术入口与资产记录](outputs.md)；已有项目局部任务只提取相关规则。

## 从体验目标到表现规则

先读取 Game Concept 中已有的体验承诺、用户选择及当前玩法与镜头约束。美术负责解释如何表现这些目标；不因整理情绪方向重定游戏定位、补写未经选择的玩法或要求另填一份情绪文档。已有明确风格直接沿用；方向含糊时给少量可比较建议，按当前委托讨论或试制。

在 Art Direction 开头或当前资产条目中保存简短方向摘要，按本轮需要覆盖：

| 方向信息 | 转成什么判断 |
| --- | --- |
| 目标感受与细微差别 | 玩家应感到什么，哪些相邻感受可支持它；不要只堆“温暖、沉浸”等形容词 |
| 视觉表达 | 用轮廓与比例、明暗分组、色彩角色、光照、材质或细节密度表达目标 |
| 动态与声音 | 本轮涉及时说明动作节奏、反馈强度、环境声或声音质感；没有材料不声称已听过或验证 |
| 会破坏方向的表现 | 指出具体冲突及其原因，不写通用审美禁令 |
| 实际使用条件 | 关联镜头、玩家要判断的信息、显示尺寸与制作条件；未知保留待定 |

把关键选择写成“体验目的 → 表现选择 → 观察条件”。例如已确定的安静探索体验，可以提出减少持续闪烁的装饰光、以稳定轮廓表达可交互对象；这是项目候选方案，需在真实背景与镜头下比较是否既安静又可辨认。可读性、隐藏意图或情绪对比发生冲突时，回到当前玩家任务取舍，不设普遍优先级。

需要视觉讨论依据时进入 [Moodboard](moodboard-and-palette.md) 的制作意愿流程。摘要只为改善选图与制作判断，不成为新审批阶段；拒绝或暂缓图板也能按已有要求继续设计、选材和制作。用户只需要局部资产时不补全整个游戏的感官方向。

## 建立可比较的基线

取得项目认可的参考、实际镜头和至少一个代表对象；缺少认可基线时先把选择标为候选。分别观察目标显示尺寸下的轮廓、明暗分组、色彩角色、材质语言、细节密度和动态表现。不要只记录“像某作品”“高品质像素风”。

已有 [Moodboard 与色板](moodboard-and-palette.md) 时读取本轮适用的主题板、资产板及当前选用版本，以实际保存的用户配色为基线。主角等资产可继承主题的明暗或材质语言，同时采用局部色板；将差异写成适用范围内的规则，不把单个资产的调色扩展为全项目换色。

将参考拆成可继承特征与不继承特征，保留来源与具体区域。例如继承大明暗块和清楚的轮廓，不继承角色造型、配色身份或细节纹样。生成候选也需经过这一选择，提示词不是风格规范本身。

## 从图板形成资产设计说明

当任务要从氛围参考推进到具体资产设计时，先形成能指导本轮设计的简短说明，维护在 Art Direction 对应资产条目或已有资产规格中，内容较多时再独立链接。它说明要做成什么样及为什么，不等于 Concept Art、模型或引擎资源已经完成；已有足够规格时补缺口，不另造重复文档。没有 Moodboard 也可依据已认可的图片和项目要求推进，不为写规格强制新建图板。

先锁定本次依据：目标资产与用途、主题/资产板标识及版本、实际保存的配置和原图、各参考用途、当前色槽及用户决定。读取适用的局部覆盖关系；候选板可以作为明确委托的试验输入，说明与设计选择仍为候选，不回写为全项目已选风格。原图来源或生成标记沿用记录，展示图不证明模型本体、授权范围或游戏内效果。

查看原图后，将直接可见的特征与本项目的设计选择分开：可以观察到“外套是绿色、背包与躯干轮廓分开”，据此提出“用绿色衣身与棕色背负区分主体和装备”，但这是用途驱动的选择，不是把原角色的全部衣饰照搬。参考种族、职业道具或镜头效果不能自动成为目标资产设定。缺少背面、运动或运行画面时将对应信息标待补，不臆造它们已经存在。

按本轮需要覆盖以下内容，不机械填写全部对象的生产字段：

| 设计内容 | 应表达的可执行要求 |
| --- | --- |
| 身份与气质 | 目标对象的用途、玩家应读出的身份；哪些来自用户要求，哪些只是候选设定 |
| 轮廓与比例 | 主要形体的大小关系、识别特征及应保持的轮廓；数值仅在有测量、用户指定或明确试制依据时填写 |
| 组成与连接 | 角色的服装/装备穿戴，场景的空间层次/通行关系，或道具的部件分界；说明必要关系与可变细节 |
| 配色与材质 | 引用当前色槽，将颜色分配到具体部位和主辅关系；区分图像光照、材质观感和拟采用的材质表达 |
| 继承与排除 | 继承哪些整体特征，如何保持目标身份，哪些原作细节不采用；排除项应能在候选中看出来 |

每条关键要求连接到参考标识、用户要求或明确标注的设计建议，并给出用途理由和可观察的检查条件。可用“依据/观察 → 本资产要求 → 如何检查 → 决定状态”的简表；只有判断需要精确回溯时才增加标识，不为每句描述建立追踪字段。按已知约束、候选建议、待定和已选决定区分状态，不能从语气肯定推断用户已经认可。

颜色沿用此次输入快照的色槽标识与 HEX，不重新取色覆盖用户值。新增部位分配属于设计提案，须与已有颜色用途相容；有意改变原用途时明确说明并保留待选状态。不要从有色灯光下的参考图反推底色、粗糙度或金属度参数。图板后续更新时复核受影响的设计条目，不静默改写旧说明所用版本。

检查说明是否足以区分符合与不符合的候选：例如缩略图中仍能区分主体与背负、帽饰不会遮住身份轮廓、强调色未抢占主体。观察条件以实际镜头、显示尺寸和背景为准；条件缺失时给出待验证计划，不编造分辨率、视角、面数、贴图、动作或骨架规格。没有产物时只能检查说明的依据和完整性，视觉验收保持未执行。

列出影响下一步的待定项及解决方式；只追问当前确实阻塞的决定，其余保留候选继续完成已授权说明。用户后续要求绘制、生成、建模或接入时，再按 [制作规格](asset-production-specs.md) 和 [资产执行](asset-execution.md) 交接，避免把提示词当成唯一设计文档。

## 用规则约束有意义的差异

每条规则写适用对象、用途、允许变化、反例和比较条件。需要区分阵营或交互功能时，规定颜色或形状承担的信息；不强迫所有对象用同一色相。颜色、声音和形状可以互补，关键信息不要只依赖一种难以区分的颜色。

| 假设项目规则 | 有效说明 | 无效替代 |
| --- | --- | --- |
| 可操作机械的接口要可辨认 | 在默认游戏镜头下保留连续外轮廓；高对比集中于交互端；背景同类装饰降低局部对比 | 所有机械更亮、更酷 |
| 敌方预警与环境灯分开 | 预警用特定形状及节奏；环境灯避免同时复制其组合 | 敌人统一红色就够了 |
| 小图标保留类别差异 | 在实际最小显示尺寸下比较工具/资源的主形状，细节不得成为唯一识别依据 | 导出更大分辨率 |

例中规则仅说明写法。项目可以选择隐藏交互物或弱化提示，只要与期望玩家承担的观察任务一致。

## 做一次代表资产试制

选择能暴露关键风险的对象：主角与背景叠放、可交互物与装饰混放、同类的两种功能变体。先让一份资产从源文件、导出到实际场景走通，再确定批量标准。只在独立白底下批准会漏掉背景和镜头问题。

记录同一场景下的正例与反例，说明差异原因；不能把低分辨率截图用于确认源贴图细节，也不能由静态画面批准动态闪烁。规则冲突时按玩家任务取舍，例如轮廓可读性与隐藏意图之间需要具体决策，而非无限增加细节。

试制同时回看方向摘要：目标感受是否从实际画面与动态中成立，玩家是否能按预期识别，资产之间是否一致。发现偏差时定位具体表现或原始假设，修改相关规则、选图或制作要求；不能仅凭画面精致或一张白底预览批准整套方向。完成的观察与下一步检查分开记录。

## 批量制作与变更

区分固定身份特征与可变部分：角色主轮廓、材质分区、挂点位置可能固定，装饰和磨损可变化。变体记录其用途与生效状态，防止同一对象不同动作、视角或损坏状态失去身份。

修订规则时列受影响资产与消费者，优先修正当前切片中的代表对象，不自动重做资产库。交付风格规则、带解释的参照、代表资产与比较场景、允许的变体和待验证项；具体尺寸与格式继续使用 [制作规格](asset-production-specs.md)。
