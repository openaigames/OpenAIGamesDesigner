# 场景美术

先取得实际场景、关卡目的/路线、玩家尺度与镜头、风格和平台约束。已有灰盒的通行、关键视线、攻击预警和交互轮廓是制作输入，不能在美术替换时无记录地改变。

新地图、按图重建或处理“模型不像设计”时，先读 [地图制作与空间交接](references/map-from-design.md)。依据本轮空间问题选择图纸、原型与代表样板，不预设地图类型或固定视图顺序；已有布局或仅探索外观时按当前依据接续。依赖风格的制作前，缺少明确风格及选型委托时须询问；题材不等于视觉风格，不能自行将写实目标降为 low poly。已有选择和授权沿用，局部修复不重走全流程。

按 [环境可读性](references/environment-readability.md) 与 [环境生产](references/environment-production.md) 工作：先验证模块尺度、材质语言和代表光照，再扩展布景。搜索现成资源可以先于完整视觉方案，但同场组合必须实际观察；同一包也不自动保证密度、精度和比例适合。

把主要路线/目标、可交互物、危险与背景分层。比较材质明度、形状、光照和动态遮挡共同造成的阅读结果；不能只加高亮或统一色板来补救混搭。用玩家正常高度和相机检查，不以编辑器俯视漂亮代替可玩视角。

场景资产按实际用途保存来源、模块规格、碰撞/LOD/材质依赖与可编辑状态；程序化布景记录生成入口及版本。影响路线/视线的改动联动关卡，影响战斗预警的改动联动战斗/VFX，技术预算与 TA/程序共同确认。

批量建模前在代表区域核对性能条件与资源策略，按 [地图性能与资源处理](../game-technical-art/references/map-performance.md) 区分传统 LOD、Nanite、重复实例和植被负载。未安装技术美术 Skill 时沿用项目工具与同样的数据口径；保留风格和关键轮廓，优化后在玩家镜头及目标运行环境复测。

交付本轮场景和源资产、实际场景视图、约束读回、性能条件与已知问题。范围可以是代表品质区域、整关内容或局部修复，按任务终点结束。不能用单块品质样例认证未制作区域。

取得或制作本轮场景资产后，按 [分类与用途标签](../game-preproduction/references/project-workbench.md#分类与用途标签) 区分地图场景、树木/建筑模块等道具模型、材质贴图；同一场景包的依赖分别归类。

## 制作迭代与版本交接

栅格设定图、地图图纸、界面图片或效果概念图的生成工具按 [生成工具选择](../game-art-direction/references/generation-tool-selection.md) 决定；普通生图优先当前宿主可用的内置工具，配置密钥不改变默认选择。

交付物多次修改或使用旧方案时，按 [资产版本与迭代记录](../game-art-direction/references/asset-versions.md) 保留实际文件、修改底稿、参考用途和当前选用。不同专业交付物分别建组，配套文件组成同一版；选回旧版不删除新版本，也不自动覆盖工程、重新绑定或认定验收通过。

本轮实际制作、转换或接入资产时，按 [资产生产登记与交付检查](../game-preproduction/references/asset-handoff.md) 同步维护既有权威清单：沿用稳定 ID，关联源文件、派生物、用途和实际证据。由执行方补齐本轮登记，不把补表留给用户；纯讨论与只读检查不写完成状态。
