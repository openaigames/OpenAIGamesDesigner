# 环境生产与组合验证

先读取关卡灰盒、尺度/通行/视点与风格。建立一个能代表模块连接、主材质、灯光和背景对比的局部组合，实际进入玩家镜头验证后再扩展内容；品质样例的范围与未覆盖区域分别保存。

模块化资源比较栅格、接缝、门洞/楼梯/掩体与角色能力，尺寸来自实际工程约束。形状能拼上不代表碰撞连续；重复材质、法线边界和曝光变化需在移动中观察。非模块场景也需保存地形、通行与可交互对象之间的关系。

材质从大面积明度/色彩结构到中频表面变化、最后近景细节调整。若远处路线消失，先查构图、灯光和背景分离，再考虑装饰；噪声纹理和高反差边缘可能抢走目标信息。美術表达可以复杂，玩家必须看到的信号要有明确层级。

布景先区分承载玩法的碰撞/遮挡与装饰，不把移动路线作为剩余空地。动态物件、天气/烟雾和特效叠加在实际玩法中检查。与 VFX、美术指导和关卡共同解决冲突，不能单靠不断增加高亮。

性能记录平台、分辨率、镜头路线、实际构建及测量方法。分别定位过绘制、材质复杂度、阴影、几何、实例数量和加载问题；截图工具的取帧开销不能当成正常运行帧时间。优化保留关键轮廓、危险和路线信息，按实际收益复测。

交付可编辑场景、模块/材料源、权威约束引用和真实视角证据。原生场景打开、碰撞/通行、最终视觉、性能与用户认可分别报告。未知只说明未测，不用静态图推定全部区域完成。

## 制作实例：灰盒门洞替换为装饰门框

以实际净通行宽度和角色碰撞为依据，先拆出承重轮廓、装饰、碰撞三层。模块外宽和净开口不同；装饰向内侵入会改变通行与镜头，不能只检查模块是否贴合栅格。先制作一扇完整门框及两侧墙的代表组合，保留接缝和材质变化，沿直行、斜入、贴边转身三条实际路线观察。

制作时保持约定枢轴/栅格，分配可重复材质、可替换装饰和碰撞简化体。把关键边缘的法线/UV 接缝放到玩家镜头中检查，远处先看明度与轮廓，再加污渍和细节。门框宽度修改登记到共享项目标准的真实来源，关联玩家胶囊、门洞、锁定镜头与路线复测；不能因为换了一张无关贴图就要求全项目重新验证。

静态道具按已确认布局组装、优化时使用 Blender 配方（源码 `adapters/processing/README.md`；安装包在 `game-preproduction/runtime/adapters/processing/README.md`），保留原件；处理报告只记录几何和依赖，场景外观与可读性仍需实际观察。
