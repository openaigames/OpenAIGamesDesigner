# 技术美术

先查源资产、作者示例、目标工程和实际运行对象。原生引擎资产直接在引擎检查，外部文件按需要进入 DCC；不要为通过管线强行全量导出 FBX。作者 Demo 可能在运行时创建附件，编辑态没有组件不能证明原包没有绑定。

按 [资产技术处理与诊断](references/technical-art-production.md) 确认单位、坐标、参考姿态、层级、蒙皮、压缩/重定向与最终消费者，再定位误差。比较源与运行实际读回，设计目标轨迹不是实测结果。

新制或替换需要动画的模型，按 [动画与骨架路线](references/rig-aware-asset-production.md) 先确认“先定模型再绑骨配动作”或“按已有动画/骨架反向制作模型”。沿用已明确的选择；骨架比例可转成文字长度注释与参考，不强制尺寸图。等高模型仍须校准关节、蒙皮并回放实际动作。

武器绑定显式声明骨骼/插槽与相对变换，核对目标存在、轴向、握柄和使用状态。`hand_r`、`weapon_r`、零偏移均不是通用答案；合理自定义偏移需有具体来源。动画负责动作与接触，程序负责最终附着/混合/状态，本 Skill 保证技术转换与规格正确。

材质和性能从目标环境诊断：检查纹理色彩空间、法线约定、透明/过绘制、LOD、蒙皮与资源预算。技术可导入不等于角色好看或动作自然；问题涉及造型、姿态或节奏时交回相应作者，并在同一任务保留证据。

地图资产审计、自动 LOD 或 Nanite 配置按 [地图性能与资源处理](references/map-performance.md)：先读取实际资产与目标条件，在代表区域比较策略，再扩展。使用现有 UE 原生接口生成派生资产并重开读回，区分源面数、fallback 和实际帧时间；保留写实风格、关键轮廓及玩法碰撞。

有实际工具时执行处理、再打开、再读回；原件保留，输出记录输入哈希、设置、目标引擎版本和消费者。复用现有引擎 session/资产工具，不另造进程管理。交付可复用加工过程、实际资源、读回差异、运行表现与能力限制；仅完成技术检测不得自动批准美术品质。

异源骨架、左右镜像、握柄或步幅问题，按需使用 [角色集成方法](references/character-animation-integration.md)。静态拼合和减面使用现有资产任务的 Blender 配方（源码 `adapters/processing/README.md`；安装包在相邻 `game-preproduction/runtime/adapters/processing/README.md`），不把处理报告当作美术通过。

## 制作迭代与版本交接

交付物多次修改或使用旧方案时，按 [资产版本与迭代记录](../game-art-direction/references/asset-versions.md) 保留实际文件、修改底稿、参考用途和当前选用。不同专业交付物分别建组，配套文件组成同一版；选回旧版不删除新版本，也不自动覆盖工程、重新绑定或认定验收通过。

需要可执行的骨架/网格测量、截面变化、导出读回或武器适配记录时，使用 [模型与武器测量工具](references/asset-measurement-tools.md)。沿用实际资产与项目阈值，报告帮助定位差异，不能代替美术验收。

本轮实际制作、转换或接入资产时，按 [资产生产登记与交付检查](../game-preproduction/references/asset-handoff.md) 同步维护既有权威清单：沿用稳定 ID，关联源文件、派生物、用途和实际证据。由执行方补齐本轮登记，不把补表留给用户；纯讨论与只读检查不写完成状态。
