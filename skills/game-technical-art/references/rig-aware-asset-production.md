# 先确认动画与骨架路线，再制作模型

用于新制或替换需要动画的角色、生物、武器及机械物体。静态场景资产不需要确认绑骨路线；已有资产的局部修复沿用当前方案。本文提供制作方法，不表示已经实现通用自动绑骨或指定骨架生成接口。

## 制作前确认什么

先读用户决定、资产规格、实际模型与动作。路线尚未确定时，用效果和成本解释以下选择，再由用户确认；不要求用户理解骨骼命名或重定向参数。

| 路线 | 适用情况 | 需要说明的代价 |
| --- | --- | --- |
| 先定模型，再建立骨架和配动作 | 造型自由度优先，没有必须复用的动作；可评估平台自动绑骨或本地绑定 | 自动绑骨要核对对象支持范围，生成骨架未必适配已有动作，仍需修权重和验证动作质量 |
| 先选已有动作和骨架，按其比例制作模型 | 希望保留已经可用的动作、接触关系和游戏接入 | 造型需适应关节位置与参考姿态；生成后仍需校准模型并绑定到指定骨架 |

可简短询问：“这个角色优先保留现有动作效果，按它的骨架比例制作，还是先定造型、再为新模型绑骨配动作？”有真实素材时给出推荐及依据。没有动作文件或用户尚不确定时，先检查候选动作与当前工具，提供可核对的比较；不能替用户默认选平台自动绑骨。

已有明确选择或明确涵盖制作路线的委托直接沿用，不重复询问。只说“生成一个角色”、保存 API Key、平台提供绑骨功能，都不能推出路线已选。路线未定时继续素材盘点、预览和只读测量，等待的仅是依赖该选择的正式生成或绑定。风格、体型与装备沿用项目约定；未知且会影响结果时一并问清。后续若需换骨架、放弃选定动作或显著改变造型，超出既有委托的取舍再交用户决定。

路线确认、收费任务授权与资产质量验收是三件事。沿用现有有效授权和任务工具，不追加重复批准，也不把路线选择当作云端收费任务授权。

## 从已有动画与骨架反向制作模型

### 1. 先证明动作值得复用

读取实际骨架、配套模型和代表片段，检查来源/许可、参考姿态、单位/朝向、根运动、手脚接触及项目接入方式。按用途选少量高风险动作：例如持枪、跑步、换弹，或机械开合。保存真实播放基线；“已有动画”不意味着质量已通过。只有第一人称手臂骨架时，范围只能覆盖手臂与装备，不能据此推定完整人体。

### 2. 提取可追溯的比例依据

在参考姿态、统一坐标和单位下记录骨架身份/版本、层级、关节位置与关键关节间距离；根据用途记录肩宽、肩—肘—腕、髋—膝—踝、握点/转轴等。区分骨架数据实测、配套网格实测、美术设定和未知值，保存单位换算与测量方法。

- 解剖长度优先来自已确认的关节位置。导入器生成的骨尾、辅助骨、IK 骨和虚拟骨不能直接当作人体骨长。
- 骨架跨度不等于角色全高；头顶、脚底、肌肉/衣物厚度需由配套网格或美术设定补足。不要从头骨位置编造头顶高度。
- 保留左右差异和参考姿态；数值由实际数据计算，生图中的标尺文字不能作为测量来源。

### 3. 组成生成提示与参考

将比例依据转成模型能利用的输入，同时保留供后续校准的数值规格。最小交接包括：目标风格/体型、参考姿态、关键比例或长度注释、身体与附件分件、关节/接触要求、源骨架和动作版本、所选生成接口实际收到的输入。

**不要求绘制带尺寸线的工程图。** 可以是提示词中的比例描述、独立的文字长度表、结构化尺寸记录，配合需要的正面/侧面参考。仅骨架线不足以定义体积与服装；可先按实际骨架搭建比例代理，再补造型参考。按 [人物参考图与交付范围](../../game-character-art/references/character-references.md) 检查部件是否齐全，并补充手套、袖管等关键体积。示意或 AI 生成图片仍须对照原始关节与轮廓，不能把看似准确的数字当成约束已生效。

检查当前接口是否支持文本、图片、多视图或指定骨架，再映射输入。具体生成方式以 [本地已接入的生成方式](../../../adapters/assets/generation-capabilities.md) 和提交检查为准；模型生成与多视图图片生成分别列出。不能假定会消费骨架文件、任意尺寸 JSON 或图片旁的说明文档。单图路线需要时先将比例落实到清晰的造型参考，标注版用于核对，送模型的版本避免尺线/文字被生成为几何。未传入的尺寸记录明确用于生成后的测量与修正，不宣称服务已读取。多视图需逐张保存实际方向和文件摘要，核对同一对象、比例、姿态和构造；未支持的 Prompt 与图片组合须明确报错，不静默丢弃。看板与传输记录应显示哪些输入实际发送，哪些只是本地说明。

### 4. 校准模型，再绑定原骨架

保留生成原件，在选定 DCC 中统一单位、朝向、原点和参考姿态，比较关键关节及轮廓。等高、整体缩放一致不能证明肩肘、髋膝、手掌和接触位置匹配；必要时局部调整网格、分件或重新制作，并记录残差及本项目容差依据。不要为了套上新网格擅自改动供旧动作使用的骨长、层级和参考变换。

保持指定骨架的身份与绑定约定，给新网格建立蒙皮。可评估从合适的配套网格转移权重，或自动权重后人工修正；同尺寸本身不保证权重可转移。肩、肘、髋、膝及装备接触必须实测变形。刚性机械部件或武器可按需求采用父子层级、插槽或刚性权重，无需强制做人形蒙皮。骨骼改名和文件中的角色绑定记录均不能代替蒙皮加工。

### 5. 回放原动作，并接入实际使用方

在同一动作、时间和镜头下比较旧模型与新模型，检查关节塌陷、穿插、手脚接触、装备握持和运动轮廓；再验证引擎中的混合、中断、根运动、碰撞及实际镜头。导出后重新打开，核对骨架、权重、材质和单位。沿用 [角色集成方法](character-animation-integration.md) 定位问题；把文件可导入、蒙皮变形、动作适配和游戏表现分开报告。骨架/参考姿态、网格拓扑、权重或关键动作改变后，重测对应证据。

## 先生成模型，再绑骨与配动作

先确定造型、可变形拓扑和部件，检查实际服务或本地工具对该对象及姿态的支持。模型生成与自动绑骨分为独立步骤；生成一个 GLB/FBX 不证明其中存在骨架、有效蒙皮或动画。平台产生的骨架也可能需要重定向、手指/根骨处理和权重修正。

检查返回文件中的实际骨骼层级、关节、网格绑定和非零权重，再用代表动作检查变形与接触。平台预览或骨架兼容提示只覆盖其已检查内容；最后仍需实际引擎运行。若动作效果达不到用途，提出调整模型/权重、替换动作或改走已有骨架路线的具体方案，不静默换掉已选路线。

## 当前工具边界与交付

执行前核实实际安装与接口版本。当前本地普通 3D 生成适配器没有接入 Tripo/混元自动绑骨任务，也没有任意指定骨架生成与通用蒙皮按钮。平台自身能力单独查证；需要接入时作为明确工程任务处理。现有角色绑定记录及骨架兼容预览负责关联/检查；已有 Blender 动作校准配方也不能当作任意新网格自动绑骨服务。

在现有资产规格中记录即可，无需另建一套管理流程：

| 交付 | 需要保留的证据 |
| --- | --- |
| 制作路线与风格 | 用户选择/委托依据、适用对象、继承条件与待定项 |
| 骨架与动作依据 | 实际文件/版本、许可、参考姿态、代表动作播放基线 |
| 生成说明与参考 | 实测/设定/未知区分，比例或长度注释、实际发送的输入、生成任务及原件 |
| 校准与绑定 | 可编辑源、网格/骨架对应、尺寸差异、蒙皮或刚性附着方法与局限 |
| 分层验证 | 导出读回、实际动作播放与引擎运行；已通过、未通过和未执行分别说明 |

单独使用某个职业 Skill 时，沿用上述选择、测量与验证原则和项目现有工具；不要求为了填写规格安装整套工具或立即调用生成服务。


## 用户要求图片与 Prompt 共同约束时

每次 3D 生成都准备具体约束 Prompt，写清对象、风格、前后结构、姿态、关键比例、材质与应避免的结构错误。先核实当前提供方、模型和模式能否把它与图片一起传入。若用户要求实际联合输入，不得删去 Prompt、转存 brief、丢弃参考图或擅自改用文生/Sketch；继续整理图片与约束，说明接口缺口，由用户决定会改变输入方式的路线。

使用 `game-preproduction/runtime/adapters/assets/generation-api.md` 的 Prompt 要求配置与提交检查；源码布局对应 `adapters/assets/generation-api.md`。看板字段和本地说明不是服务已接收的证据。保存最终 payload 中的文字与逐张图片方向、摘要；将待发送、请求获接受、输出遵守约束分别记录。参考图须保持同一姿态、结构和共同尺度，生成后先检查原始网格的前后方向及体积，再绑骨。不要把本项目的角色外形写成其他资产的固定模板。
