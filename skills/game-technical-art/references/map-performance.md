# 地图资产预算、LOD 与 Nanite

用于新地图的代表区域、场景资源审计或已定位的性能问题。沿用目标引擎、风格、硬件、分辨率和帧率；已有选择不重复询问。目标缺失时先收集资源事实，确有必要再问会改变方案的设备/帧率问题，不擅自把写实目标改成低多边形风格。

## 在制作流程中落位

设计图 → 同版平面/立面 → 明确风格与性能条件 → 代表区域 → 检查及优化 → 扩展 → 同条件实机复测。已有风格可以更早确定；局部修改只进入相关步骤。遵守用户已有图纸核对要求，不额外设置逐资产批准。

代表区域应覆盖本图真实负载，如近景建筑、铺装、植物、道具、代表材质和阴影。先校准几何/材质预算与渲染路线，再批量生产。预算来自目标设备和样板测量；面数、材质槽和贴图阈值是筛选线索，不能直接换算为 FPS 或品质通过。

## 先取得可比较的资产事实

- 分开保存 DCC 求值后三角面、唯一资源数量、场景实例数量和 UE 实际读回。四边面数量不能当三角面；实例展开总数不能当每帧可见面数。
- UE 启用 Nanite 时，普通 LOD 的 render-data 三角面可能是 fallback 数据，不能报告为 Nanite 原始面数或屏幕实际绘制量。
- 记录各级 LOD、屏幕切换值、Nanite 与 fallback、材质槽、双面/透明、贴图尺寸和碰撞。磁盘体积、引用纹理尺寸均不能充当显存占用。
- 说明场景加载范围。只读当前编辑世界不能证明 World Partition 未加载区域、运行时生成物或完整对局已经覆盖。
- 重复网格只是实例化候选；同时检查材质覆盖、阴影、碰撞、独立交互和可见性，不能直接把全部房屋合成一个大网格。

## 按资产决定处理方式

| 情况 | 处理依据 |
| --- | --- |
| 支持 Nanite 的复杂静态建筑/岩石 | 检查目标平台、材质和当前引擎能力；比较样本，配置 Nanite 与必要 fallback |
| 传统静态网格 | 自动生成多级 LOD，保留 LOD0，按画面占比设切换；层数与比例按资产决定 |
| 树叶、草、细碎几何 | 比较传统 LOD 和 Nanite，重点看过绘制、阴影、密度、风动及远处变薄；不默认启用即更快 |
| 重复模块和植物 | 共享资源、评估 ISM/HISM/植被系统，保留独立交互和碰撞职责 |
| 表面细微砖缝/裂纹 | 结合贴图/法线表达；保留会影响轮廓、近景和玩法遮挡的几何 |
| 碰撞 | 依据通行/射线用途设计简化体或适当 collision LOD；检查门洞、楼梯和薄掩体 |

传统 LOD 和 Nanite 为不同主路线；Nanite 的 fallback 仍可能参与复杂碰撞或其他渲染功能。降低 Nanite 存储比例主要改变源数据体积，不保证帧时间下降。不要为了减面统一删掉关键轮廓、屋檐厚度或把所有材质设为双面。

## 工具入口与实际边界

静态源模型的比例减面继续使用 Blender 资产配方。UE 原生资产使用现有 `engine_workflow.py execute`，请求与真实能力见源码 `adapters/engines/unreal/mesh-resources.md`；安装包位置为相邻 `game-preproduction/runtime/adapters/engines/unreal/mesh-resources.md`。

`mesh_audit` 只读列出实际资源和实例化候选；`static_mesh_configure` 在新路径生成 LOD 或 Nanite 派生网格，保存并记录前后数据。参数由已选策略生成，批量前完成代表样本。新会话重开 inspect 确认持久化。失败可能留下派生副本，先检查再重试，不覆盖源件或自动替换关卡引用。

目前接口不执行自动重拓扑、贴图烘焙/缩图、碰撞体生成、实例化重写、HLOD 或 GPU 性能采样。需要这些工作时沿用项目现有工具，在授权范围内专项处理；没有执行就保留待完成。

## 两种结果分别验证

技术读回确认资源生成、设置和持久化；玩家视点确认轮廓、材质、切换跳变和通行/射击；性能采用相同版本条件下的固定路线，测 CPU/GPU 帧时间、尖峰和内存，方法见性能验证 Skill 的 `references/performance-validation.md`。录屏或截图采样不替代无采集干扰的性能测量。

交付关联源资产 → 处理参数 → 派生资产 → 实际消费者与运行版本。记录哪些区域已测、何种质量代价、是否真正改善瓶颈；局部技术测试不能批准整张地图。
