# 角色模型与动作资产匹配

用于已有模型、动画和武器的集成或返修。先选一条代表性的「模型 → 动作 → 挂接 → 实际操控」链验证，再批量迁移动作；不要求换引擎或重建控制器。本文是生产配方，不是工具已提供自动重定向、绑骨或布料模拟的承诺。UE 的能力/Montage 接入继续使用 [动作与动画接入](../../game-technical-design/references/action-animation-integration.md)。

## 分清资产与问题层

按拓扑、骨架与参考姿态、蒙皮、动作重定向、接触与挂接、衣物二级运动、运行规则的顺序定位。骨架决定关节，权重决定顶点跟随；给骨头改名不能同时解决两者。

| 输入情况 | 先检查 | 处理边界 |
| --- | --- | --- |
| 已蒙皮模型与配套动画 | 骨架、权重、材质、动画轨道是否齐全 | 优先保留原配关系，不先拆骨重绑 |
| 已蒙皮模型与异源动画 | 骨骼语义、参考姿态、轴向、单位、根运动 | 建立重定向配置，不直接复制所有局部变换 |
| 静态生成角色 | 是否真的含骨架和有效权重、关节拓扑能否变形 | 先清理、必要减面、绑骨和修权重，再重定向 |
| 武器或披风与身体合并 | 可分离部件、连接处拓扑、材质/顶点分组 | 在副本操作；不能凭空间阈值删面后就称修复 |
| 非人形或特殊比例角色 | 关节结构、接触方式、可复用的动作语义 | 优先配套动画或定制映射，不强套人形骨架 |

记录源文件及依赖版本、目标模型、片段 ID、骨架配置、导入器/引擎版本、轴向与单位。保留原件；处理、运行版和审阅结果相互关联。生成服务返回成功或面数符合预算，均不能证明关节拓扑与动画合格。

模型需重新生成时，先在资产规格中分清身体、武器、布料和附件；尺寸、连接位置、轮廓、材质、是否需要蒙皮分别说明。不同部件可分任务生成，再统一比例和材质。Tripo 请求与恢复沿用既有资产任务工具；不因模型生成接口可用就宣称它支持任意指定骨架、重拓扑或自动绑骨。

重新制作前按 [动画与骨架路线](rig-aware-asset-production.md) 沿用或确认用户选择。若要保留已有动作，先检查其实际质量，再从原骨架提取比例，转为生成提示/参考并校准新网格后绑定；同尺寸或同名骨骼不能证明兼容。平台自动绑骨是另一条可评估路线，不能静默替换。

## 参考姿态与重定向

1. 在统一的角色空间检查源与目标参考姿态，区分模型朝向、骨轴和引擎世界轴。不对未核实的模型盲目应用变换或重置骨架。
2. 按髋、脊柱、肩肘腕、髋膝踝等语义建立映射，检查缺失、重复及父子关系。源模型若左右不对称，逐侧确定关节，不能镜像一侧坐标估算另一侧。
3. 先验证参考姿态，再传递相对参考姿态的旋转变化。使用全局旋转差的实现，要先统一源/目标坐标基，再与目标参考旋转组合，最后转回目标父骨的局部空间。不要混用局部、骨架空间和世界空间。
4. 默认保持目标骨长；源骨局部平移不能整套复制到目标。根、髋位移和特殊伸缩轨道按明确策略处理，不能把所有平移一概删掉。
5. 先检查肩、肘、膝，再检查手掌和脚掌方向。可用腕—食指根—小指根建立手掌参考架，用踝—脚趾方向检查脚掌；缺骨或近共线时需另设参考，不能归一化零向量。
6. 以同一片段、同一时间并排比较源和目标；先关闭 IK/布料等二级修正找根因，再逐项恢复。接触修正不能掩盖错误骨长。

以下 Godot 分支是按项目版本执行的方法；现有 UE 采样脚本不能因此视为跨引擎执行器。Godot 可先评估导入器的 BoneMap 与 SkeletonProfile 路线。原作者参考姿态需要保留时，再考虑离线或运行时重定向。移除轨道可能同时移除附件动画，需按用途检查。具体姿态语义和选项以项目版本的 [Godot 重定向文档](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/retargeting_3d_skeletons.html) 为准。

## 左右镜像与持械侧

先回放片段确认哪只手完成攻击，不根据文件名判断。镜像的是动作在角色空间中的运动及左右语义，不能只改动作名称或给整个角色负缩放。

离线处理时定义镜像平面，对成对骨交换左右映射，并在统一参考坐标下反射位移与旋转，再重建目标局部变换。参考姿态不对称时额外校正。根运动、事件中的左右手挂点、武器轨迹与 IK 目标一起检查。非成对的中心骨也需要按镜像平面处理。单纯给四元数某个分量取反不是通用镜像算法。

验收至少包含起手、接触、收招与混合过渡；持械手应完成攻击，武器刃向与目标接触方向一致，根运动没有反向或翻折。镜像前的片段保留，运行配置显式选择新版本。

## 武器挂接：检查实际握柄

武器模型原点不一定在握柄中心，手骨原点也不一定在掌心。先检查作者原生骨骼、插槽或组件的绑定及运行时创建方式；已有正确绑定直接保留。需要重建时，分别记录「武器局部握柄参考架」和「实际挂接参考架中的持握变换」。不默认选择 hand_r、weapon_r 或零偏移。在一致的矩阵约定下：

```text
weapon_world = attachment_world × attachment_grip_local × inverse(weapon_grip_local)
```

attachment 是已核实的骨骼、插槽或组件参考架。若武器已经是它的子节点，只设置对应局部变换，不能重复乘世界变换。模型单位和缩放先统一；非均匀缩放可能引入剪切，需显式处理。

挂接读取动画混合、IK 和骨骼修正之后的最终姿态；确认引擎更新时序，避免一帧延迟或两个系统同时写变换。两手握持应有主手和辅手约束，不能让两只手分别争夺武器位置。

跑动时剑穿过身体，依次查：握柄参考架、最终手掌姿态、持械跑步动画/上身层、武器长度与持握姿态。优先修原因；缩小武器是需要说明视觉与攻击范围影响的候选。不能用偏移武器脱离手掌来掩盖错误动画。

## 步幅、位移与脚滑

先确认位移所有者：根运动、角色控制器，或明确分轴的组合。避免同时累计根骨位移与控制器速度。模型缩放变化后，重查根运动单位、步幅、碰撞和镜头。

先声明真实触地窗口、脚部采样点及坐标依据；没有声明或没有实测时标记未验证，不能从设计轨迹外推脚滑通过。副手接触同样需要明确窗口。记录一个完整步态周期的时长、实际世界位移、左右脚触地/离地时间以及触地段脚掌漂移。原地动画不能靠根位移测步幅，应从脚部运动、参考角色和目标速度标定；有根运动则检查提取前后的尺度与方向。

```text
周期平均速度 = 一个完整周期的实际位移 / 周期时长
```

Boss 抬腿很大但只向前挪一点时，先检查步幅与根运动提取/缩放，再调整播放速率、移动速度或选择更合适的片段。单纯提高步频可能加剧滑步。急停、转向、斜坡与锁定横移另验；不要求所有移动都使用根运动。

使用真实引擎固定步进采样位置和触地；在普通循环里多次手动调用移动函数、却没有推进物理世界，不能当作运行距离证据。

## 披风与附件

先查肩颈固定区、下摆权重和主体动画，不把蒙皮错误当作风力问题。需要二级运动时，可在明确布片上增加骨链、简化躯干碰撞与受限风力；这类近似不等于布料自碰撞。

暂停、顿帧、跳时间、换片段、传送与重生要定义二级运动的暂停/重置方式，避免保留旧速度产生甩飞。采样在骨骼修改器实际完成之后进行。若删披风破坏身体或暴露空洞，恢复原件并修部件划分、权重或动画，不能继续扩大删除范围。

## 最小动态验收与交付

按项目已有动作选择，不强制增加新动作。对本轮涉及的待机、走跑、转向、连击、重击、翻滚、受击、处决检查：

| 检查 | 证据 | 返修方向 |
| --- | --- | --- |
| 正/侧/背面完整周期，慢放与正常速度 | 源/目标同步录屏、时间点和资产版本 | 区分源片段、重定向、混合与附件问题 |
| 骨长、脚方向、掌心握柄、刃向与接触 | 关键姿态及运行时挂点观察 | 修参考姿态、权重或持握配置 |
| 起停、切换、中断、重生 | 实际操控和状态记录 | 修位移所有者、历史状态或清理 |
| 目标平台/渲染器的运行资产 | 导出包中的实际消费者、帧时间与场景负载 | 修导入、依赖、透明叠加或骨骼开销 |

减面检查关节轮廓、蒙皮与材质；性能同时观察纹理、绘制次数、透明叠加、骨骼和同屏数量，不设所有项目通用的面数上限。交付处理配置、可编辑源、运行资源与证据位置；骨架数值检查通过、视觉接受与用户审阅分别记录。进一步检查见 [动态视听验收](../../game-prototype-validation/references/audiovisual-validation.md)。
