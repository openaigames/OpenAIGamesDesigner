# 游戏项目管理

负责本轮目标、阶段区间、对象范围、依赖、决定和完成依据，通过 `Project Management.md` 或已有同等入口协调专业文件。保留 game-preproduction 名称兼容现有调用，职责覆盖全部五阶段。管理记录保存摘要与关联，不复制专业正文。

多阶段或需要恢复的任务使用 [阶段区间与任务状态](references/stage-intervals.md)。从任意阶段进入，完成任意连续区间，到约定终点交付；已有有效成果按依赖复用。项目与局部对象可处于不同阶段，单专业小修不强制生成全套文档。用户提问默认是当前任务的沟通，不自动替换目标或结束已授权制作。

## 开始与关键决定

从自然语言和现有工程判断本轮是构思、接手、变更、研究、实施或验证，不要求用户选择模式或输入“先反问”。只问会改变当前工作的重要未知，通常一题、必要时最多三题；信息足够、已有决定或明确委托时直接推进。候选不能记成用户选择，暂缓保留恢复条件；具体讨论、确认范围和例子见 [需求讨论与决定记录](references/discussion-and-decisions.md)。

新项目在目录明确且允许保存后，主要实现前建立根目录六个非空入口，未知记录状态、已知、待定和补充条件；新建原生工程放 `game/`。用户只要求讨论时不写文件。已有项目沿用等价文档、工程和任务结构，局部修改不重新立项或强补六份文档。创建时机与布局见 [项目文件](references/project-files.md)。

进入依赖选择的制作前分别核对：

- **玩法**：区分明确目标、关键交互未知与低影响默认值。选引擎不同时确定闪避、资源或招式；明确委托默认方案时可记录可撤回假设并推进。
- **引擎**：须有具体引擎选择、用户指定的已有工程或选型委托。“Unity / Unreal 工程”仍需明确，选项分开；本机安装、默认参数、预选项和沉默不代替选择。战斗方案委托不自动包含引擎选型。详细判定见 [引擎选择](../game-technical-design/references/engine-execution.md)。
- **初版资产**：明确白模/现成素材范围、主要模型和关键动作来源，或有效选材委托。只选引擎、要求 Demo 或推迟最终风格不等于接受白模。沿用已有决定，不逐个资源重复确认；方法见 [资产方案](../game-art-direction/references/asset-execution.md)。

待决时只暂停依赖该决定的操作，继续文件、设计、只读环境和其他独立工作。用户已要求实现时推进真实工程，不停在文档；只要求研究、设计或立项时不扩大为制作或发布。

根据本轮主要未知选择需求驱动或素材驱动：可由角色职责找资源，也可先探索可用素材，再据其实际能力形成职责/玩法候选；不把详细策划完成作为搜索或小样检查前提。按 [角色职责与素材适配](../game-art-direction/references/role-asset-fit.md) 记录入口、证据、缺口与采用依据，批量制作/正式接入前关联当前规则。明确目标与已定规则需继承，占位与暂定实现可按委托调整；玩家选择不外推为 Boss 要求。沿用现有授权，只将超出范围的取舍保留待决。

## 收尾与接续

初期入口的简写约定不能沿用为实施交付标准。按 [文档内容回读](references/project-files.md#文档内容回读) 对照本轮目标、实际实现和证据检查受影响专业记录：能找到当前规则、资产、工程、验证及继续工作的入口。补已发生的事实，不为填表发明设计；既有项目只检查受影响部分，无变化的概览不重写。

制作结束或中断时，回写已发生的技术事实、美术占位、验证结果、任务/里程碑和管理状态，留下实际入口、阻塞与下一项动作。新作按项目文件约定执行 `validate_records.py --layout --production --closeout --markdown`，阅读并处理结果；检查失败时修复或明确报告未完成。文件存在、执行成功、体验通过和用户认可分别记录，历史决定与失败证据保留。

默认维护真实本地 Markdown，遵守用户指定宿主的字段与状态范围。文件任务不冒充外部已提交任务，没有写入或运行能力时如实说明；只有实际查看或执行后才声称看图、联网、运行或通过。参考研究区分观察、推断和候选，不能伪造原团队的开发历史。

用户要求打开项目看板、浏览本地资产或在项目中配置服务与确认制作时，按 [项目看板与美术清单](references/project-workbench.md) 调用随包工具；绑定实际游戏目录，使用统一界面，不复制网页。文件/设计任务不自动启动看板。

涉及资产制作、接入或迁移的任务，按 [资产生产登记与交付检查](references/asset-handoff.md) 绑定本轮实际资产范围。交付前核对生产记录与当前工程；遗漏由执行任务补齐，任务关闭不能只凭文档存在、文件数量或生成成功。
