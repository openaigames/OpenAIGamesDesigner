# 动态特效制作与诊断

## 分清信息与装饰

先给每个事件分配信息职责、可见范围和主信息通道。蓄力、预警、实际攻击、命中、状态维持和消退各自对应不同事实；范围提示与判定的差异需有设计理由，不能让观众看到的安全位置实际受击。

特效形状/方向表达作用方式，起伏节奏表达能量积累与释放，明暗/色彩/大小决定主次。先做关键形状与时间曲线，再加噪声和碎片。攻击型效果与环境效果共享画面预算，关键预警不能只在黑底窗口清晰。

## 资源和引擎实现

依据实际引擎与资产选择粒子、网格、材质、贴花、光源或动画资源；选现成效果时确认版本、依赖、真实动态演示与来源。保持可编辑参数和源图/网格，程序生成也保存配方与运行使用方。

定义局部/世界空间、挂点、轴向和缩放继承。挥动拖尾采用武器实际变换并指定启停；角色转向、武器切换和瞬移要处理长尾拉线。命中效果使用命中点/法线及表面类型，不从动画长度猜命中。

每个实例需有开始、持续、结束、取消和所属对象。重复通知可以去重或合并，选择由表现意图决定；取消后持久区域是否保留来自规则，不能一律删除或一律残留。

## 解析已有特效并沉淀方法

从正在运行的系统实例开始，沿启用的发射器、渲染器、材质覆盖和材质实例父链确认实际资源。网格自带材质可能被渲染器覆盖，资源名称也不能证明它正在使用。从最终材质输出反向追踪有效节点；断开分支中的贴图、时间节点或曲线不算当前画面的组成。

对关键参数和曲线记录：来源或默认值、运行覆盖、输入自变量及单位、实际使用方、输出属性。只找到序列化数值时标为默认值未验证；运动可能来自几何、UV 或粒子更新，不能看到噪声纹理就推断存在材质滚动。

在同轨迹、镜头、曝光和背景下关闭单层、改变单个参数，判断它对轮廓、内部层次、速度和消散的贡献。未做这种对照时，保留推断标记。将已有实现迁移到另一类特效前，明确哪些机制可复用、哪些形状与运动需要重新设计；刀光派生成功不足以验证护盾制作方法。

制作配方需落实尺度/坐标、输入姿态、采样与几何、UV、纹理来源或生成算法、混合与材质运算、曲线使用方、生命周期和观察条件。分别标明已经测得的事实、新设定的基线、仍缺失的信息。

## 调校与诊断

按相同输入比较单层与整体：动作轮廓、FX、音频、镜头/停顿分别观察，再恢复真实组合。若“没力度”，核对接触时点、被击方响应与明暗/速度对比；先解决峰值错位，不同时把所有强度翻倍。

观察近远景、多个敌人重叠、背景最亮/最暗位置和中断时刻。检查遮挡、方向反转、附着跳变、重复生成、无主循环与清理遗漏。记录正常帧率下的效果及性能，慢放仅用于定位。

成本按真实密度、屏幕覆盖、材质、光源与平台测量，不能从粒子数独自判断。降级可降低装饰密度、替换次要材质或缩短尾部，必须保留关键信息与事件语义。

交付事件—资源—使用方映射、关键时序、实际资源、正常/叠加/取消证据及尚未满足的品质/性能项。专业评审解释视觉层级和可读性，工具只校验版本、采样和显式关系。

## 制作实例：可取消的蓄力与命中分层

先做三项独立可编辑资源：贴地范围形状、随持有者移动的蓄力主体、命中点的一次性冲击。范围形状读规则范围，蓄力主体读准备进度，冲击只读实际命中；一次挥空不能显示目标受击。用材质参数控制边缘、明度和透明曲线，再添加次级碎片。第一次组合只验证主形状与峰值，避免装饰遮住动作。

UE 可用 Niagara/材质/网格按实际项目接口组合，Godot 可用 GPUParticles/材质/绘制资源；具体版本先核对已安装 API。以动作实例 ID 关联所有者，取消清理该实例的蓄力与拖尾，已独立生成的持续区域按规则保留。混合测试在明暗背景各触发一次，再同时触发多个实例，观察范围边缘是否重叠失读、爆光是否覆盖敌人和清理是否误杀其他效果。

共享观察记录开始、规则提交、FX 请求、实际活跃状态和清理；截图/录像用于核对可见响应，不把请求事件当渲染已经出现。若取消后的活跃状态延后，先修生命周期；若生命周期正确但仍有尾部，则区分设计尾音/尾迹与残留。公开 Godot 工程夹具提供原创弧形反馈、实际射线命中和延迟清理复现，属于工程示例，不是最终 VFX 美术样板。

裂地、扬尘、脚步与武器拖尾的制作和返修，按需阅读 [战斗特效配方](combat-effects-recipes.md)。
