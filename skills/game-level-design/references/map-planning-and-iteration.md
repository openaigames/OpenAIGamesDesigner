# 地图规划与迭代

用于新区域规划、空间重构及向美术制作交接。方法由本项目的玩家活动、空间结构和待解决问题决定；不内置参考作品、地图形状、路线数量、目标数量或固定尺寸。项目明确选用的参考只作为该项目输入，提炼方法时不把其内容设定带入通用流程。

## 从目标和未知项选择表达方式

先读取玩家要完成的活动、镜头与移动能力、世界状态、已有有效布局及制作范围。说明这轮最需要判断什么，再选择能暴露该问题的表达方式。无需从头重做已有可靠内容，也不要求每张地图先产出同一种图。

| 当前要判断的问题 | 可采用的表达与检查 |
| --- | --- |
| 区域如何连接、哪些路径可选择 | 区域关系图或拓扑草图；落实几何时补实际边界、出入口和尺度 |
| 平面中的距离、占地与遮挡是否成立 | 可编辑俯视草图、局部平面或引擎正投影 |
| 上下层、侧向移动或隐藏连接怎样组织 | 分层平面、剖面、侧视图或局部空间原型 |
| 大尺度移动、区域衔接和活动分布是否合适 | 区域层级图、地形与旅行尺度记录、代表路线或区域原型 |
| 顺序、解锁、重访及状态变化怎样影响空间 | 路径与状态对应图，并检查变化前后的路线 |
| 外观、材质与空间体验能否共同成立 | 概念表达、代表视点和可运行的局部美术样板 |

这些是表达选择，不是必须提交的图纸清单。箱庭可先解决回环、层间关系和重访；开放世界可先解决区域层级、旅行体验和代表区域；横向空间可用侧视与剖面。实际需要仍由项目目标决定，不为类型名称套布局模板。

在图上标出本轮有效的边界、关系、状态和待测假设。需要几何判断时使用共同坐标、方向、单位及尺度依据；连接图不证明净宽或视线成立，透视效果图不能唯一确定隐藏结构。设计建议、估算和实测分别标明。

## 用最小有效原型回答问题

把问题写成可观察的玩家行为或运行结果，再选择区域、初始状态和必要系统。可以在草图与原型之间往返；不要求先铺完整世界，也不把完整美术图纸设为玩法试验的前提。

原型保留影响判断的实际能力、镜头、碰撞与规则。验证空间移动可用灰盒；验证发现线索、视听感受或美术可读性时需要相应表现。占位会影响什么结论应明确，必要系统缺失时缩小结论范围。

记录预期、实际行为、问题位置与原因假设，针对差异修订并在可比较条件下复测。检查项随目标选择：探索可关注发现、返回和状态变化，旅行可关注导航与沿途节奏，对抗可关注视线、时机与不同参与方的选择。只有实际涉及的联网、程序生成或分区加载才加入对应检查。

静态检查、估算、软件输入、单人操作和多人体验分别记录。可达不等于容易理解，局部通过不等于整图成立；结论引用本次场景、配置、操作与覆盖范围。更细的状态与修改回归见 [状态与灰盒验证](level-design/state-and-blockout.md)。

## 将有效空间交给制作

视觉方向可以与空间探索并行。进入依赖风格的制作前沿用已选风格或有效选型委托；缺少这些依据时先询问。布局选择、风格选择与运行验证分别记录，阶段审阅沿用用户要求。

按下一步制作者需要补齐图纸、尺度和约束，而不是默认完整总平面加四面立面。图纸来自同版空间依据；涉及视觉与玩法的修改一起评估。具体交接见 [地图制作与空间交接](../../game-environment-art/references/map-from-design.md)；独立安装缺少该文档时，在现有规格中记录同样的版本、单位、推定内容和约束。

扩大制作前，用能代表当前风险的区域检查风格、模块、导入和实际负载；已有有效样板可复用。扩展后复核区域之间的联系和受影响的玩家活动。局部改动只回归相关依赖，不自动重走整个开发流程。

交付本轮实际完成的草图、原型、模型或场景及其结论；只要求草图审阅时停在该范围。流程指导和设计提案不能记为已运行或已通过体验验收。
