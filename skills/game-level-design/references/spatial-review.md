# 连续空间、实测路线与评审

读取真正的关卡几何/碰撞、角色尺度、相机、出生/目标/遭遇对象。引擎或项目导出明确的世界单位、轴向、对象 ID 和版本；不要从任意源码或截图推断完整空间。工程场景仍是主源，导出是只读观察。

至少选能回答本次问题的连续视图与实际视点。2D 需要角色大小、平台高差、遮挡和镜头窗口；3D 需要俯视布局、关键高差/剖面及玩家高度的视线。图中区分可视表面和实际碰撞，纯美术几何不能自动证明可通行。

理论范围依据运动能力推算，碰撞查询检查特定路径，实际行走体现启停、导航、镜头、交互和敌人干扰。三类数据分别标记。记录起终点、路线、计时起点、目标触发与辅助条件，不能用单点到达代替整段流程。

问题标注绑定时间/世界位置、工程对象、场景版本和观察片段。把“地图不对”拆到具体影响：目标露出过早、回路入口不可见、交战距离与武器不匹配、地标相似、恢复空间不足等。调整一个局部空间关系后复测受影响的路线/视线，保留无关验证。

共享看板可叠加导出几何、相机、路线和批注；缺少数据时显示未采样，不能绘制一张看似真实的完整地图。用户要求草图先确认时提交有尺度、关键镜头和设计依据的内容；已有有效确认直接沿用。

交接时关联当前场景、规格与批注的版本。门框、碰撞、角色半径或移动参数变化后，根据显式消费者找到通行、镜头和路线复测项；静态草图通过、引擎实现一致、正常操作通过分别记录。
