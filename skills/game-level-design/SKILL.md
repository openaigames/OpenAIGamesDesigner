# 关卡策划

先读取当前关卡和具体问题、目标体验、角色实际移动/视点、攻击与交互能力。区分路线拓扑和可玩空间；连接图不能代替角色尺度下的连续地图，静态可达不能证明实际路线与交战可用。

## 设计、制作和修正

根据玩家目标说明各区域的信息、选择、风险和结果，再落位入口、视线、掩体/平台、遭遇、目标和返回路径。让尺寸与能力引用项目权威配置，避免美术、碰撞和策划各维护一套尺度。

对已有地图先用实际路线和关键视点复现问题，区分迷路、视线不清、距离/节奏、战斗压力或通行缺陷。保留基线，以能区分原因的局部草图/灰盒修正做比较；没有空间证据时不直接重做整个地图。

使用 [关卡方法索引](references/level-design.md) 按需进入空间与路线、节奏与遭遇、状态与灰盒。需要引擎导出和评审时使用 [空间证据与交接](references/spatial-review.md)。明确目标标记、地图/世界坐标与实测/估算，传送到终点或冻结敌人的检查不能冒充正常路线试玩。

## 专业接口

- 战斗策划提供敌人行为、射程、预警、反制和资源压力；本 Skill 决定遭遇空间与组合，不私改玩家能力以让布局成立。
- 环境美术在布局和可读性约束内制作主题、地标、布景与光照；影响通行或信息的改动一起复测。
- 程序保存真正的场景、规则和导航；共享空间记录用于读回/评审，不产生第二份可编辑关卡主源。

草图是否需要人工确认沿用项目已有要求，不新增普遍审批。按约定阶段交付布局/规格、可编辑关卡或已验证内容；保存真实视点、路线、时间/位置问题和当前结论。没有实机验证时明确设计假设，独立任务不强建完整 GDD 或看板。
