# 关卡与体验编排

用于新区域设计、路线改动、遭遇放置、教学与检查点设计，以及现有关卡的定位和节奏问题。关卡可以是房间、连续地图、节点网络或一段有状态的体验，不预设三维空间、敌人或线性闯关。

从 [设计推理入口](design-reasoning.md) 读取项目目标。先辨认玩家在本段需要理解、选择和完成什么，以及进入时的能力、知识和世界状态；不要先画房间再为房间填系统。

| 本轮问题 | 参考 |
| --- | --- |
| 目标怎样转为空间、路线与尺度 | [空间与路线](level-design/space-and-routes.md) |
| 活动、遭遇、教学和休息怎样排列 | [体验编排](level-design/beats-and-encounters.md) |
| 检查点、重访、灰盒与修改验证 | [状态与灰盒验证](level-design/state-and-blockout.md) |

探索参考解释 [发现与导航](exploration-adventure-design.md)；本专题负责将这些目标落实到区域关系和整段流程。战斗参考定义敌人应对关系，本专题决定交锋出现的位置、进入方式和前后情境。移动能力引用 [移动与交互](movement-interaction.md)，不要在关卡里偷偷改变角色规则来满足距离。

交付可以是已有 GDD 的区域章节；复杂关卡才拆独立规格。工具包 `templates/feature-spec.md` 提供通用结构，按本参考补进入状态、节点/连接、段落、尺度视角、恢复与灰盒检查。草图、灰盒可达、试玩理解和最终美术品质是不同进度，不互相替代。
