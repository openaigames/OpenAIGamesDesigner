# 体验、行动与系统关系

用于建立整体设计、连接不同活动或解释机制的作用。不要把“核心循环”限定为战斗/收益/升级，也不要认为所有游戏都必须有反复刷取。

## 从体验到具体情境

将好奇、紧张、掌控、轻松等目标对应到具体情境：玩家看到什么、可以做什么、怎样判断、结果如何被感知。体验词可以保留为方向，但不能直接推出一套功能。先分析用户已经给出的行为与关系，候选机制说明为何支持目标及引入的代价。

描述一个局部活动的进入、行动、回应和退出，以及结果如何影响下一次行动。故事可推进到新的不可逆情境，解谜可通过理解改变后续判断，探索可改变知识而不增加属性。持续动机不必都是奖励积累。

## 跨系统联系要独立设计

对于有实际联系的活动，记录来源、输出、接收方、触发时点、玩家反馈和返回影响。输出可能是物资、信息、人物态度、世界状态、能力或限制。说明谁保存和消费它、何时失效；设计阶段写职责而不强定程序架构。

| 检查角度 | 要回答的问题 |
| --- | --- |
| 因果 | A 的结果究竟改变了 B 的哪个条件或选择？ |
| 双向影响 | B 是否改变下一次 A 的目标、方法或理解？单向推进也可以成立 |
| 可感知性 | 玩家如何知道这些变化有关，而非两个活动碰巧相邻？ |
| 强制性 | 是否必须完成 A 才能继续 B，是否存在替代路径？ |
| 边界 | 跳过、重复、失败、缺失输入或顺序颠倒时怎样处理？ |

并非所有系统都必须互相依赖。某段独立活动可能承担叙事、休息或惊喜；解释其目的与接入方式即可。强行让一切产出同一种货币，可能消除原本不同的意义。

## 识别关系上的矛盾

如果强调自由探索却只能按唯一任务顺序获得通行条件，检查自由具体体现在哪里；如果强调自主经营却所有决策都被外部采集量完全决定，检查经营是否仍有选择。矛盾可能是有意取舍，不必机械消除，但要说明真实体验。

例：发现一种古代标记，可以改变居民对地点的解释，再让玩家用新信息辨认旧路线。这里的连接是知识与人物互动，不必添加出售、经验或装备升级。

交付典型活动、系统关系、条件与结果、关键选择和待证实问题。按复杂度使用叙述、表或图；模块清单不是关系说明。风险分析见 [information-and-risk](information-and-risk.md)，节奏连接见 [pacing-and-iteration](pacing-and-iteration.md)。
