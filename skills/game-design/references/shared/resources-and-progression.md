# 资源、成长与选择

本篇提供跨系统概念。需要制定具体供需、奖励分布、曲线或解锁规格时，进入 [成长与经济](../progression-economy.md)，避免用概念列表替代详细模型。

用于资源流、获得/消耗、能力变化、解锁与长期目标。信息或关系不一定适合数值化；没有成长要求的项目不自动加入经验、等级、装备或永久加成。

## 资源关系

对本项目实际需要的资源说明来源、消费者、容量/限制、转化、更新时点及耗尽/溢出后果。判断它服务什么选择：准备、承诺、分配、恢复、交换还是节奏。资源名称不同不证明设计角色不同。

检查转换是否可以循环套利、恢复是否绕过预期活动、供给不足是否造成无法继续、溢出是否消除选择。循环可能是有意奖励；先判断目标和条件，不将所有高收益组合视为漏洞。文档中的候选值说明依据，工程落地后引用生效配置及覆盖关系。

## 进展可以有不同形式

能力增加、可达范围扩展、理解加深、故事推进、人物关系变化都可能形成进展。描述变化后玩家能作出的新选择，而不是只记录累积量。横向新增选项、纵向强化、熟练度与玩家知识不能互相替代。

明确获得、失去、替换、重置与持久化的边界。若某内容依赖特定能力或物品，检查获得顺序、丢失后恢复、替代路径及玩家事先可知程度。随机供给不能自动保证前置条件可满足。

## 组合与基准

用代表情境比较主要选项的收益、成本、限制和操作要求。平均值可能掩盖门槛、阶段差异与极端组合；需要算例时注明假设和单位。不要把某项在专长情境更优直接判定为不平衡。

成长可能降低先前任务的阻力，也可能让原本希望保留的决策消失。判断这是否符合阶段目标，再决定调整内容、成本还是能力，不要求所有内容永远保持相同挑战。

例：发现一条捷径会降低今后返回的时间，但也可能改变玩家对补给或任务顺序的选择。它可以是一种进展，不需要兑换成数值奖励。

交付实际资源/状态关系、来源与消费者、进展形式、规则边界、参数来源及待测假设。跨活动转化见 [experience-and-systems](experience-and-systems.md)；伤害和战斗资源的特殊结算留在战斗参考。
