# 战斗基础、体验目标与系统关系

用于从零设计、方向调整或发现战斗“什么都有但没有核心选择”时。局部动作修订无需重新讨论全部基础。

## 战斗目标中的能力取舍

通用的体验到行为、系统连接和交付方法见 [体验与系统关系](../shared/experience-and-systems.md)，此处只展开战斗特有的关系。根据已有目标解释玩家应关注和学习什么：识别、执行、位置、时机与承诺、资源管理、组合规划或协作。多项可以共存，但要说明主次与冲突，例如精确瞄准与复杂连段是否能在当前输入和注意力条件下同时发生。

战斗目标可以是掌握攻击距离后更稳定地创造机会；动画更长、敌人更多等功能数量不能单独说明这种目标成立。

确定当前必要边界：操控对象、时间推进方式、视角与输入、单人/多人及目标使用场景。沿用已知事实；不要求所有细节在立项时定完，也不将作品参考扩展成用户未选择的整套规则。

## 建立决策循环

沿共享方法建立循环，再重点追踪攻防如何互相改变机会、时间、位置、暴露、行动点或其他代价。对抗并不要求统一体力条。

描述交锋、取得/丢失优势和恢复。实时战斗可分析压力与恢复节奏；回合制可分析行动顺序、可预测信息和回合间状态。战斗结果与其他活动的连接使用共享方法，不在这里预设局外成长或永久死亡。

为主要选择列出：何时值得用、何时不适用、玩家如何提前得知、对局面产生什么变化。动作数量少也能有深度；动作很多但所有情境都重复一个选项，通常需要回到关系而非继续加招式。

## 画关系，而不只是系统树

系统树用于定位职责；关系说明要回答它们如何互相影响。对本项目适用的攻击、防御、移动、资源、状态、敌人、战场、装备、信息与胜负规则，记录一条有条件的因果关系：

| 机制关系 | 要检查的内容 |
| --- | --- |
| 攻击与移动 | 是否能同时进行、距离/方向如何改变收益和风险 |
| 防御与输出 | 防御是否牺牲机会，成功防御是否产生反击条件 |
| 资源与节奏 | 获取/消耗鼓励接近、等待、轮换还是持续压制 |
| 敌人与玩家能力 | 威胁是否要求使用某种决策，是否允许替代应对 |
| 反馈与学习 | 失败原因和机会是否能从信息中学到 |

每个重要机制说明要解决的体验问题、代价和受影响系统。不要强制石头剪刀布、统一资源或一套状态架构；具体关系来自目标。

## 常见矛盾与取舍

- 声称攻击需要承担风险，但任意时刻都能无成本取消：检查真正的承诺保留在哪里，或承认目标是自由组合而非承诺感。
- 声称鼓励进攻，但脱战等待总能无风险恢复全部资源：检查场景压力、恢复来源与目标是否一致；等待也可能是被允许的策略。
- 声称考验识别，但关键提示在镜头外或被特效覆盖：这是信息和空间问题，未必应通过加长敌人动作解决。
- 声称多种流派，但只有一种能应对关键机制：判断是明确的内容限制、可接受的专精，还是误设的必选项。

可以保留这些张力，只要说明取舍；设计审查不是寻找一组普适“正确机制”。

## 示例与交付

示例：若目标是“玩家主动寻找攻击机会”，候选 A 是敌人招式后的恢复窗口，候选 B 是玩家通过压制创造破绽。A 更依赖读招，B 更依赖持续行动与资源选择；不应不加解释地将二者视为同一种体验。验证时观察机会由何产生、玩家是否理解和利用，而不是只统计总伤害。

交付体验目标、典型决策循环、机制关系、范围与待决、主要矛盾和验证问题。将操作空间交给 [controls-and-space](controls-and-space.md)，动作关系交给 [actions-and-interactions](actions-and-interactions.md)，实验选择交给 [iteration](iteration.md)。
