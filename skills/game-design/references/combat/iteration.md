# 战斗诊断、调试与迭代

用于“手感不好、节奏太慢、招式没用、敌人不公平”等反馈，以及已明确的规则/参数修改。策划负责解释问题和提出改动；技术、表现与验证提供实际依据。未运行的推断必须标注，不能冒充测试结果。

## 先建立症状与基线

症状、基线、实验归因与证据分层采用 [共享迭代方法](../shared/pacing-and-iteration.md)。这里补充战斗的事件时序、对抗条件和回归关系，不另建一条战斗工作流。

读取实际生效参数及覆盖关系，确认改动对象。固定可重复的初始状态、装备、敌人/场景和必要随机种子；真人操作无法完全固定时记录差异。重置、状态显示、命中可视化和慢放可帮助诊断，但调试模式中的感觉不能代替正常速度与目标环境表现。

## 分层定位原因

| 层次 | 典型问题 | 需要的依据 |
| --- | --- | --- |
| 规则与选择 | 没有值得切换的行动、代价可被绕开、应对互相冲突 | 系统关系、具体情境和选择过程 |
| 数值与节奏 | 窗口、收益、阈值或恢复与目标不符 | 实际配置、算例和运行观察 |
| 信息与表现 | 提示不清、命中不可读、反馈让人误判状态 | 真实画面/声音、事件与时间对照 |
| 实现 | 输入丢失、重复命中、状态残留、配置未生效 | 复现、日志、代码/资产与测试 |
| 内容与环境 | 地形、敌人组合、设备或负载使局部规则失效 | 代表场景、设备、对照条件 |

同一症状可有多个来源。“射击慢”可能指射速、输入到反馈的延迟、击杀所需发数、换弹间隔或敌人节奏；只有用户明确要求射击间隔数值变化时，才可直接按该范围调整而不再展开方向讨论。

## 提出能区分原因的实验

从证据形成少量可证伪假设，选择成本较低且能区分它们的观察。例如先比对输入事件与射击事件时间，再决定是否调射速，而不是同时改射速、伤害、镜头与敌人血量。

战斗对照记录装备、目标防御、初始资源、攻击序列和适用场景；多个强耦合规则一起修改时，依共享方法说明归因限制。

解释战斗结果时考虑熟练度、装备/内容可获得性、学习与顺序效应；胜率、命中率或平均伤害不能单独证明平衡或手感。

## 迭代闭环与回归

基线、版本与报告层次沿共享方法。战斗规则以实际命中、状态、资源和表现结果对照，不只检查技能是否激活。

依据变更关系挑选回归：调整取消窗口需检查资源/状态清理与后续输入；修改命中触发需检查多段/范围和返还效果；更换动画需检查时序与挂点。无关系统不自动纳入全量重测。

结果可支持保留、调整、补测或放弃。保留旧决定和失败记录，说明结果适用版本；不因实现完成或命令通过自动更新整个项目阶段。项目管理入口链接结论，受影响的专业文档更新规则与依据。

## 示例与交付

示例：玩家认为闪避“不可靠”。若日志显示闪避已激活但伤害仍发生，应先核对无敌规则、伤害类型、窗口与判定时序；若输入未激活，则检查状态阻断、缓冲和成本；若未受伤却播放了受击反馈，则可能是表现问题。这三种情况不适合用同一项“延长无敌”修改统一解决。

交付问题证据、原因假设、候选改动及取舍、实际变更与验证结果、剩余限制和下一步。正式测试记录沿用验证 Skill 的方法；相关规格参考 [actions-and-interactions](actions-and-interactions.md) 与 [damage-and-resources](damage-and-resources.md)。
