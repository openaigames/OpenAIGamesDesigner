# 操作、信息与战斗空间

用于移动/瞄准/镜头设计、锁定问题、命中体验、近远程关系或场景限制。先读项目现有输入与视角；不是所有战斗都需要角色自由移动或相机控制。

## 输入必须表达明确意图

按玩家意图区分移动、选择目标、攻击、防御、切换和确认/取消，再描述具体设备映射。对本次涉及的点击、按住、释放、重复输入、组合输入、缓冲和上下文动作给出解释。记录冲突优先级及不可用反馈，不默认所有输入都能同时处理。

输入缓冲说明接收条件、失效条件和消费时点，而不只写“支持缓冲”。例如攻击后摇中按下防御，是立即取消、合法窗口再执行、只缓存下一动作，还是忽略？不同结果改变玩家预期。切换目标、被打断或死亡后是否保留旧输入，按规则决定。

设备与辅助选项按目标场景考虑：重映射、按住/切换、重复按键负担、瞄准辅助、提示可读性。说明它们影响的操作能力，避免把设备差异当作玩家水平差异；无需为不在范围内的平台实施全部方案。

## 镜头与信息约束

说明玩家在采取行动前能知道哪些信息：威胁方向、目标距离、攻击范围、地形、队友与资源。视角、遮挡、镜头跟随、抖动和特效都影响这个信息面。需要屏外威胁时定义提示或应对依据，而不是假设玩家总能看到敌人。

锁定/选中机制按需定义候选、切换、失效与解除；检查目标死亡、遮挡、超距、移动和多个相邻目标。自动面向、辅助吸附或软锁定会影响玩家实际控制，需说明何时介入及如何反馈。

## 空间是战斗规则的一部分

将距离、朝向、速度、转向、覆盖范围、地形与可达路径放在同一情境分析。射程更远不必然更强：观察瞄准需求、掩体、接近方式和资源；近距离动作也可能因位移或控制改变空间。

根据游戏采用连续空间、格点、站位或抽象前后排规则，明确可达、遮挡、范围和目标合法性。需要高度或空中战斗时再补高度关系。不要将实时角色碰撞规则机械用于回合制选择界面。

攻击期间移动/转向是否受限，动作是否带位移，敌人追踪何时停止，命中方向以哪个时点为准，都可能改变躲避和攻击承诺。规则与视觉位移需一致，但根运动或代码位移的具体选择交给技术侧。

## 取舍与故障诊断

| 现象 | 先检查 | 不应直接得出的结论 |
| --- | --- | --- |
| 玩家一直后退射击 | 追击可达性、有效射程、场景目标、恢复来源 | 必须削弱远程伤害 |
| 明明躲开却被命中 | 目标追踪时点、判定体积、视觉轮廓、延迟与实际日志 | 只需增加无敌时间 |
| 近战在狭窄场景失效 | 墙体、转向、目标选择、动作空间与镜头 | 连段设计本身失败 |
| 锁定后操作别扭 | 移动坐标系、镜头变化、转向与目标切换 | 必须移除锁定 |

这些是候选原因，不是未经证据的诊断。先建立可复现条件，再选择修改方向。

## 示例与交付

示例：要让绕侧攻击有意义，只有背击加成还不够。敌人转向速度、追踪截止、场地宽度和玩家绕侧成本共同决定是否真的有机会；若敌人瞬间持续对准玩家，加成可能永远无法主动利用。

交付输入意图/映射、冲突与缓冲规则、信息与镜头要求、目标选择、移动/距离约束，以及用于验证的空间样例。需要时用俯视草图或位置序列说明，不要求先完成正式关卡。与 [动作规则](actions-and-interactions.md) 和 [遭遇设计](enemies-and-encounters.md) 对齐。
