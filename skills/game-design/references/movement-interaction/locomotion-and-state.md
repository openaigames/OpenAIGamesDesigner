# 移动能力、输入与状态

## 从输入到移动结果

描述输入代表方向、目标点、速度意图还是离散动作，以及它依赖世界、角色或相机坐标。说明按下、持续、释放分别做什么；模拟量、死区和设备差异按实际支持的输入处理。

速度、加速度、制动、转向、空中控制、重力或路径跟随是可选设计维度。先找到它们怎样影响目标行动，再设置参数；不要给所有项目统一加入冲刺或跳跃。

对现有工程引用真实单位、参数来源、更新方式和测试状态。候选值说明依据，比较时保留同一环境；不同帧率下的差异可能来自实现而非规则。

## 能力的完整过程

按需说明进入条件、起始状态、持续行为、退出条件、失败结果和下一次允许的动作。说明输入被拒绝、缓冲还是延后；取消后速度、碰撞、资源和动画怎样处理。

能力同时存在时检查优先级与组合，例如交互中移动、落地同帧再次请求动作、平台离开时释放控制。只选与项目实际能力有关的组合，不生成无穷状态表。

移动的权威来源需明确：控制器、路径、物理、动画位移或几者分段接管。两处叠加位移、结束后残留速度、动画提前退出是不同问题，交给技术侧核查对应实现。

## 空间条件与容错

检查坡面、台阶、边缘、天花板、移动表面或动态阻挡中的适用项；二维和网格移动使用各自空间表达。名义移动距离不保证碰撞后的实际落点。

输入缓冲、离地宽容、吸附和自动修正可以降低误差成本，也可能改变玩家控制感。用户未选择时作为候选，记录触发范围、重复触发及错误吸附的代价，不把这些当作所有游戏必备功能。

## 诊断与验证

区分请求未到达、规则拒绝、运动被阻挡、镜头误导和表现迟滞。记录输入与状态转换能定位实现问题，熟悉操作的开发者试玩不能单独证明新玩家易用。

交付能力过程、可调参数/单位、空间依赖、组合边界以及代表输入序列。动画接口与提示消费者只引用状态事实，不维护第二套完成规则。
