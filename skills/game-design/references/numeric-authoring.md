# 数值表、计算模型与持续调参

用于需要批量配置、成长曲线、公式推算，或用户希望自己编辑数值后交回工程的任务。它是功能设计的附件工作方式，不是新阶段或每个项目必备的表格包。几个参数直接放在现有规格表即可；不要为一个价格调整生成整套经济模型。

## 何时生成雏形

从用户当前问题识别需要的表：攻击收益与时间窗口、成长曲线、资源收支、奖励概率等。先读已有规则和真实配置，能提取的直接提取。无工程时按已知设计生成候选表，区分已确认值、暂定值及未知；未知不能以 0 冒充，也不能把教学样例作为默认游戏配置。仅在单位、目标、取值逻辑或导入对象会影响本轮结果时提问，不要求用户学会工具命令。

批量数值可保存在项目已有表格目录；新项目按需放在 `design/numerics/`，由 GDD 或对应功能规格链接。表格按用途分区或分表：

| 内容 | 最小有用信息 | 修改方式 |
| --- | --- | --- |
| 输入/配置 | 稳定 ID、字段、值、单位、范围及当前状态 | 用户或 AI 修改可编辑单元格 |
| 计算过程 | 输入引用、公式、取整规则、时点、假设 | 修改模型时说明原因，不覆盖成静态结果 |
| 输出 | 推导配置、期望值、曲线和比较 | 由公式更新，注明适用条件 |
| 交接 | 对应规格、实际生效来源、导入方法、导出基线、验证入口 | 引用真实文件，不复制另一套权威数值 |

数值文件使用稳定字段名；中文列名、说明、单位和可视化可放在展示页。供机器导入的页只含约定字段和记录。小表不强制拆页；复杂 Excel 文件用独立数值输入/导出页，计算页与图表留给策划阅读。

制作 XLSX 时优先使用宿主可用的电子表格能力，验证公式、改输入后的重算及视觉效果；不可用时交付 CSV 和规则说明，不谎称生成了可重算工作簿。CSV 不保存公式、图表、格式或多页结构。

## 修改与用户回传

- 用户说“重击伤害改成 60”时，按已授权范围修改该输入，重算相关指标，说明影响；不自动调整别的参数来抵消效果。
- 用户说“升级太慢”时，先定位经验来源、升级成本与体验目标，可提出几种候选曲线；不要把一种推算冒充用户决定或实测结论。
- 用户交回文件时，读取保存后的实际文件，与导出基线按稳定 ID/字段比较。只改顺序不是数据变更；新增、删除、改 ID、改单位是另一个结构/规则变更，不能悄悄当数值覆盖。
- 用户只要草案或测算时，交付表格和结论即可。用户已要求“应用到工程”时，在授权范围内继续校验、导入和验证，不为每个单元格重复确认；文件刚被保存、或只是请模型看看，不构成导入授权。
- 计算表中带公式的值需可靠重算再导出数值，并保留公式来源、输入版本与计算方法。Excel 的旧缓存不能证明用户最新修改已经算完。

具体读取、冲突处理与工程写回由技术侧 [数值交换与工程接入](../../game-technical-design/references/numeric-exchange.md) 负责。不默认工程使用 JSON；现有数据格式和导入器优先。

## 设计解释和联动

引用参数配置而非在 GDD 中另写一份待维护的数值；规格解释目标、取舍和关系。例：修改攻击间隔可能影响动画节奏、判定窗口、AI 决策、耐力消耗和 UI 提示，但单独改伤害未必需要美术调整。按真实依赖检查，不强迫所有方向都发生修改。

模型需要明确的口径，例如首击是否在 t=0、单级与累计经验、概率是否独立、是否有保底、资源流是否包含失败局。理论 DPS 不直接证明手感，期望收益不等于每位玩家都获得，静态经济收支不代表平衡。

同一变更记录链接输入表版本、变更差异、目标配置、导入记录与验证；分别记录“候选表已更新”“工程配置已写入”“运行已生效”“体验待验证”。管理入口汇总完成与未完成；概览仅在定位或体验承诺改变时修订。
