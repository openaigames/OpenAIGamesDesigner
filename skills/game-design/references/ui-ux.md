# 游戏 UI/UX 与教学

用于玩家任务、信息结构、界面流程、输入焦点、操作反馈和机制学习。不等于 UI 美术风格，也不意味着创建浏览器看板。

从玩家想完成什么、当前看见什么和哪里受阻开始，使用 [设计推理入口](design-reasoning.md)。现有界面局部问题只处理受影响流程，不自动重新设计全部菜单。

| 问题 | 参考 |
| --- | --- |
| 信息组织、流程、选项和结果 | [任务与信息结构](ui-ux/tasks-and-information.md) |
| 焦点、设备、确认取消与状态 | [输入与反馈](ui-ux/input-and-feedback.md) |
| 教学、辅助与实际可用性 | [学习与可用性](ui-ux/learning-and-usability.md) |

规则属于相关系统，UI 呈现条件、接收意图并解释结果；技术负责实际数据和输入接入，美术负责视觉语言与资源。状态要覆盖成功之外的实际情境，不能只交一张漂亮的默认页面。

需要独立交付时用工具包 `templates/feature-spec.md`，细化玩家任务、流程、数据来源、焦点、输入、教学和反馈；实际观察使用 `templates/validation-report.md`。线框、视觉稿、已接入数据和试玩验证分别记录。三维世界提示、声音和控制器反馈也可以承担信息，不强制每个需求变成屏幕面板。
