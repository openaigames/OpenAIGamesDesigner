# 玩家任务与信息结构

## 从任务而非页面开始

写出玩家此刻目标、起点、必要信息、行动和期望结果。区分查看、比较、选择、编辑、提交和退出；页面数量少不等于操作成本低。

界面名称采用项目自己的语言。一个完整流程应覆盖入口和完成后的去向；设置或装备变更何时生效、取消保留什么，不由实现者从按钮文案猜测。

## 信息支持决策

区分即时行动所需、比较选项所需、深入研究所需的信息。层级可随任务变化，不能把所有参数放到同一优先级。隐藏细节要保留可发现入口；减少文字不能删去决定性的成本或条件。

比较须保持单位、基准、适用状态一致。预览值、当前生效值和暂存修改应能区分。涉及随机或条件效果时，不把估算展示为确定收益。

图标、颜色、位置、声音和文字可以互补，未知与零值、锁定与不适用需有区别。文本长度、数字范围及本地化后的扩展按目标内容检查，不默认已经完成多语言支持。

## 流程中的例外

根据真实依赖处理空内容、不可用、正在加载、提交中、失败和结果过期等状态。离线本地即时功能不必加入虚构网络错误页。

改变世界状态后，打开着的面板需要更新还是暂时锁定，必须与系统约定。例如制作材料被消耗后，配方详情不能继续显示旧的可制作结果。

## 交付与诊断

用流程表说明起点、条件、行动、状态改变、反馈和下一步；复杂时再画图。链接信息字段的真实来源，明确候选与已决定内容。

“找不到按钮”可能是入口命名、布局层级、焦点或禁用解释问题。先定位玩家在哪一步偏离预期，不凭设计者觉得清晰就判定完成。
