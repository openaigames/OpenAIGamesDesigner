# 探索与冒险：参考入口

用于好奇心、导航、发现、通行条件、探索活动与后续目标的设计。它不是完整游戏分类；不预设开放世界、战斗、任务清单、地图标记、生存条、资源收集或失败惩罚。

先按 [设计推理入口](design-reasoning.md) 理解玩家为什么探索、会作什么选择、发现怎样改变后续体验。没有战斗也可以成立；有战斗时只为实际对抗问题调用 Combat。叙事、关系、经营等活动可以相连，但不能从“冒险”自动添加现成系统。

| 当前问题 | 按需读取 | 交付重点 |
| --- | --- | --- |
| 为什么寻找、发现有什么意义 | [探索目标与发现](exploration-adventure/discovery-and-motivation.md) | 好奇、发现层次与结果用途 |
| 怎样辨认路线、看懂世界 | [导航与环境信息](exploration-adventure/navigation-and-information.md) | 信息分布、路线判断与引导 |
| 怎样通过、返回、开启新可能 | [通行与世界变化](exploration-adventure/traversal-and-world-state.md) | 空间/知识/能力条件与状态边界 |
| 活动如何串联、怎样避免重复或断裂 | [活动、节奏与迭代](exploration-adventure/activities-and-iteration.md) | 跨活动关系、代表情境与观察 |

项目内用自己的地点、活动与系统名称维护设计。整体探索需解释发现、选择、可达与后续影响；局部路标或入口修订无需重写整张地图。未知可以保留，候选不能冒充用户选择。

交付可为现有 GDD 的章节、区域规格或路线/状态说明，必要时使用工具包 `templates/feature-spec.md`，按本参考展开发现、路线、世界变化及活动联系。地形图、任务表和奖励表各自只能表达一部分，不能替代体验关系。正式美术不是验证导航与选择的先决条件，实际视听效果也不能仅由文字判断。
