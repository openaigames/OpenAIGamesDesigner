# 成长、经济与奖励设计

用于资源供需、奖励节奏、能力成长、解锁和相关规则调整。它是可组合的专业方法，不要求项目具有等级、货币、局外成长或商店。玩家知识和世界变化也可能承载进展；没有交易或数值成长时只读适用内容。

先读取实际循环、资源/能力来源、当前配置、持久化边界和本轮问题。区分“玩家觉得成长慢”“特定升级买不起”“后期资源无处使用”“一个选项总是占优”，它们可能有不同原因。按 [功能设计](feature-design.md) 处理范围，通用资源概念沿用 [共享资源方法](shared/resources-and-progression.md)。

| 当前问题 | 深入方法 | 应形成的结果 |
| --- | --- | --- |
| 产出、消耗、价格、转换、资源过剩或短缺 | [资源模型与供需](progression-economy/resource-models.md) | 账户/流向、交易规则、阶段收支与边界算例 |
| 奖励是否有用、随机多久能获得、重复奖励、保底 | [奖励与节奏](progression-economy/rewards-and-pacing.md) | 奖励语义、分布/约束、实际机会成本与验证条件 |
| 成长后改变什么选择、解锁顺序、重置与重配 | [成长与解锁](progression-economy/progression-and-unlocks.md) | 前后选择差异、前置关系、曲线依据与恢复规则 |

把体验目标、候选模型、工程生效配置分开。计算题可以给明确假设下的答案；未知产能不能凭空填成实测均值。详细规格应让实现者知道什么时候生成、展示、领取、扣除和保存结果；数值来源、单位与覆盖规则交技术落实。

从代表情境检验模型，而不是仅证明总收入等于总支出：新进入阶段、连续失败、低收益路线、资源已满、全部解锁、旧存档和重复提交中选择相关项。理论可得不等于玩家愿意获取，静态算例不证明经济平衡。

需要独立交付时继续用工具包 `templates/feature-spec.md`；计算表或配置文件作为其附件，不新增专项模板。验证由 game-prototype-validation 依据实际机制选择实验和算例。以下资料中的数值全是教学假设，不继承为项目默认配置。
