# 通行条件、返回与世界变化

用于地点可达、能力/知识门槛、环境交互、捷径、世界状态与重访。不要因通行问题自动加入跳跃、攀爬、钥匙或装备系统。

## 定义可达的依据

入口或路径可能受位置、操作能力、知识、物品、时间、关系或世界状态影响。说明玩家如何得知条件、条件由何满足、失败反馈与替代路径。知识门槛可能在玩家理解后就能通过，不必再增加角色属性校验。

通行操作本身是否是挑战，需要与用户目标一致。若重点是观察与发现，重复操作可能只是负担；若重点是掌握移动，空间与容错就需要详细规格。相关移动或交互机制超出已有专题时使用通用功能规格，而不是硬归入战斗。

## 状态变化及顺序

记录变化前后哪些连接、对象或信息改变，触发和保存时点，重复/撤销/离开/重新进入如何处理。已开启捷径、桥梁状态、人物开放的入口等实际来源需明确，避免多个系统各维护不一致状态。

检查玩家在“意料之外”的顺序取得条件时是否仍可继续：提前获得信息、丢失物品、错过事件、改变关系、从另一侧进入。不可逆事件可以成立，但应有清楚的设计后果，不能无意造成无法继续。

## 返回不只是重复道路

重访可以提供新的理解、新行动或不同世界状态，也可以单纯支持熟悉与归属。快速返回、捷径、移动能力或省略过场会改变节奏，按目的选择，不强制所有游戏都开放传送。

若每次完成活动都要求长距离原路返回，检查这段时间承担的作用；如果承诺世界会变化，需让变化可感知，不能只在配置里切换标志。恢复/重试记录保留什么、重置什么，不默认失败丢失成果。

例：学会辨认潮汐标记后，玩家能选择合适时机通过旧海湾。需要定义信息怎样获得、时机怎样被观察、错过后的接续和是否存在替代路线，不必把它转换成等级门槛。

交付条件与来源、连接/状态变化、可知信息、替代/恢复路径、重访意义和边界情境。技术侧实现持久化与触发，验证侧检查实际顺序和恢复，不以状态图完整宣称所有路径可达。
