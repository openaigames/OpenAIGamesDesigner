# 战斗运行时契约

规则与调校由 [战斗策划](../../game-combat-design/references/production-and-tuning.md) 维护。沿用当前权威动作配置、状态和事件接口，不另造招式表或强制框架。以下是实施方法，不是已实现的 Boss AI。

## 一次动作怎样形成结果

沿现有代码追踪：输入/AI 意图 → 资格检查 → 接受动作 → 前摇 → 生效窗口 → 恢复 → 结束或中断。每次执行有可区分的实例 ID；片段 ID 不能代替一次执行 ID。动作配置与运行中的窗口、命中集合和取消状态分开维护。

| 事实 | 唯一负责者需要确定什么 | 表现使用方可做什么 |
| --- | --- | --- |
| 动作被接受 | 条件、成本、状态进入、实例标识 | 起手动画、预警、招式吼声 |
| 武器释放/挥动 | 实际片段或规则时间轴中的时点 | 挥舞声和轨迹，不要求命中 |
| 候选接触 | 当前窗口、几何、目标及遮挡/高度条件 | 调试显示；尚不播放已命中反馈 |
| 命中被确认 | 无敌、重复命中、阵营等规则 | 按结果播放血花、火花和命中声 |
| 受击反应已裁决 | 存活、抗性、优先级、已有反应 | 播放最终选中的反应与位移 |
| 动作结束/中断 | 关闭窗口、取消后续事件、释放控制权 | 收尾并回收本次实例拥有的资源 |

动画事件可以提出请求，不应绕过资格检查直接扣血。明确规则时钟、动画时钟、物理步进和不受顿帧影响的时钟；变速后保持生效窗口、轨迹和实际接触同步。暂停、跳帧与迟到回调应以当前实例/阶段判断，不能补发已取消攻击。

同一模拟步内双方都可能命中时，先在同一姿态阶段采集候选接触，再按项目明确的同时命中或优先级规则结算。不能无意中因脚本遍历顺序先让一方受击、关闭其窗口，导致永远只有另一方命中。

每目标去重键可由「动作实例、窗口/段 ID、目标 ID」组成，实际间隔和次数来自配置。多段攻击要有独立窗口或明确命中间隔，不能每个渲染帧重复扣血。

## 顿帧是双方共同的时间约定

武器接触产生的顿帧，通常需要同时冻结攻击者和受击者的相关动作与位移；不能只暂停敌人动画。列清受影响范围：骨骼、根运动、控制器、武器挂接、轨迹采样、二级运动、依附粒子和判定窗口。暂停动画而继续逻辑位移，会在恢复时错位。

输入缓存、UI、音频、镜头与不相关单位是否继续，由项目选择；局部战斗顿帧不应意外冻结全局联机模拟。保持输入缓冲的有效期语义明确，防止恢复时重复释放同一动作。

用秒或固定逻辑 tick 保存时长，并标记调参时的基准频率。某项目的 60 Hz 下 6–10 帧相当于约 100–167 ms，只能作为待试玩的示例。按设备渲染帧直接计数会使 30/120 FPS 下体感不同。

嵌套命中需要有上限和合并策略。例如将解冻时刻取当前值与新请求时刻的较晚者，并限制最大持续时间；不要每次命中无限相加。维护实际受影响对象集合，目标死亡/销毁、动作取消或场景重置时释放冻结，恢复原有速度而不是统一写 1。

验收轻击、重击、连击的命中/挥空、同时命中、冻结期间输入、对象销毁与重生；记录双方位置、动画时间、窗口状态及正常速度录屏。时间正确不代表体感已接受。

## 可复现验证

使用固定招式、距离和输入序列，至少覆盖当前任务修改涉及的命中/挥空、窗口边缘、无敌、零伤害控制、重入和中断。比较 30/60/120 渲染帧率时保持模拟时间含义一致。推演、自动断言、录屏和试玩结论分别记录。

对反应/AI 修改，回放连续轻击、重击插入、同时致死、无合法招式、路径不可达、连段节点中断和重试。检查的是明确期望，不用一个长时间随机木桩测试替代边界用例。交付实际配置、状态/事件归属与证据，未执行的场景保持待测。
