# 玩法数据、配置覆盖与版本变化

用于将策划规格落实为配置、新增内容类型或修改已有字段。先沿 [工程变更](engineering-change.md) 找到实际数据读写路径，不默认 JSON、数据库、DataTable 或某种架构。接口生命周期沿用 [玩法接口](gameplay-interface-contracts.md)。

需要生成可编辑数值表或读取用户回传的 CSV/Excel 并写回时，使用 [数值交换](numeric-exchange.md)，包含基线、变更预览、冲突检查、恢复和实际生效验证。

## 找到真正生效的数据

对一个实际参数追到作者编辑处、导出文件、引擎资源、运行实例和表现消费者。记录标识、类型、单位、可选范围、默认值及缺失行为。显示名称可以变化，稳定标识是否影响存档/引用需单独判断；数组位置通常不应被未经检查地视为稳定身份。

明确谁拥有定义、谁保存当前状态、谁只读或缓存。资源定义里的最大值和角色当前值属于不同生命周期；UI 上的预览值与实际提交后的值也不能共用一份未说明状态。

列出真实覆盖顺序及每层作用，不从常见引擎习惯推断。例如某假设工程使用默认武器 → 项目难度 → 关卡 → 实例覆盖，最后再应用临时效果。若同时存在加法和乘法，写清顺序与时点；不要在策划表和代码中分别维护不同公式。定位问题时输出生效值和来源链，不能只证明某配置文件已修改。

## 数据合同与检查位置

| 层次 | 应检查的内容 | 失败结果如何交接 |
| --- | --- | --- |
| 单字段 | 类型、单位、范围、缺省、非法值 | 指出具体记录与字段，避免悄悄修成另一个合法但错误值 |
| 同一记录 | 条件字段、互斥、上下限、阶段顺序 | 解释冲突规则；编辑期提示与运行兜底可不同 |
| 跨记录 | 标识唯一、引用存在、解锁/掉落关系 | 定位源与被引用项；允许未完成内容时标明其构建范围 |
| 运行实例 | 实际覆盖、状态有效性、消费者刷新 | 保存复现状态和最终值，不只复查静态表 |

校验放在最能给作者反馈的位置，同时在必要的加载/提交边界处理失败。全部放到运行时会拖慢内容生产；所有错误都自动夹取到范围内又会隐藏设计问题。项目已有校验器优先复用。

## 假设例：射击间隔改单位

旧定义为 `cooldown_seconds: 0.3`，新定义需要 `cooldown_ms: 300`。这是单位与字段变更，不是只改名字。需要定位配置加载器、关卡覆盖、UI 换算、AI 使用者、测试输入和真实存在的存档副本。

先约定版本规则：例如 v1 加载时把秒乘 1000 得毫秒，v2 直接读取毫秒，转换结果明确标为 v2。重复读 v2 不再次乘 1000。若允许同时存在两字段，需明确冲突优先级或拒绝；不能让不同消费者各选一个。缺失字段的默认值和是否支持向后导出依据实际兼容需求决定。

至少保留一个 v1 样本、一个 v2 样本、非法值和重复转换结果。若存档只存稳定武器 ID、并不存该配置值，则不要虚构一项存档迁移任务。若真实存档存有剩余冷却，则另定义其单位和暂停/离线语义，不能将定义转换直接套到运行状态。

## 提交、保存与交付

对购买、奖励、升级等一次性副作用，明确校验、扣除、授予和持久化的提交边界，以及重复请求/中断后的处理。规则由策划确定，技术选择现工程适用的事务、幂等标识或状态机制；单机小系统不必为此引入服务器。

涉及持久数据时，在隔离样本完成转换和重载，保存旧数据及版本。代码回退不等于数据回退；无法可靠恢复时不能以“有 Git”代替说明。

交付字段/单位/默认与约束、真实读写和覆盖路径、兼容策略、修改文件、样本和实测结果。配置表可以作为规格附件，原生工程保留权威生效值；工具包的结构化记录约定不等于游戏自身的数据 schema，不要把游戏字段塞入运行记录契约。按 [原生工程实施](engine-execution.md) 定位共享工具包后，查阅其 `schemas/` 中与当前记录匹配的 schema，以及 `tools/README.md` 中对应工具的说明；不在专业参考中维护固定 schema 数量或平行字段定义。
