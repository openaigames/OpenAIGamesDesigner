# 网页游戏实施

仅在用户选定网页路线、已有网页工程或明确委托选型时采用。网页 3D 的工具包路线为 Three.js，2D 为 Phaser；已有其他框架不主动迁移。“Unity / Unreal”仍不能解释为允许浏览器替代。框架选择已明确时不重复询问。

沿用 project-intake、prototype-build、feature-change、vertical-slice 和 delivery。新作先保存六份入口和最小实施交接；渲染库、模型、动作、输入和玩法规则不是同一个决定。实现可见对象前沿用本轮美术选择或选材委托。

## 按路线实施

| 路线 | 需要明确与实现 | 工程交接 |
| --- | --- | --- |
| Three.js 3D | 镜头、控制、碰撞需求、动画状态、加载与释放；物理按需选型 | 规则与渲染分开，按对象登记 glTF/GLB、贴图、动画及坐标/比例 |
| Phaser 2D | Scene 生命周期、输入、碰撞规则、加载、暂停/重开与场景切换 | 按用途登记精灵/图集/地图/声音，处理缩放、像素过滤和销毁后的监听清理 |

详细命令读取共享工具包 `adapters/engines/web.md`：源码根或已安装 `game-preproduction/runtime/`。可创建空入口、prepare、play、build/export；已有工程配置自己的 commands 优先。没有共享工具时使用项目已有命令。依赖通过项目锁文件追踪，不复制本机 node_modules，不自动迁移到最新主版本。

## 浏览器与交付

确定目标浏览器、设备与键鼠/触屏范围，必要时询问影响体验的选择。检查真实页面控制台、资源网络失败、渲染内容、输入焦点、窗口变化、暂停/重开；涉及声音和指针锁时检查用户手势及退出恢复。录屏/截图不能代替状态与操作检查。

测试按功能编写真实断言，可用项目现有浏览器测试工具；不要只断言 canvas 存在就宣称战斗通过。smoke/test 没有项目命令时保持未执行或 blocked，交付时说明。构建、开发服务、浏览器试玩与部署分别记录，性能只报告真实测量。

数值配置按 [数值交换](numeric-exchange.md) 绑定真实主源，明确 import 打包或 fetch 加载方式；修改后重载/重构建并检查有效值。静态网页不因存在数值工具而需要后端。

新模板只有空画布，不能当作可玩原型。真正的原型交付仍需实现已确认规则、输入、反馈及验证目标。导出包通过 HTTP 单独检查，不能依赖开发服务器路径或本机文件；公开发布按用户要求另行执行。
