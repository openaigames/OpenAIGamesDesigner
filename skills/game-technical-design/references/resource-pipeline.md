# 从源资产到引擎资源的接入与替换

用于模型、贴图、图集、动画、VFX、声音和其他内容的导入、替换或批次制作。读取资产规格、现有导入器、实际资源引用和目标构建，不按文件后缀推断已具备引擎支持。

## 建立一条可追踪资源链

定位可编辑源 → 导出文件及依赖 → 导入设置 → 引擎资源及标识 → 场景/代码消费者 → 构建内产物。记录哪些是人工维护、哪些可重建，以及生成它们的工具/版本。缓存可以被重建的判断必须有实际来源和方法；不能把唯一人工修改当缓存清理。

资产工具的任务号、输入快照和哈希提供生成/转换来源；引擎资源的 GUID、UID、软引用或其他身份以项目实际机制为准。本地 asset-job 成功不表示资源已导入，更不表示消费者引用已替换。

## 接入前核对合同

选择规格中真正影响运行的项：单位/朝向/原点、贴图语义与色彩解释、图集帧名/锚点、材质槽、骨架/挂点、动画事件、声音格式与循环、碰撞或导航代理。将美术目标映射到实际导入选项，记录覆盖和派生关系；引擎版本变化时查询对应本地配置或官方接口，不依赖固定 UI 截图。

先导入一份代表资源并在使用它的场景运行，再扩展到批次。需要重新生成派生文件时使用已有可重复命令；人工配置仍须保存。重复导入应保持哪些标识、是否改变文件，以及失败后留下什么中间状态，都应可解释。

## 假设例：只替换 Boss 的受击特效

假设玩家与 Boss 引用同一个公共资源，目标只改 Boss。先定位引用是否允许实例覆盖：若允许，创建或接入 Boss 专用变体并只改该引用；若修改公共源，两个消费者都会变化，不能把这当作局部替换。

记录旧公共资源、Boss 的旧/新引用、变体及其依赖。先在 Boss 场景检查挂点、重复触发和死亡清理，再在玩家场景确认原效果；最后检查实际打包目标是否包含新依赖。编辑器已打开的预览成功，可能仍依赖缓存或未保存资源，不能代替重新加载和构建验证。

## 加载、释放与异步结果

明确资源由谁加载、在什么范围复用、何时释放以及对象销毁后的异步结果处理。按实际使用选择预加载、按需加载或流式加载：前者可能增加初始内存，后者可能带来首次使用等待。选择依据是目标场景的测量和可接受体验，不普遍规定一种方式。

池化对象复用时需重置材质参数、播放位置、挂点、订阅与状态中的适用项；缓存引用不得让旧版本“看似已替换”。动态资源路径还需确认构建收集机制，静态引用扫描并不覆盖所有运行时加载。

## 批次、失败和恢复

批量处理前列输入、预期输出、标识碰撞、消费者与可恢复版本；转换先写独立输出，再检查选定结果并接入，避免半成功任务覆盖唯一源文件。多文件模型列主文件与侧文件，重命名或移动后核对相对路径。

批次部分失败时按资产登记成功/失败，不宣布整批完成，也不无差别重跑已稳定的资产。工具支持 dry-run 时可预检；不支持就用隔离代表样本，不伪造预检能力。

回退至少覆盖源/运行资源、引用和导入配置；必要时重新生成派生文件并重载消费者。哈希只能比较内容，不能恢复丢失数据。交付资源链、配置差异、受影响引用、真实导入/构建结果和已验证的恢复范围。通用流程与本地工具定位见 [原生工程实施](engine-execution.md)。
