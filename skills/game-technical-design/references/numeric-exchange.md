# 数值交换与工程接入

用于策划/用户编辑表格后把已授权的改动带回真实工程。字段、单位、覆盖顺序与状态生命周期沿用 [数据配置](data-configuration.md)；策划表制作方式见 [数值创作](../../game-design/references/numeric-authoring.md)。

## 确认来源与消费者

先追踪实际作者文件、导出配置、引擎资源、运行实例。明确本轮编辑源是现有工程配置还是策划工作簿；导出交换表是有基线的工作副本，不是自动双向同步的新权威源。若工作簿为主源，工程配置为派生产物，模型必须更新该工作簿再导出；禁止只改派生文件并遗忘作者源。已有主源优先，不能为了通用工具改造工程格式。

记录稳定 ID、可写字段、类型、单位、范围、必填规则、目标文件/资源与导入器。跨字段/跨表规则由项目校验器检查，例如前置等级、引用存在、技能总时长、掉落池总权重；通用工具不能靠 min/max 证明它们成立。用于存档的字段变化另查迁移，不把当前生命等运行状态覆盖成定义的最大生命。

## 从草案到工程

1. 有工程时读取配置并保存导出基线，再给用户编辑表；无工程时先生成候选数值和规格。只有实际实现了加载器或导入器，才能建立到工程的绑定。不能只为了让工具有文件可写而声称完成接入。
2. 读取用户保存的表格，或由 AI 按要求修改。展示按 ID、字段、旧值、新值和单位比较的差异，检查类型、缺失、边界、引用和项目规则。只改变数值的工作沿用功能变更流程。
3. 写入前重新核对输入表、字段绑定和目标配置是否与基线一致。源文件被其他人、编辑器或上一轮任务改动时，保留双方，重新导出并人工/模型合并明确的改动，不全表覆盖也不静默以“最后保存”为准。
4. 用户已授权应用时保存可恢复原文件，再使用工程支持的导入器或原子文件替换。暂停会竞争写同一配置的编辑器自动导出/其他任务；通用文件工具不提供跨进程锁或多人实时协作。
5. 执行相关项目检查，并在真实引擎加载后读取或观察最终生效值，检查覆盖层、缓存、现有实例与新建实例的差异。按改动复测代表性行为，保留输入、命令、日志与报告。仅静态写入不写成运行或平衡已通过。

## 当前可用工具及边界

按管理 Skill 的资源定位方式找到工具包根。共享运行包的 `tools/numeric_workflow.py` 支持 `export → plan → apply`，详细绑定格式和命令见工具包 `tools/README.md` 的“数值表往返”。无需部署后台。

| 输入/目标 | 当前处理方式 |
| --- | --- |
| 已有 JSON 记录数组（根数组或顶层键中的数组） | 声明 ID 与数值字段后导出 UTF-8 CSV，保存哈希基线；只更新已有记录的已绑定字段，保留其他字段 |
| 用户修改的 CSV | 检查完整列、ID、有限数值、整数和范围，按 ID 匹配，不按行号 |
| 用户修改的 XLSX | 可选 openpyxl 只读所选页，默认 Parameters；表头在第一行，严格对应绑定，无多余列/记录；其他计算/说明页不导入 |
| 公式单元格 | 直接导入拒绝，即使带缓存。用可靠计算工具重算，核对依赖和结果，再导出纯数值页/CSV；保留原工作簿作为依据 |
| 新增/删除记录、改 ID、字段/单位/公式变化 | 不在通用数值覆盖范围内，按功能/数据结构变更实现迁移并重新建立基线 |
| UE DataTable、CurveTable、DataAsset、GAS 定义、Lyra 配置 | 定位工程已有作者源/导入器，通过实际可用的编辑器接口、脚本或工程命令更新与重载；此工具不修改 .uasset，也不自动接通 GAS/Lyra |
| Unity ScriptableObject、Godot Resource、其他格式 | 复用项目导入器或按需求实现专项转换。仅项目确实加载被绑定 JSON 时才使用本工具直接写回 |

`plan` 是文件级差异，保存后表格再次修改需要新计划。`apply` 重新计算并比对计划，保存 `.openaigame/numeric-imports/<id>/before.json` 与 `receipt.json`。完成状态为 `configuration_written`，`engine_validation` 保持 `not_run`；它不创建 engine run，也不代替相关 `game_workflow.py run` 或项目检查。

本工具没有后台监视、自动推送与公式计算器。用户自然语言交回文件后由助手调用；无需用户操作 CLI。它不阻止有权限者直接改工程文件，因此不能用它宣称整个项目已有强制门禁。

## 中断与恢复

备份是写入前的原始字节。记录停在 prepared 时先比较目标哈希与 source_sha256/result_sha256，判断尚未写入、已写入但未收尾，或发生其他变更，不能直接重跑并宣布成功。failed 也要检查目标现状。

需要回退时先核对目标仍等于该次 result_sha256；一致则在用户已授权的修复范围恢复备份并重载/复测，另外保存恢复记录。若目标后来又改动，只恢复明确相关字段或合并，不能拿整份旧备份覆盖后续修改。恢复配置不恢复存档、编辑器缓存或已运行实例。

Technical Design 维护编辑源、字段/单位、映射和加载入口；任务链接计划、回执与实测证据。GDD/功能规格解释设计意图，美术仅调整实际受影响的节奏/表现，管理汇总各项真实状态。
