# 战斗时序、受击反应与招式选择

用于已确定的实时动作战斗实现或返修；回合制、联网权威和项目已有实现按自身规则取舍。先阅读 GDD 中的 [动作](../../game-design/references/combat/actions-and-interactions.md)、[数值](../../game-design/references/combat/damage-and-resources.md) 与 [敌人职责](../../game-design/references/combat/enemies-and-encounters.md)。本文提供接口和检查配方，不强制事件总线、状态树或某个引擎类。

## 一次动作怎样形成结果

沿现有代码追踪：输入/AI 意图 → 资格检查 → 接受动作 → 前摇 → 生效窗口 → 恢复 → 结束或中断。每次执行有可区分的实例 ID；片段 ID 不能代替一次执行 ID。动作配置与运行中的窗口、命中集合和取消状态分开维护。

| 事实 | 唯一负责者需要确定什么 | 表现消费者可做什么 |
| --- | --- | --- |
| 动作被接受 | 条件、成本、状态进入、实例标识 | 起手动画、预警、招式吼声 |
| 武器释放/挥动 | 实际片段或规则时间轴中的时点 | 挥舞声和轨迹，不要求命中 |
| 候选接触 | 当前窗口、几何、目标及遮挡/高度条件 | 调试显示；尚不播放已命中反馈 |
| 命中被确认 | 无敌、重复命中、阵营等规则 | 按结果播放血花、火花和命中声 |
| 受击反应已裁决 | 存活、抗性、优先级、已有反应 | 播放最终选中的反应与位移 |
| 动作结束/中断 | 关闭窗口、取消后续事件、释放控制权 | 收尾并回收本次实例拥有的资源 |

动画事件可以提出请求，不应绕过资格检查直接扣血。明确规则时钟、动画时钟、物理步进和不受顿帧影响的时钟；变速后保持生效窗口、轨迹和实际接触同步。暂停、跳帧与迟到回调应以当前实例/阶段判断，不能补发已取消攻击。

同一模拟步内双方都可能命中时，先在同一姿态阶段采集候选接触，再按项目明确的同时命中或优先级规则结算。不能无意中因脚本遍历顺序先让一方受击、关闭其窗口，导致永远只有另一方命中。

每目标去重键可由「动作实例、窗口/段 ID、目标 ID」组成，实际间隔和次数来自配置。多段攻击要有独立窗口或明确命中间隔，不能每个渲染帧重复扣血。

## 血量、失衡、冲击与位移分开

字段名称沿用项目，至少避免下列语义混用；没有的系统不必新增。

| 语义 | 记录内容 | 常见错误 |
| --- | --- | --- |
| 血量变化 | 数值、修正顺序、免疫、舍入 | 用伤害大小直接决定所有受击类型 |
| 失衡/架势积累 | 单位、阈值、衰减与清空时点 | 与生命值共享一个模糊的 power 字段 |
| 反应请求 | 轻硬直、站立击退、击倒等语义与优先级 | 所有控制统一播放倒地 |
| 反应抗性 | 当前阶段是否接收、阈值和恢复 | 抗硬直顺带变成生命无敌 |
| 强制位移 | 距离或速度、单位、方向、时长、碰撞处理 | 把速度当每帧位移，结果依赖帧率 |

示例：推掌和怒吼可配置为生命伤害 0、允许打断、站立击退、禁止击倒。只有在项目认可时采用；命中事件、伤害事件和反应事件分别判断，不能因伤害为 0 就跳过控制，也不能因此播放受伤出血。

反应裁决应考虑死亡、处决/阶段接管、击倒、站立反应等当前状态的优先级，具体顺序由玩法决定。轻击不能无条件重置正在播放的重受击，也不能每帧把硬直计时恢复至最大。需要抗连续控制时定义窗口/阈值，并说明期间是否仍扣血、积累失衡及给予反馈。

保存可定位的记录：动作实例、窗口、目标、命中结果、生命前后、失衡变化、反应选择/拒绝原因与单位。不把详细日志默认永久开启在发行版中。

## 顿帧是双方共同的时间约定

武器接触产生的顿帧，通常需要同时冻结攻击者和受击者的相关动作与位移；不能只暂停敌人动画。列清受影响范围：骨骼、根运动、控制器、武器挂接、轨迹采样、二级运动、依附粒子和判定窗口。暂停动画而继续逻辑位移，会在恢复时错位。

输入缓存、UI、音频、镜头与不相关单位是否继续，由项目选择；局部战斗顿帧不应意外冻结全局联机模拟。保持输入缓冲的有效期语义明确，防止恢复时重复释放同一动作。

用秒或固定逻辑 tick 保存时长，并标记调参时的基准频率。某项目的 60 Hz 下 6–10 帧相当于约 100–167 ms，只能作为待试玩的示例。按设备渲染帧直接计数会使 30/120 FPS 下体感不同。

嵌套命中需要有上限和合并策略。例如将解冻时刻取当前值与新请求时刻的较晚者，并限制最大持续时间；不要每次命中无限相加。维护实际受影响对象集合，目标死亡/销毁、动作取消或场景重置时释放冻结，恢复原有速度而不是统一写 1。

验收轻击、重击、连击的命中/挥空、同时命中、冻结期间输入、对象销毁与重生；记录双方位置、动画时间、窗口状态及正常速度录屏。时间正确不代表体感已接受。

## Boss 招式池与决策边界

先实际审阅动作，把主动攻击、移动、战吼、受击、倒地、处决与死亡分开。名称中含 attack/combo 不能证明它适合作为主动招式；保留候选不等于已配置成技能。

沿用既有 AI，将职责解释清楚即可，不要求重建框架：

1. **观察**：何时获得距离、朝向、视线和目标状态。若目标体验不允许读输入，使用可感知的动作/位置和明确延迟，不能直接针对玩家刚按下的键选克制招。
2. **合法性筛选**：阶段、距离、高差、空间、冷却、当前状态和素材就绪。没有合法攻击时，选择接近、重定位或等待等有效行为。
3. **选择**：在合法集合内按职责、近期重复、距离偏好和冷却取舍。保留可重放的随机种子/选择原因用于调试；随机不等于公平。
4. **执行**：前摇、朝向追踪截止、生效、连段节点和恢复。连段只在允许节点续接，已承诺攻击不因每帧重新评分而变招。
5. **反应**：受击、目标丢失、阶段切换、处决和死亡按已定义优先级打断；清除未执行分支，不能恢复后补打一招。

示例：Boss 在高台等待接近，入场触发后才进入战斗；等待状态不能同时使用追击逻辑。玩家死亡后停止对其选择攻击，胜利动作/声音只触发一次。脱战与重试需要复位冷却、反应、招式序列与接管状态。

## 判定与额外范围

把武器接触与附加冲击区域作为同一招式的不同窗口/来源，注明二者是否可以在同一段重复伤害同一目标。形状、方向、长度、宽度、传播速度和有效时段由同一权威配置驱动判定、调试显示及 VFX；表现可加无伤害装饰，但要能读出真正危险范围。

向前裂地按传播前沿与已扫过区定义命中，不能效果刚起点亮就对全长度同时造成伤害。下砸扇区/圆区仍检查高度、遮挡和场地边界，不能默认穿墙或攻击其他楼层。残留尘雾与持续伤害分别定义。

## 可复现验证

使用固定招式、距离和输入序列，至少覆盖本轮修改涉及的命中/挥空、窗口边缘、无敌、零伤害控制、重入和中断。比较 30/60/120 渲染帧率时保持模拟时间含义一致。推演、自动断言、录屏和试玩结论分别记录。

对反应/AI 修改，回放连续轻击、重击插入、同时致死、无合法招式、路径不可达、连段节点中断和重试。检查的是明确期望，不用一个长时间随机木桩测试替代边界用例。交付实际配置、状态/事件归属与证据，未执行的场景保持待测。
