# UE 能力系统选型：GAS 或项目自有实现

在 UE 已确定、当前功能将涉及能力/属性/状态实现且工程尚未定技术路线时读取。它服务于通用接入、原型和变更 workflow，不新增 GAS 专用阶段，也不要求每个 UE 用户回答框架问卷。

## 先了解需求，再介绍技术

用户只说“做一场 Boss 战”不能推出 GAS、联网、连段或完整动作框架。先读取已有规则和约束，只有缺口影响当前实现时才澄清：例如能力是否需要频繁增加或组合，是否有持续状态与叠加，是否明确需要联机，已有系统是否足够。不要把所有问题一次问完。

| 当前情况 | 助手如何处理 |
| --- | --- |
| 只讨论定位、玩法或美术 | 继续设计，不为写文档提前选 GAS |
| 已有工程采用 GAS，局部增加技能/属性 | 检查现有 ASC、授予和数据主源，按 [GAS 方法](gas-combat.md) 扩展，无需重选 |
| 已有自有系统能够支持本轮需求 | 原位修改；不为了统一工具包迁移到 GAS |
| 新工程的实现将需要大量能力交互、状态叠加、资源/冷却，或明确需要相应网络预测/复制支持 | 主动向用户介绍 GAS 的收益与接入成本，再与自有实现比较；单个特征不自动决定选型 |
| 仅验证少量稳定动作或简单交互，属性和状态需求很少 | 可以推荐小型组件/状态机实现；检查后续扩展与团队维护能力，不把“Demo”自动等同于不用 GAS |
| 用户明确指定 GAS 或已授权助手选择技术方案 | 按有效选择实施并记录依据；不重复确认，不将“你来决定”变成永久阻塞 |
| 用户没有委托，候选的依赖和成本差异会改变当前制作路线 | 给出一项有理由的推荐，用易懂语言说明取舍，再询问该决定；等待期间继续无关工作 |

向非技术用户可以这样说明：“这些技能共享冷却、资源和可叠加状态，使用 UE 的 GAS 能复用这些管理能力，但初次接入更复杂。另一条路线是只为当前几种动作写组件，早期范围更小，后续扩展需自行维护。”根据真实需求调整，不承诺用了 GAS 就免写战斗逻辑、自动联机或更快。

## 比较的内容

| 维度 | GAS 路线 | 自有组件/状态机路线 |
| --- | --- | --- |
| 能力与状态 | 用 Ability、Effect、Attribute、Tag 等表达适用规则 | 项目自行定义行为、数据、状态与事件；也可复用 UE Gameplay Tags 等功能 |
| 生命周期 | 需要正确接入 ASC、授予、Avatar、取消和清理 | 需要自己建立初始化、退出、重生和资源释放规则 |
| 数值与效果 | 框架提供属性修改、持续效果等工具；具体公式仍由项目定义 | 生命/伤害组件、配置和计算函数自行组织；可用 UE 基础伤害事件 |
| 联网 | 可复用 GAS 的复制/预测能力，仍需按机制实现并实测 | 按实际需求自行实现权威、复制和必要的预测；单机不强加联网 |
| 动画与手感 | 仍需动作资源、控制、时序、命中与反馈 | 同样需要这些部分；不用 GAS 不代表不用动画系统 |
| 维护 | 评估团队理解框架的成本及能力扩展需求 | 评估自有系统的规模、可测性和长期维护，不等同于随处散落蓝图逻辑 |

选型不按“技能超过几个”或“3A 必须 GAS”这类固定门槛判断。伤害系统只是其中一部分，GAS 也可用于适合其模型的非战斗能力；普通交互不因此自动引入 GAS。

## 保存决定与接入边界

在 Technical Design.md 记录候选/已采用、理由、用户指定或委托依据、已有依赖、实施范围及待验证点；重要取舍链接 production/decisions 中的决定，管理入口汇总。不要把 GAS 写成模型/动画素材，也不要为了这个决定生成另一套项目模板。

已选 GAS 时读取 [实现方法](gas-combat.md)；角色动作需要落地时，不论是否采用 GAS，都读取 [动作与动画接入](action-animation-integration.md)。新工程不再以 Lyra 为预设基础，不要求下载示例工程。接手已有样例派生项目时仍保护其现有依赖，不能把工具包移除专项路线解释为授权删除用户工程中的框架。

自有实现也要交接输入→动作状态→命中/交互提交→数值与反馈→结束/取消的职责关系，保留可复现验证。后续确需迁移时，先盘点能力、属性和消费者，再制定迁移/回退范围，避免两套逻辑重复扣血。

依据：[GAS](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-ability-system-for-unreal-engine)、[UE Apply Damage](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Game/Damage/ApplyDamage)。API、插件和依赖以目标工程版本为准。
