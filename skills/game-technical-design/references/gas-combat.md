# GAS 战斗实现方法

仅用于已采用或用户选择采用 GAS 的工程。先检查当前实现，避免平行创建第二套属性、伤害或状态系统。此处的 Gameplay Ability 是游戏能力，不是助手的专业 Skill。

## 从规则到实现

将本轮动作规格映射到实际 Ability、Attribute、Effect、Tag、表现事件及目标/命中处理。Ability 组织激活、执行与结束；属性表达需要管理的数值；Effect 表达项目适用的数值/状态影响；Tag 表达条件与关系。并非每个参数都必须成为 Attribute，每个表现也不必新建 Ability。

核对 ASC 的拥有者、Avatar、初始化和重生/换角色生命周期；玩家与敌人沿用各自真实架构，不假设 ASC 必须挂在同一类 Actor 上。确认能力由谁授予、撤销和恢复，以及装备/角色更换时如何清理。

对相关动作明确：输入来源、激活条件、资源消耗时点、冷却、重复输入、阻断/取消关系、命中规则、结束清理。将正常完成、主动取消、受击打断和死亡等适用路径闭合，检查遗留 Tag、任务、命中监听、位移和表现。取消能否返还成本由策划规则决定。

动画时序与规则时序建立明确连接：说明生效窗口从何触发、变速/中断如何影响它、哪个系统负责命中及权威结果。不能仅播放 Montage 就声称完成攻击逻辑。敌人决策选择何时出招，GAS 执行相应能力；GAS 不替代敌人行为设计。

联网项目核查权威执行、预测和校正、目标数据及重复应用；只报告实际测试的网络条件。单机验证不能证明多人同步正确，也不为单机任务自动扩展联机系统。

输出真实代码/资产路径、规则到实现的映射、可调参数入口与回归证据。原型与切片使用相同实现依据，只按各自品质与范围验收。

官方依据：[Gameplay Ability System](https://dev.epicgames.com/documentation/unreal-engine/gameplay-ability-system-for-unreal-engine)。具体 API 以工程版本和实际源码为准。
