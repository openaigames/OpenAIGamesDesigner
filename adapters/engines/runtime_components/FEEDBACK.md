# Shared Feedback

[English](FEEDBACK.md) | [简体中文](FEEDBACK.zh-CN.md)

Godot `OAGDFeedback` and UE 5.8 `UOAGDFeedbackComponent` manage native audio, optional visuals, and additive camera angles. Games choose cues after committing events and own door conditions, damage, quests, and asset selection. No character-animation plugin is required.

## Integration and Ownership

Run `tools/runtime_components.py create --engine godot --scenario feedback --project <new-directory>`, or use `--engine unreal --ue-root D:/UE_5.8`. Godot imports WAVs on first open. UE requires editor compilation and `create_map.py` to create the map, SoundWaves, and materials. Existing games can install components and call interfaces without adopting sample characters or menus.

`feedback-profile.json` maps door, zone, ui, and action cues to committed door opening, actual player zone entry, menu selection, and project action callbacks. Four WAVs are original calibration sounds generated by `templates/runtime_feedback/generate_audio.py`, with no third-party samples. Procedural rings in Godot and discs in UE expose position, timing, and cleanup; they are not finished art.

Godot entry files: `main.gd`, `audio/`, `pulse.gd`, `pulse.tscn`. UE: `Source/OAGDExamples/ExampleGame.cpp`, `Content/OAGDData/feedback-profile.json`, `Content/Feedback/`. Copied resources, mappings, and component locks belong to the game; toolkit upgrades do not change them.

## Interfaces and Rules

| Purpose | Godot | UE 5.8 |
| --- | --- | --- |
| Configure | `configure(profile, audio, visuals)`, empty string on success | `Configure(TMap<FName,FOAGDFeedbackCue>, budget, error)` |
| Play | `play(cue, event_id, owner, position, follow, scope, intensity)` | `Play(Cue, Event, Owner, Position, Follow, Scope, Intensity)` |
| Stop | `stop(handle, reason)` | `Stop(Handle, Reason)` |
| Scene cleanup | `stop_scope("scene")` | `StopScope(TEXT("scene"))` |
| Full cleanup | `clear()` | `Clear()` |
| Pause | `set_game_paused(value)` | `SetGamePaused(Value)` |
| Camera angles | `camera_offset` Vector3 | `CameraOffset` FRotator |
| Lifecycle | `lifecycle(handle,event,cue,state)` | `Lifecycle` dynamic delegate |

Successful play returns an increasing handle; rejection returns -1 and sets `last_error/LastError`. Treat `active/Active` as read-only; do not mutate internal collections or destroy owned resources. Stopping the same handle twice returns false on the second call.

`event_id` uniquely identifies an event, not a cue. The last 256 accepted IDs remain deduplicated after stopping; Clear or successful reconfiguration resets them. This is not cross-session/network exactly-once delivery.

Each cue permits 1–16 instances; the global budget is 1–32. At the cue limit, reject or replace the oldest handle according to configuration. At the global limit, reject if this cue has no replaceable instance. There is no priority-preemption queue. Invalid configuration preserves the previous valid one; active instances prevent reconfiguration.

Profiles use schema=1. Cues require domain=`game|ui`, overflow=`reject|oldest`, loop/spatial booleans, duration 0.02–60 seconds, volume 0–1, camera 0–3 degrees, integer limit, three color values in 0–1, and audio/visual asset IDs (empty means unused). Intensity is 0–2; nonfinite values are rejected. Godot accepts JSON plus resolved resources. The UE example parses JSON into native structs; C++/Blueprint can supply structs directly.

## Lifecycle, Position, and Clocks

One-shot effects end at their declared duration; audio may naturally finish sooner. Loops need a living owner and native looping audio resources; UI loops are unsupported. Stop immediately silences audio and removes visuals. Arbitrary fade tails, complex mixing, occlusion, music, and middleware are outside this component.

With `follow=false`, position is world-space. With `follow=true`, it is owner world position plus a world-axis offset (Godot meters, UE centimeters). Rotation, scale, and skeletal sockets are not inherited. Projects can supply attachment nodes/proxy Actors. Owner destruction stops its effects on the next update without affecting independent ownerless world effects.

Explicitly notify the component of game pause; the example uses the input router's pause signal. Game audio pauses, visual/camera clocks freeze, and new game cues are rejected. UI cues continue on real time. UE audio is enabled during engine pause and explicitly SetPaused by domain. Game cues resume their remaining duration. UI expiry cleans up on the next engine update, not while the main thread is blocked.

Visual contract: Godot PackedScene roots are Node3D with `sample(age,strength,color)`; UE derives `AOAGDFeedbackVisual` and implements `Sample`. UE should retain an independent movable root and animate children locally. Mesh examples are provided; no generic Niagara/particle-editor adapter is included.

Camera output is an absolute additive angle. Each frame, remove the previous contribution before adding the new one; never accumulate it indefinitely. Combined pitch is clamped to ±3 degrees and roll to ±1.5. Godot feedback priority is -10 and the example camera defaults to 0. UE uses `AddTickPrerequisiteComponent(Feedback)` so the controller reads after feedback updates. Cleanup zeros the contribution and preserves base angles.

Callbacks may Stop/StopScope/Clear; snapshot iteration tolerates clearing other instances. Play/Configure inside lifecycle callbacks is rejected and must be deferred. Visual Sample should only adjust visuals, not the manager.

## Validation and Evidence

`tools/runtime_validation.py --engine godot|unreal --project <project> --executable <engine> --visual` creates separate results and temporary saves. Godot imports automatically; UE requires compilation/map creation. Feedback uses real time; fixed-frame-time arguments cannot substitute for audio timing. Unfocused UE automation sets `[Audio] UnfocusedVolumeMultiplier=1.0` for that launch only.

Reports include 33 native assertions, instance events, mixed WAV, and screenshots. The runner checks non-silent, unclipped WAV output; this establishes signal output, not listening quality. Without `--visual`, there is no visual acceptance. Godot's silent headless driver can also fail the mix check; use native execution with an audio device.

Scope is Windows single-player 3D projects. Verify listening quality, final mix, sustained performance, device input, and handoff execution separately.
