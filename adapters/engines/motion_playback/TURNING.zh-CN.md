# 可选踏步转向

[English](TURNING.md) | [简体中文](TURNING.zh-CN.md)

下文引用的审计脚本保留在源码仓库，不随安装包分发。

示例提供平地减速、左右 45°／90°／180° 踏步转身和重新起步。工具按已校准角色的真实 idle 姿态制作可编辑动作，控制器负责位移与朝向，原生动画图负责骨骼播放。没有运行时脚部 IK，也不要求已有游戏替换自己的移动系统。

## 制作和接入

```powershell
python tools/motion_turns.py --base VERIFIED_PROFILE_REVISION --output NEW_TURN_REVISION --blender BLENDER_EXE
```

输入必须是已经通过加工验证、目标前向为 Blender -Y 的角色配置版本，含 hips、thigh/shin/foot 映射及真实蒙皮 idle。输出保留原八个动作，增加六个转身动作的 `.blend`、GLB、FBX、实际求值 capture、`turns.json` 接触时段及制作报告。输出目录必须新建，原件不改。新动作在目标骨架上制作；它们不是从第三方项目复制的动作，也不是任意骨架自动适配。

每 45° 使用 0.6 秒的两次换脚，另有进入／退出各 0.2 秒：45° 为 1 秒、90° 为 1.6 秒、180° 为 2.8 秒。离线烘焙保留支撑脚的世界位置和朝向，抬脚弧线为 7.5 厘米。制作端检查实际骨骼漂移、姿态步进及蒙皮最低点；报告通过仍需原生接入验证。

播放绑定增加对应六个非循环、无事件动作，并显式设置：

```json
"turning": {"mode":"step_turn_v1","trigger_deg":30,"settle_s":0.2,"recover_s":0.2},
"turn_observation_bones": {
  "dst_hips":"实际髋骨", "dst_thigh_L":"左大腿", "dst_shin_L":"左小腿",
  "dst_thigh_R":"右大腿", "dst_shin_R":"右小腿"
}
```

此策略依赖已有 `locomotion`，CLI 核对六个动作、时长、角色映射和已验证的制作清单。通过 `motion_playback.py create` 或 `stage` 接入；已有工程须显式升级项目副本，再运行原生导入及 activate。工具包安装不会改写游戏工程。

## 项目运行规则

- 输入方向偏离身体至少 30° 时，沿当前方向减速到接近静止，等待 0.2 秒，再选最接近的 45°／90°／180° 转身；较小角度沿用普通转向。
- 位移在转身中停止，朝向使用实际动画片段位置求值。Godot 在 AnimationTree advance 后更新朝向；UE 在世界帧末读取原生播放进度后更新。没有用另一套累计时钟代替动画实际位置。
- 改变或释放输入时，等当前一步双脚落稳再恢复并重新选择方向。暂停同时保持移动、动画与转向；重开清除转向状态。
- 转身期间本模板不开始全身交互或跳跃；恢复后可正常触发。已有游戏可以自行定义这些规则，不能只改时长或旋转曲线而沿用原接触证据。
- Godot 和 UE 的转身资源都保留 60 fps 采样。按角色前向处理 Blender 与引擎旋转符号，避免看似转向却让支撑脚反向绕行。

## 验证与限制

`tests/scenarios/motion_turning_audit.py` 测量真实骨骼的支撑漂移（包括进入混合）、足部朝向、膝盖、暂停及连续输入恢复；`motion_turning_roundtrip.py` 在混合结束后对照源动作与原生姿态。案例必须保留当前消费者哈希和运行报告，不能把离线目标轨迹当成引擎结果。

这是平地技术动作样例，转身采用减速和踏步，因此响应比直接旋转角色慢。不是高速弧线跑、急停冲刺、侧移、倒退、地形 IK、运动扭曲或最终动作美术。当前验证中的漂移阈值属于案例约定；游戏应根据体型、镜头和手感继续调校。
